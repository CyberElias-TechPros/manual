## B. Learning Outcomes
<!-- kind:outcomes -->
By the end of this session, the learner will be able to:
1. Explain what data validation is and why it matters.
2. Check data against source documents for accuracy.
3. Identify discrepancies between the dataset and source documents.
4. Use Excel's built-in validation tools to prevent future errors.
5. Create a validation report documenting all findings.
6. Explain the difference between validation and verification.

<!-- kind:prereq_review -->

Inconsistent formats, misspellings, duplicates, missing values and wrong data types.
2. "How do you remove duplicates in Excel?"
Data tab > Remove Duplicates.

Mark it as 'N/A' and flag it for follow-up.

It creates a record that others can follow and verify.

Accuracy.

## F. FULL LECTURE NOTES (35 minutes)
<!-- kind:lecture -->
Topic 1: What Is Data Validation? (5 minutes)
Instructor Script: "Data validation is the process of checking data against a source to ensure it is accurate and complete. It is
like auditing — you compare what you have against what should be there.
Validation vs Verification:
Validation: Checking that data meets the required standards (format, type, range).
Verification: Checking that data matches the original source.
Why Validation Matters:
Catches errors before they cause problems
Ensures data integrity
Builds trust in the dataset
Prevents costly mistakes"
Topic 2: Checking Data Against Source Documents (15 minutes)
Instructor Script: "Here is a systematic process for validating data against source documents:
Step 1: Prepare
Have the dataset open in Excel.
Have the source documents ready (invoices, receipts, forms).
Step 2: Check Each Record
For each row in the dataset, find the matching source document.
Compare every field: date, name, product, quantity, price, total.
Mark any differences.
Step 3: Classify Discrepancies
Typo: A digit or letter is wrong (e.g., '15000' instead of '150000').
Missing data: A field is empty in the dataset but filled in the source.
Extra data: A record exists in the dataset but not in the source.
Missing record: A record exists in the source but not in the dataset.
Calculation error: The total does not match quantity x price.
Step 4: Correct Errors
Fix typos based on the source document.
Fill in missing data from the source.
Remove extra records.
Add missing records.
Recalculate totals.
Step 5: Document Everything
Create a validation report listing every discrepancy found and how it was resolved."
Topic 3: Using Excel's Built-in Validation Tools (10 minutes)
Instructor Script: "Excel has tools that help prevent data entry errors.
Data Validation Rules:
1. Select the cells you want to validate.
2. Go to the Data tab.
3. Click 'Data Validation'.
4. Choose a rule type:
Whole number: Only integers allowed.
Decimal: Decimal numbers allowed.
List: Only values from a predefined list.
Date: Only dates within a range.
Text length: Limit the number of characters.
5. Set the criteria.
6. Add an error message that appears when invalid data is entered.
Conditional Formatting for Error Highlighting:
1. Select the data range.
2. Go to the Home tab.
3. Click 'Conditional Formatting'.
4. Choose a rule (e.g., 'Highlight Cells Rules' > 'Duplicate Values').
5. Duplicates are highlighted."
Topic 4: Creating a Validation Report (5 minutes)
Instructor Script: "A validation report documents everything you found and fixed during the validation process.
Validation Report Structure:
1. Header: Dataset name, date, validator name.
2. Summary: Total records checked, total errors found, total errors corrected.
3. Error Log: A table listing each error:
Record number
Field name
Error type
Dataset value
Source value
Resolution
4. Sign-off: Validator name and date."

What the Instructor Prepares:

What the Instructor Says and Does: "I am going to validate this dataset against the source invoices."
1. "I start with the first record. I find the matching invoice."
2. "I compare the date: Dataset says '01/10/2026', invoice says '01/10/2026'. Match."
3. "I compare the customer name: Dataset says 'Adaeze Okafor', invoice says 'Adaeze Okafor'. Match."
4. "I compare the quantity: Dataset says '25', invoice says '2'. MISMATCH — typo in the dataset."
5. "I correct the quantity to '2'."
6. "I compare the price: Dataset says '35000', invoice says '35000'. Match."
7. "I compare the total: Dataset says '875000', but 2 x 35000 = 70000. MISMATCH — calculation error."
8. "I correct the total to '70000'."
9. "I continue this process for all 20 records."
10. "I create a validation report listing all discrepancies and resolutions."

## I. INDEPENDENT CLASS EXERCISE (10 minutes)
<!-- kind:exercise -->
Exercise: "Validation Scenarios"
Answer the following questions:
1. You are validating a dataset and find a record that exists in the dataset but not in the source. What type of error is this? What
do you do?
2. You find a price that is 10x higher in the dataset than in the source. What type of error is this? What do you do?
3. A field is empty in the dataset but filled in the source. What do you do?
4. You cannot find the source document for one record. What do you do?
5. What is the difference between validation and verification?
Time Allowance: 10 minutes
Complete Answer Key:
1. Extra data — remove the record from the dataset and note it in the validation report.
2. Typo (likely an extra zero) — correct the price based on the source document.
3. Fill in the missing data from the source document.
4. Mark the record as 'Unverifiable' and flag it for follow-up. Do not delete the record.
5. Validation checks that data meets required standards. Verification checks that data matches the original source.

## J. REAL-WORLD CASE STUDY (5 minutes)
<!-- kind:case_study -->
Case: "The Invoice That Did Not Match"
Situation: An accountant is reconciling the sales dataset at the end of the month. She finds that the total sales in the dataset do
not match the total on the bank statement. The difference is ₦150,000. She investigates and finds that one invoice was entered
twice — a duplicate that was not caught during data entry.
The Problem: The duplicate was not identified during data entry or cleaning. It was only caught during reconciliation.
Why It Matters: Validation catches errors before they cause problems. Without validation, duplicates, typos and missing
records can go unnoticed and cause serious consequences.
Worked Solution: The accountant removes the duplicate, corrects the total and implements a validation process to check every
dataset before it is used.
Transfer Exercise: "Why is it important to validate data before using it for reports or decisions?"

## K. COMMON MISTAKES AND TROUBLESHOOTING (5 minutes)
<!-- kind:troubleshooting -->
Mistake 1: Not Checking Every Record
Symptoms: Only some records are validated. Fix: Always check every record against the source document.
Mistake 2: Not Documenting Discrepancies
Symptoms: Errors are corrected but not recorded. Fix: Always create a validation report.
Mistake 3: Correcting Based on Memory
Symptoms: The learner 'remembers' what the value should be instead of checking the source. Fix: Always check the source
document. Never rely on memory.
Mistake 4: Ignoring Small Differences
Symptoms: The learner ignores a ₦100 difference because it is 'small'. Fix: Every discrepancy matters. Document and resolve all
differences, no matter how small.
Mistake 5: Not Implementing Validation Rules
Symptoms: The same errors keep appearing. Fix: Use Excel's Data Validation tool to prevent future errors.

## M. KNOWLEDGE CHECK (5 minutes)
<!-- kind:knowledge_check -->
1. What is data validation? Answer: The process of checking data against a source to ensure it is accurate and complete.
2. What is the difference between validation and verification? Answer: Validation checks that data meets required standards.
Verification checks that data matches the original source.
3. What are the five types of discrepancies you might find during validation? Answer: Typo, missing data, extra data, missing
record and calculation error.
4. What Excel tool prevents invalid data entry? Answer: Data Validation (Data tab > Data Validation).
5. Why should you never correct data based on memory? Answer: Memory is unreliable. Always check the source document
to confirm the correct value.
