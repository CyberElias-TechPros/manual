# HTML Basics

## A. Session Identification
<!-- kind:identification -->
**Week / module:** Week 1 — Module 1: HTML Foundations

**Recommended duration:** 105 minutes

**Difficulty:** Beginner

**Prerequisite knowledge:** Session 1 — How the Web Works. The learner can set up a webdesign-practice folder, create index.html , save it, and open it in Chrome. Connection to previous session In Session 1 learners saw the shape of an HTML file and opened a page. This session explains the language properly: tags, elements, attributes, document structure, text, lists and comments.

**Preparation before class:** Academy PCs on; VS Code and Chrome open; webdesign-practice folder present; a sample image images/logo.png (or images/sample.jpg ) placed in each learner's folder; a demo file prepared for Section G; projector connected. Running project We continue building Adaeze Fashion. This session we replace the rough home page with a properly structured one using headings, paragraphs, lists, bold/italic and comments.

## B. Learning Outcomes
<!-- kind:outcomes -->
By the end of this session, the learner will be able to:
1. Explain what HTML is and state clearly that it describes structure and meaning, not appearance.
2. Write a complete HTML document with the correct order: <!DOCTYPE html> , <html> , <head> , <title> , <body> .
3. Define and distinguish a tag, an element and an attribute, giving one example of each.
4. Use headings h1 – h6 in the correct hierarchy and explain why there should normally be one h1 per page.
5. Add paragraphs with <p> and explain how the browser spaces them.
6. Create unordered and ordered lists using <ul> , <ol> and <li> correctly, and choose the right one for a given situation.
7. Apply bold, italic and importance using <strong> , <em> , <b> and <i> , and explain the difference between looks and
meaning.
8. Use line breaks <br> and horizontal rules <hr> appropriately, including when not to use them.
9. Write HTML comments with <!-- --> and explain why they help.
10. Nest and indent elements correctly so the code is readable and valid.

D. OPENING ACTIVITY (~6 minutes)
"The Tag Game"
Instructor setup. On the whiteboard, write a plain sentence: Welcome to Adaeze Fashion . Have a marker ready. Optionally hand
one learner a strip of paper with a tag printed on it ( <h1> , </h1> , <p> , <em> ).
What the instructor says:
"Look at this sentence on the board: Welcome to Adaeze Fashion. That is just text. Nothing tells a computer what it is. Is it a
heading? A paragraph? A warning?
In HTML, we wrap content in tags to say what it is. Watch."
- Write around it:] <h1>Welcome to Adaeze Fashion</h1>
"The <h1> at the front says: 'This is the main heading.' The </h1> at the end says: 'The heading stops here.' Tags are like
labels on jars. The jar holds the content; the label says what the content is."
- Now write:] This gown costs <strong>₦25,000</strong>
"Here <strong> says: 'This part is important.' The browser will show it in bold. Every single thing on every website is
content wrapped in tags like this."
Expected learner response. Learners grasp that tags are labels, not decoration, and often try to guess other tags (e.g. "what tag
makes it red?"). Use that: "Making it red is CSS — next week. Today we label what things are."
Why this opener works. It turns an abstract idea (markup) into a physical action (wrapping words on the board) and
immediately corrects the biggest confusion — that tags are about structure, not looks.
E. PREREQUISITE REVIEW (~7 minutes)
Run as an oral round-robin; put the questions on the projector.
Question 1: "What is the difference between the internet and the web?"
Expected answer: The internet is the network; the web is the content/pages on it.
Gap: Learners reverse them. Reuse the road/building analogy in one sentence.
Question 2: "What do we call the complete set of a file's letters after the dot, and what extension do web pages use?"
Expected answer: file extension; .html .
Gap: Some forget the extension controls behaviour. Remind them of the .txt trap.
Question 3: "What are the three building blocks of a website, and what does each do?"
Expected answer: HTML (structure), CSS (appearence), JavaScript (behaviour).
Gap: If they say "HTML is the design", correct now with the house analogy.
Question 4: "In the file webdesign-practice/images/logo.png , what does the / do?"
Expected answer: It shows a path — go into the images folder to find logo.png . Forward slash separates folders.
Gap: Some write backslashes. Remind: web paths use forward slashes.
Question 5: "After you change code, what two things must you do to see the change?"
Expected answer: Save ( Ctrl + S ) and refresh the browser ( F5 ).
Gap: This is the most common failure. Drill it now.
Bridge to today (say this):
"Last session you met the shape of an HTML page. Today we open it up. You will learn the words HTML uses for everything
— headings, paragraphs, lists, bold and italic — and how to arrange them neatly. By the end, you will write a proper

Gap handling. If several learners cannot recall HTML/CSS/JS roles, spend two extra minutes with the house analogy before
continuing. If many cannot save-and-refresh, pair them with confident learners for the whole session.
F. FULL LECTURE NOTES (~40 minutes)
F.1 What HTML is (and is not)
The idea. HTML stands for HyperText Markup Language. It is the language we use to describe the structure and meaning of a
web page — what each piece of content is.
Plain-English definition. HTML wraps content in tags so the browser knows "this is a main heading", "this is a paragraph", "this
is a list of items". It is a markup language, not a programming language: it does not calculate, decide or repeat. It simply labels.
Why it exists. A browser needs to know the role of each piece of content so it can display it sensibly, and so that other software
— screen readers for blind users, search engines, and printing tools — can understand it too. Without structure, everything
would be one grey blob of text.
Familiar analogy. Think of labelling boxes in a storeroom. You have boxes of "shoes", "shirts", "caps". The boxes hold the
goods; the labels tell everyone what is inside. HTML is the labelling system for web content. CSS is the paint on the shelves
(appearance). JavaScript is the forklift (behaviour).
Worked example.
```text
<h1>Adaeze Fashion</h1>
<p>We sew beautiful custom clothing in Port Harcourt.</p>
```
The <h1> says "this is the most important heading on the page". The <p> says "this is a paragraph". The browser shows the
heading large and bold and the paragraph in normal text — but that sizing is only a default; CSS can change it later.
Misconception. "HTML is a programming language." It is not. There is no logic, no maths, no decisions. Calling it a
programming language confuses beginners into expecting it to "do" things. It only describes.
Limitation. HTML alone gives an ugly page (plain black text on white). It cannot make things pretty or interactive. That is fine —
it is not its job.
F.2 Tags, elements and attributes — the vocabulary
These three words are used constantly. Learn them exactly.
Tag. A tag is a keyword inside angle brackets < > . There are two kinds:
Opening tag: <p> — starts an element.
Closing tag: </p> — ends an element. Notice the forward slash / before the name.
Some tags have no closing tag because they hold no content; these are called void (or self-closing) elements, for example
<br> , <hr> and <img> .
Element. An element is the whole package: opening tag + content + closing tag.
```text
<p>Hello, Port Harcourt!</p>
```
The element above is a paragraph element. "Element" is the thing; "tag" is the marker.
Attribute. An attribute gives extra information about an element. It goes inside the opening tag and almost always has a
name and a value in quotes.
```text
<a href="https://www.cea.ng">Visit Cyber Elias Academy</a>
```
href is the attribute name (here: where the link goes).
"https://www.cea.ng" is the attribute value, in quotes.
Why attributes exist. A tag like <a> says "this is a link", but it does not say where the link goes. Attributes supply that missing
detail.
Worked example — one element with two attributes:
```text
<img src="images/logo.png" alt="Adaeze Fashion logo">
```
src = the file path of the image.
alt = the alternative text (read aloud by screen readers, shown if the image fails to load).
Rules to remember.
1. Tags are not case-sensitive, but write them in lowercase — it is the standard and looks professional.
2. Every element that holds content needs a closing tag: <p> … </p> .
3. Attribute values go in quotes — use double quotes " and be consistent. (On a Nigerian keyboard, the double-quote key is
usually Shift + the apostrophe key near the Enter key.)
4. Elements must be properly nested — the last one opened is the first one closed.
Misconception. "Any tag in angle brackets is fine." No — misspell a tag (e.g. <paragrap> ), and the browser ignores it or treats it
as an unknown element. Spelling matters.
F.3 The document structure — the skeleton of every page
Every HTML page follows the same shape. Learn it once and use it forever.
```text
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Adaeze Fashion — Home</title>
</head>
<body>
  <h1>Welcome to Adaeze Fashion</h1>
  <p>Beautiful custom clothing made in Port Harcourt.</p>
</body>
</html>
```
Line by line:
<!DOCTYPE html> — the DOCTYPE. It is not a tag exactly; it is a declaration that tells the browser "this is an HTML5
document". It must be the very first line. Without it, browsers may switch to a slow, old-fashioned "quirks" mode.
<html lang="en"> — the root element. Everything lives inside it. lang="en" declares the page language as English, which
helps screen readers pronounce words correctly.
<head> — a hidden section holding information about the page — not shown on the screen.
<meta charset="UTF-8"> — tells the browser which characters to use, so the Naira sign (₦) and accents show correctly.
UTF-8 means "universal character set".
<title>…</title> — the words shown on the browser tab (and used by search engines as the clickable link).
</head> — closes the head.
<body> — everything visible on the page goes inside here: headings, paragraphs, lists, images, links.
</body> — closes the body.
</html> — closes the document.
Worked example — expected browser result.
The tab shows: "Adaeze Fashion — Home".
The page shows: a large bold heading Welcome to Adaeze Fashion and beneath it the sentence Beautiful custom clothing
made in Port Harcourt.
Why the head is separate. Mixing page information (title, character set) with page content would be messy. The head is the
page's "identity card"; the body is the page's "face".
Misconception. "Everything I write appears on the page." Not true — anything in the <head> (like the <title> ) is not shown on
the page itself, only on the tab.
F.4 Headings h1 – h6
The idea. Headings give a page a structure in levels, like the chapters and sub-chapters of a book. HTML gives six levels: <h1>
(most important) down to <h6> (least important).
Plain-English definition. A heading is a short piece of text that names a section of content.
Why they exist. Readers skim; headings help them find things fast. Screen readers let blind users jump between headings.
Search engines use them to understand what a page is about.
Familiar analogy. A table of contents in a textbook:
<h1> = the book title.
<h2> = the chapter titles.
<h3> = sub-sections inside a chapter. …and h4 – h6 go deeper still.
Worked example (runnable).
```text
<h1>Adaeze Fashion</h1>
<h2>Our Services</h2>
<h3>Custom Gowns</h3>
<p>We design gowns for weddings and celebrations.</p>
<h3>Corporate Uniforms</h3>
<p>We supply neat uniforms for schools and offices.</p>
```
Expected result. Adaeze Fashion is the largest; Our Services is smaller; the two <h3> sub-headings are smaller still. The
paragraphs are normal-sized text.
Rules and good habits.
Use one <h1> per page — it names the whole page.
Do not skip levels for looks (do not jump from h1 straight to h4 ). The level expresses meaning, not size.
Do not use headings just to make text big. That is CSS's job.
Misconception. " <h4> is just a smaller font, so I can use it whenever." No — the number is a level of importance. A page that
jumps h1 → h5 confuses screen readers.
A note for the teacher: the browser's default sizes for h1 – h6 can be changed with CSS later; do not let learners think the size
is the meaning.
F.5 Paragraphs <p>
The idea. A paragraph is a block of running text. Wrap it in <p> … </p> .
Worked example.
```text
<p>Adaeze Fashion was founded in Port Harcourt in 2019.</p>
<p>We believe every customer deserves clothing that fits perfectly.</p>
```
Expected result. Two separate blocks of text, with a small gap between them. The browser automatically adds space before
and after each paragraph.
Why paragraphs matter. They create natural reading blocks. If you write text without <p> , the browser glues lines together into
one run-on block regardless of how you typed them in the file.
Worked example — the "glue" problem.
```text
<p>
  First line in the file.
  Second line in the file.
  Third line in the file.
</p>
```
Expected result. All three lines appear as one continuous paragraph. The browser ignores the line breaks you typed in the
code. (If you truly want a forced break, you use <br> — see F.8.)
Misconception. "Pressing Enter in my code creates a new line on the page." It does not. Only tags control the output.
F.6 Lists — <ul> , <ol> and <li>
The idea. Lists present a group of items. There are two kinds:
Unordered list <ul> — items shown with bullet points; order does not matter.
Ordered list <ol> — items shown with numbers; order matters.
Every item in either list is wrapped in <li> (list item).
Unordered example.
```text
<ul>
  <li>Ankara gowns</li>
  <li>Corporate uniforms</li>
  <li>Bridal wear</li>
</ul>
```
Expected result: three bulleted lines:
Ankara gowns
Corporate uniforms
Bridal wear
Ordered example.
```text
<ol>
  <li>Choose your fabric</li>
  <li>Take your measurements</li>
  <li>We sew your outfit</li>
  <li>Collect your order</li>
</ol>
```
Expected result: the same four items, but numbered 1, 2, 3, 4.
How to choose. Ask: does the order change the meaning?
A list of services → order does not matter → <ul> .
Steps in a process → order matters → <ol> .
Nesting. An <li> can contain other elements, including another list:
```text
<ul>
  <li>Women's wear
    <ul>
      <li>Gowns</li>
      <li>Skirts</li>
    </ul>
  </li>
  <li>Men's wear</li>
</ul>
```
Expected result: "Women's wear" and "Men's wear" as top bullets; "Gowns" and "Skirts" indented underneath.
Misconception. "I can put text directly inside <ul> without <li> ." The rule: inside <ul> or <ol> , items must be wrapped in
<li> . Text placed directly inside the list is invalid and shows unpredictably.
F.7 Bold, italic and importance — <b> , <i> , <strong> , <em>
The idea. Four tags control emphasis in text, but they are not all the same:
<strong> — says "this is important". Shown bold.
<em> — says "this is emphasised". Shown italic.
<b> — makes text bold but carries no special meaning.
<i> — makes text italic but carries no special meaning.
Plain-English difference. <strong> and <em> carry meaning; <b> and <i> are purely visual. Meaning matters to screen
readers, which can change their tone for <strong> and <em> .
Rule of thumb. Prefer <strong> and <em> . Use <b> and <i> only when you want bold/italic with no extra meaning (for
example a foreign word in <i> ).
Worked example.
```text
<p>Our <strong>opening hours</strong> are Monday to Saturday, <em>9am to 6pm</em>.</p>
```
Expected result: "opening hours" appears bold; "9am to 6pm" appears in italics.
Misconception. " <strong> and <b> are exactly the same." They look the same by default, but they mean different things, and a
screen reader treats them differently. Prefer the meaningful one.
F.8 Line breaks <br> and horizontal rules <hr>
The idea.
<br> forces a line break inside the current block (like pressing Enter once in a letter).
<hr> draws a horizontal rule — a full-width line — used to mark a change of topic.
Both are void elements: they have no closing tag and no content.
Worked example.
```text
<p>Adaeze Fashion<br>
24/26 Ebony Road<br>
Port Harcourt, Rivers State</p>
```
```text
<hr>
```
```text
<p>Thank you for visiting our website.</p>
```
Expected result: the address appears on three separate lines because of the <br> tags, then a horizontal line across the page,
then the thank-you sentence.
When NOT to use them.
Do not use many <br> tags to add space between paragraphs — use separate <p> elements, or CSS later.
Do not use <br> to lay out a page in columns — that breaks on phones and is not real layout.
Misconception. " <br> is how I make a new paragraph." <br> makes a line break; <p> makes a new paragraph block with
spacing. They are different tools.
F.9 Comments <!-- -->
The idea. A comment is a note in the code that the browser ignores completely. It is never displayed on the page.
Why they exist. To explain your code to yourself, your team-mates, or your future self. A comment like <!-- Start of products
section --> saves minutes when you return to a file months later.
Worked example.
```text
<!-- ===== Header ===== -->
<h1>Adaeze Fashion</h1>
```
```text
<!-- The navigation links will go here in a later session -->
```

F.10 Nesting and indentation — keeping code readable
The idea. Nesting means putting elements inside other elements. Indentation means using spaces or Tab to push inner
elements to the right so you can see the structure.
Why nesting matters. HTML is a tree. The <html> contains <body> , which contains a <ul> , which contains <li> items. If you
close the wrong tag, the tree breaks and the page misbehaves.
The nesting rule. The last element opened is the first one closed (like brackets in maths).
```text
<p>This is <strong>very important</strong> news.</p>
```
Correct: <strong> opens and closes inside the <p> .
```text
<p>This is <strong>very important.</p></strong>
```
Incorrect: the tags cross over each other. The browser will guess, producing unpredictable results.
Indentation example — hard to read:
```text
<body><h1>Adaeze Fashion</h1><ul><li>Ankara gowns</li><li>Uniforms</li></ul></body>
```
Indented version — easy to read:
```text
<body>
  <h1>Adaeze Fashion</h1>
  <ul>
    <li>Ankara gowns</li>
    <li>Uniforms</li>
  </ul>
</body>
```
The browser treats both the same, but humans find the second far easier to check and fix.
VS Code tip. Select the code and press Shift + Alt + F to auto-format (fix indentation) if the extension is available. Or press Tab
to indent and Shift + Tab to un-indent. Set indentation to 2 spaces for this course.
Misconception. "Indentation changes how the page looks." It does not — indentation is for humans. But it prevents mistakes,
which is why professionals always do it.

## K. Common Mistakes and Troubleshooting
<!-- kind:troubleshooting -->
Use this table for live troubleshooting. Do not answer at once — point the learner to the relevant row.
K.1 Missing closing tag — style leaks to later content
Symptoms: A heading or bold text seems to "bleed" onto the next paragraph; the layout looks stretched. Likely cause: An
opening tag was never closed (for example <h1> without </h1> ). How to investigate: Check each opening tag has a matching
closing tag; look for a tag that has no / partner. Corrective steps: Add the missing closing tag. How to confirm resolved:
The next content returns to its normal size/style. Prevention: Type the opening tag, then immediately type the closing tag, then
fill in the content between them.
K.2 List items have no bullets or numbers
Symptoms: A list shows as plain text lines, or the bullets vanish. Likely cause: The items are not wrapped in <li> , or the items
were placed outside <ul> / <ol> . How to investigate: Check that every item sits between <li> and </li> , inside the list tag.
Corrective steps: Wrap each item in <li> … </li> . How to confirm resolved: Bullets or numbers appear. Prevention: Type the
list opening tag and one empty <li></li> first, then duplicate.
K.3 Text runs together / no paragraph spacing
Symptoms: Several sentences form one block with no gaps. Likely cause: Text was typed in the body without <p> tags, or line
breaks in the code were expected to work. How to investigate: Check whether the text is wrapped in <p> … </p> . Corrective
steps: Wrap each paragraph in <p> tags. Use <br> only for a forced line break inside a paragraph. How to confirm resolved:
Clear gaps appear between paragraphs. Prevention: One idea = one <p> .
K.4 Wrong heading level / too many h1 s
Symptoms: The page has several huge headings; sections are confusing. Likely cause: Using <h1> for everything, or picking
levels by size rather than meaning. How to investigate: Count the <h1> s — there should normally be one. Corrective steps:
Keep one <h1> ; use <h2> for sections and <h3> for sub-sections. How to confirm resolved: A clear, single-level hierarchy.
Prevention: Choose the level for meaning, not looks.
K.5 The document does not show correctly / page blank
Symptoms: Blank page or odd rendering. Likely cause: Content typed outside <body> , or a mis-typed tag name. How to
investigate: Check the content sits between <body> and </body> ; check tag spelling. Corrective steps: Move content into the
body; fix spelling. How to confirm resolved: The page draws correctly. Prevention: Use the document skeleton every time.
K.6 Naira sign (₦) or accents show as ?
Symptoms: The ₦ symbol shows as ? or a box. Likely cause: Missing <meta charset="UTF-8"> , or the file saved in the wrong
encoding. How to investigate: Check the charset line; check VS Code's bottom-right encoding label. Corrective steps: Add
the charset line; Save with Encoding → UTF-8. How to confirm resolved: ₦ displays. Prevention: Keep charset in every page
from the start.
Distinguish likely vs confirmed. A likely cause becomes confirmed only after checking (seeing the missing tag, the absent
<li> , the charset line). Teach learners to confirm before fixing.

## M. Knowledge Check
<!-- kind:knowledge_check -->
(Learner version — answers in the Instructor Key below.)

Q2. Short answer. Explain the difference between a tag and an element in one sentence each.
Q3. Error detection. Find the mistake and correct it: <p>Come and see our <strong>latest designs.</p></strong>
Q4. Multiple choice. For a numbered list of steps where order matters, which tag do you use? a) <ul> b) <ol> c) <li> d) <p>
Q5. Explain in your own words. Why should a page normally have only one <h1> ?
Q6. Fill in the blanks. In the document structure, the ________ contains information about the page (like the title), and the
________ contains everything that is visible on the page.
Q7. Practical identification. Look at this line: <a href="https://www.cea.ng">Cyber Elias Academy</a> . Which part is the attribute,
and what is its value?
Q8. Scenario. A learner writes a paragraph across three lines in the code, expecting three lines on the page — but the browser
shows one block. Why, and what tag would force a line break?
INSTRUCTOR ANSWER KEY (Q1–Q8)
A1. (c) <br> — it is a void element. ( <img> and <hr> are other examples.)
A2. A tag is the marker in angle brackets (e.g. <p> or </p> ). An element is the whole package: opening tag + content +
closing tag (e.g. <p>Hello</p> ).
A3. The tags cross over (nesting error). Correct: <p>Come and see our <strong>latest designs.</strong></p> — the <strong> must
open and close inside the <p> .
A4. (b) <ol> .
A5. Because the <h1> names the whole page; a page has one main topic. Multiple <h1> s confuse screen readers and search
engines. Sections use <h2> and below.
A6. The head contains information about the page; the body contains the visible content.
A7. The attribute is href ; its value is https://www.cea.ng . (The visible text "Cyber Elias Academy" is the content, not the
attribute.)
A8. The browser ignores the line breaks you type in the code — they are for the human reader only. To force a visible line break
inside a paragraph, use <br> . (For a new paragraph, use a new <p> .)

Suggested remedial exercises.
1. "Close the tags" drill: hand out five lines each missing one closing tag; learners fix and check in the browser.
2. List sorting: give ten scenarios (a menu, a recipe, a shopping list, a to-do order) and ask <ul> or <ol> for each.
3. Nesting cards: write tags on paper strips ( <p> , <strong> , </p> , </strong> ) and ask learners to arrange them correctly,
then type the result.
Differentiation.
Level 1 (supported): Provide a skeleton file with the document structure and empty <p> , <ul> , <ol> already in place;
learners fill in content. Pair with a confident learner and allow extra time.
Level 2 (standard): Complete the exercises and assignment as written.
Level 3 (challenge): Add a nested list (a services list with sub-items), use h3 sub-sections under an h2 , and research the
<abbr> element (for abbreviations) and use it once with a title attribute.
