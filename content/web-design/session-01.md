# How the Web Works

## A. Session Identification
<!-- kind:identification -->
**Week / module:** Week 1 — Module 1: HTML Foundations

**Recommended duration:** 105 minutes

**Difficulty:** Beginner (first contact with web design)

**Prerequisite knowledge:** Basic computer skills: creating folders, saving files, using a browser, typing. A learner with no prior coding experience is expected and welcome.

**Connection to previous work:** This is the first session of Web Design. It sets the foundation every later session builds on.

**Preparation before class:** Academy PCs on and logged in; Google Chrome installed; Visual Studio Code installed; projector connected to the instructor machine; a folder webdesign-practice created on each learner Desktop (or the learners create it in Section H); a simple demo HTML file prepared for Section G. Running project Across the whole course we are building a small business website for Adaeze Fashion, a clothing business in Port Harcourt. This session we simply meet the idea of a website and set up the tools.

## B. Learning Outcomes
<!-- kind:outcomes -->
By the end of this session, the learner will be able to:
1. Explain in their own words what happens, step by step, when a person types a website address (URL) into a browser and
presses Enter.
2. Describe what a web browser is and name at least three popular browsers used today.
3. Describe what a web server is and explain, in simple language, how it delivers a webpage to a browser.
4. Distinguish between local files (files sitting on your own computer) and live websites (files served to anybody on the
internet).
5. Identify the three core languages of a webpage — HTML, CSS and JavaScript — and state what each one does, using the
house analogy.
6. Explain what a file extension is and correctly name the extensions .html , .css , .jpg / .png and recognise a website
address (URL) when they see one.
7. Explain the difference between a relative path and an absolute path, and read a simple file path such as images/logo.png .
8. Set up a workspace in Visual Studio Code using the folder webdesign-practice .
9. Create, save and open a simple index.html file in Google Chrome without help.

One computer per learner (academy desktops). Sharing one machine between two learners is acceptable — pair them so

Instructor computer connected to a projector or large screen.

Instructor prepares a tiny file demo/index.html to show the "magic trick" in Section D (contents given in Section G). It

Optional: a small image file such as logo.png to demonstrate that a webpage can show pictures.
Worksheets / printed materials
Worksheet 1.1 — "The Journey of a URL" (one page, with four blank boxes to fill in).
Worksheet 1.2 — "Label the House" (a simple house drawing with three blank labels for HTML, CSS, JavaScript).

Internet
Not required for this session — all work is done on local files. If the academy has Wi-Fi, the instructor may optionally open a

Any laptop with Chrome and VS Code works. If a learner has only a phone, pair them with a desktop user for the session;

D. OPENING ACTIVITY (~6 minutes)
"The Magic Trick"
Instructor setup: On the projector, open the prepared demo/index.html file in Chrome. It should show a short heading and a
paragraph (for example: "Welcome to Adaeze Fashion" and "Beautiful clothes made in Port Harcourt."). Do not show the code yet
— show only the finished page.
What the instructor says:
"Good morning, everyone, and welcome to Web Design at Cyber Elias Academy. Before we type a single line, I want to
show you a small magic trick.
Look at this screen. What do you see? … A beautiful page with words on it. Adaeze Fashion — a clothing business right
here in Port Harcourt. Now watch carefully."
- Right-click on the page → View Page Source (or press Ctrl + U ).]
"Do you see this jumble of words with little marks like <h1> ? This is what makes the page. Every website you have ever
visited — Google, your bank, Jumia, your church's page — is built from text like this. It is not magic; it is a language, and it
has rules.
By the end of this course you will write this language yourself. Today we start by understanding how the whole web works
— because you cannot build a house well if you do not know what a house is for."
Expected learner response: Curiosity and some nervousness. Learners may say the code looks "hard" or "like a virus". Reassure
them:
"It looks strange today. In four weeks it will read like plain English. I promise."
Some learners may recognise the tags and say "that's HTML". Praise them and say, "Exactly — and today we find out what
HTML really is and where it fits."
Why this opener works: It creates a small surprise (the page is "hiding" code), connects the work to a familiar local business,
and removes the fear that coding is magic. It also gives the session a clear destination: by the end, they will do this themselves.
E. PREREQUISITE REVIEW (~7 minutes)
Run this as a quick oral round-robin. Put the questions on the projector. Every learner should answer at least one. These check
the basic computer skills the course assumes.
Question 1: "How do you create a new folder on the Desktop?"
Expected answer: Right-click an empty space → New → Folder → type a name → press Enter.
Common gap: A learner may only know phones, not Windows. Show them physically on one machine.
Question 2: "What is a file extension? Give one example."
Expected answer: The letters after the dot in a file name — for example .html , .css , .jpg , .txt . It tells the computer
what kind of file it is.
Common gap: Learners confuse the dot in a sentence with the dot in a file name, or think the extension is the whole name.
Question 3: "What is the difference between a file and a folder?"
Expected answer: A file is a single piece of information (a document, an image). A folder is a container that holds files and
other folders.
Common gap: Some learners call everything a "document". Use the analogy below.
Question 4: "How do you save a file, and then how do you see changes in a browser?"
Expected answer: Ctrl + S to save; then refresh the browser with F5 (or Ctrl + R ).
Common gap: Learners change code but forget to save, then wonder why nothing changed. This is the number-one
beginner habit to fix, so repeat it now.
Question 5: "Name one web browser you have used."
Expected answer: Chrome, Firefox, Edge, Opera, Safari, or a phone browser. Any is fine.
Bridge to today (say this):
"Good. You can make folders, save files and use a browser. That is all you need to be a web designer. Think of a website as
a house you are building:
HTML is the walls, doors and rooms — the structure and the contents.
CSS is the paint, tiles and curtains — the appearance.
JavaScript is the electricity and plumbing — the things that do something.
Before we can build the house, we must understand the village it stands in. That village is the web. Let us begin."
Gap handling: If more than a third of the class cannot create a folder or save a file, pause and do it physically with each
struggling learner while the rest begin Section F quietly. Do not skip this — every later session depends on it. Pair strong learners
with weak ones for the rest of the day.
F. FULL LECTURE NOTES (~40 minutes)
F.1 What the internet is, and how it differs from the web
The idea. The internet is a very large number of computers connected together so they can send information to one another.
The World Wide Web (usually just "the web") is the collection of pages and websites that travel over that connection.
Plain-English definition.
Internet = the network of cables, routers, satellites and computers that connect the world. It is the infrastructure.
World Wide Web = the websites and web pages you look at through that infrastructure. It is the content.
Why they exist. People needed a way to send messages and share documents between computers far apart. The network
(internet) came first. Later, someone invented an easy way to link documents together so they could be read with a click — that
is the web.
Familiar analogy. Think of roads and buildings.
The internet is the road network: streets, bridges, junctions. You drive on it but it is not a destination.
The web is the buildings along the roads: shops, schools, offices. They are what you actually visit.
You need the roads to reach the buildings, but the roads and the buildings are not the same thing.
A short, honest history. The internet grew out of research networks in the 1960s. The World Wide Web was invented in 1989 by
Tim Berners-Lee, who wanted scientists to share documents easily. He created the first web browser and the first website. (Do
not quote exact user numbers or dates you have not verified — the point is simply that the web is younger than the internet.)
Misconception to correct. "The internet and the web are the same thing." They are not. You can use the internet to send an
email or make a WhatsApp call without visiting a web page at all. Email and video calls use the internet but are not "the web".
Limitation / honesty note. A learner does not need to know the deep technical details of cables and satellites to design
websites. They need the difference between getting to a page and the page itself, and that is what the analogy gives them.
F.2 What happens when you type a URL — the journey, step by step
This is the heart of the session. Write these steps on the whiteboard as you explain them, and have learners fill in Worksheet 1.1.
First, what is a URL? URL stands for Uniform Resource Locator. In plain English it is a web address — the words you type to
reach a page. Example: https://www.adaezefashion.com/products.html .
Step 1 — You type the address and press Enter. Your browser (Chrome) reads what you typed.
Step 2 — The browser asks DNS for directions. Computers do not really use names like adaezefashion.com ; they use numbers
called IP addresses (for example 192.0.2.10 ). DNS stands for Domain Name System. It is like the contacts app on your phone:
you tap a name, and the phone finds the number. DNS takes the name you typed and finds the number (IP address) of the
computer that holds the website.
Step 3 — The browser sends a request to the server. The browser now travels across the internet to the correct server and
asks: "Please give me the page products.html ." This request is called an HTTP request (HTTP means HyperText Transfer
Protocol — simply, the agreed set of rules computers use to ask for and send web pages).
Step 4 — The server responds. The web server is a computer that stores the website's files. It finds products.html (plus the
CSS file, the images, and so on) and sends them back to your browser. This is called the HTTP response.
Step 5 — The browser renders the page. "Rendering" means drawing the page on the screen. The browser reads the HTML
(structure), applies the CSS (appearance) and runs the JavaScript (behaviour), then paints the finished page for you. All of this
usually takes a fraction of a second.
Analogy for the whole journey — ordering food.
1. You decide what you want and place the order (typing the URL).
2. The waiter checks the kitchen's address (DNS finding the IP).
3. The waiter carries your order to the kitchen (the request).
4. The kitchen cooks the food and sends it out (the response).
5. The waiter brings it to your table and you eat (the browser renders the page).
Worked example — follow www.adaezefashion.com/index.html together:
1. Browser reads www.adaezefashion.com/index.html .
2. DNS finds that adaezefashion.com lives at, say, 192.0.2.10 .
3. Browser asks that server for index.html .
4. Server sends back the HTML text, the CSS file and the images.
5. Browser draws Adaeze's home page — the logo, the headings, the colours.
Misconceptions.
"The browser keeps the website inside it." No — the browser asks the server each time (though it may keep a cache, a saved
copy, to load faster next time).
"Typing a URL downloads the whole website at once." No — the browser asks for the HTML first, then requests the images
and CSS it discovers inside.
Limitation. Real web servers, DNS and security (HTTPS) have many more details. For now, this five-step picture is accurate
enough to build on, and every later session fits inside it.
F.3 Clients and servers — who asks and who answers
The idea. In every web conversation there are two roles:
The client — the computer (and program, like the browser) that asks for information.
The server — the computer that holds the information and answers.
Plain-English definition. A client requests; a server serves.
Why it matters. When you look at your own file in the browser, there is no server involved yet. When you publish your site, you
put your files on a server so that any client in the world can ask for them. Understanding this stops learners being confused later
when "it works on my computer but not online".
Analogy. A customer and a shopkeeper. You (the client) ask for a product; the shopkeeper (the server) has it in stock and hands
it over. The shopkeeper must be open and stocked for the customer to succeed.
Worked example. Your friend in Lagos opens www.adaezefashion.com on their phone.
Their phone is the client.
The computer in the data centre holding Adaeze's site is the server.
The client asks; the server answers with the page. Adaeze does not have to be online at that moment — the server works for
her around the clock.
Misconception. "The server is the same as the internet." No — the internet is the road; the server is a building on the road where
your files live.
F.4 The three building blocks: HTML, CSS and JavaScript
The idea. Every webpage is made from three languages, each with one clear job.
Language Full name Job Plain sentence
HTML HyperText Markup Language Structure and content What is on the page
CSS Cascading Style Sheets Presentation and appearance How it looks
JavaScript JavaScript Behaviour and interactivity How it responds
Plain-English definitions.
HTML is a markup language: it "marks up" content with tags so the browser knows what each part is (this is a heading, this
is a paragraph, this is an image). It is not a programming language — it does not calculate or decide.
CSS is a styling language: it sets colours, fonts, spacing and layout. Without CSS, every page is plain black text on a white
background.
JavaScript is a programming language: it can make decisions and react to clicks and typing. It runs inside the browser. (We
touch JavaScript only lightly in this course — full JavaScript is the separate Web Development course.)
Why three, not one. Fighting one language would be messy. If structure, appearance and behaviour are mixed together,
changing a colour means hunting through the content, and one mistake can break everything. Separating the three jobs keeps a
website clean, easy to update and easy to reuse. This idea is called separation of concerns.
The house analogy (learn this by heart).
HTML = structure: the walls, rooms, doors, roof — the shape of the house and what is inside it.
CSS = appearance: the paint, tiles, furniture and curtains.
JavaScript = behaviour: the electricity, plumbing, lights and doorbell — the parts that do something.
A house with only structure and appearance is beautiful but dead. Add behaviour and the lights come on.
Worked example — the same page, three layers.
```text
<!-- HTML: the structure and content -->
<h1>Adaeze Fashion</h1>
<p>Beautiful clothes made in Port Harcourt.</p>
```
```text
/* CSS: the appearance */
h1 { color: #8B0000; text-align: center; }
p  { font-size: 18px; }
```
```text
/* JavaScript: the behaviour (we only peek at this for now) */
button.onclick = function () { alert("Thank you for your order!"); };
```
Misconception. "HTML is the design." No — HTML is the structure. It says what the content is, not how pretty it looks. Many
beginners think making text bigger in HTML is "design"; real design happens in CSS.
Limitation. Three building blocks are the foundation, but a modern site may also use frameworks and backend code. For a
small business website (which is our goal), HTML and CSS alone can produce a professional result.
F.5 File types, extensions and what they mean
The idea. A file extension is the group of letters after the final dot in a file name. It tells the computer (and the browser) what
kind of file it is and how to open it.
Common web file types:
Extension Full name What it is Example
```text
.html
```
HyperText Markup Language A web page — the structure and content
```text
index.html
```
```text
.css
```
Cascading Style Sheets The styling file
```text
style.css
```
.jpg / .jpeg JPEG image A photograph
```text
model.jpg
```
```text
.png
```
Portable Network Graphics An image, often with transparency
```text
logo.png
```
```text
.gif
```
Graphics Interchange Format A simple image or animation
```text
banner.gif
```
```text
.svg
```
Scalable Vector Graphics A sharp logo that never blurs
```text
logo.svg
```
Why extensions matter. If you save a web page as index.txt , the computer thinks it is plain text. The browser will show the
code instead of the page. Saving as index.html tells the browser "draw this as a web page".
Worked example. You type your first page in Notepad and press Save As. If you type the name index and Notepad adds .txt ,
your file becomes index.txt and it opens wrongly. The fix: name it index.html , or choose "All files" in the Save As dialog.
Misconception. "The extension is optional." It is not — it decides how the file behaves. Also watch out: Windows sometimes
hides file extensions, so learners cannot see the .html at all. Show them how to turn on "File name extensions" in the View
menu of File Explorer.
Naming rules (good habits).
Use lowercase: index.html , not Index.HTML .
No spaces — use a hyphen instead: my-photo.jpg , not my photo.jpg .
Keep names short and meaningful.
F.6 Local files versus live websites
The idea.
A local file lives on your own computer and only you can open it. It has an address like C:\Users\Ada\Desktop\webdesign-
practice\index.html .
A live website lives on a server and anyone in the world can open it. It has an address like https://www.adaezefashion.com .
Why it matters. In this course, for most sessions, you will work with local files — fast, free and private. At the end of the course
you will publish (upload) your files to a server so the whole world can see Adaeze Fashion.
Analogy. A local file is a cake in your kitchen — only you can eat it. A live website is a cake in a shop window — anyone
passing by can see it. To move from kitchen to shop window, you must carry the cake to the shop: that is publishing.
Worked example.
You open C:\Users\Ada\Desktop\webdesign-practice\index.html in Chrome. Only Adaeze (the learner) sees it.
After publishing, you open https://adaezefashion.github.io . Now a customer in Abuja, Lagos or London can see the same
page.
Misconception. "If I finish my file on my computer, my website is already online." No — you must upload it to a server first.
This is why the course ends with a publishing session.
F.7 Folders and file paths (relative versus absolute)
The idea. A file path is the route to a file — like directions to a house. Because a website has several files (HTML, CSS, images),
the links between them use paths. If a path is wrong, the link or image breaks.
Two kinds of path:
Absolute path — the full address from the very top.
On your computer: C:\Users\Ada\Desktop\webdesign-practice\images\logo.png
On the web: https://www.adaezefashion.com/images/logo.png
It always points to the same place, no matter where the file using it lives.
Relative path — the route relative to the file you are in.
images/logo.png — "go into the images folder, then find logo.png ".
logo.png — "find logo.png in the same folder as this file".
../logo.png — "go up one folder, then find logo.png " (the .. means "up one level").
Why relative paths are used. They keep a website portable. If Adaeze moves her whole website folder from her laptop to a
server, relative paths still work, because they describe the arrangement of files, not one machine's exact location. Absolute paths
on your own computer ( C:\Users\Ada\... ) would break the moment the files moved to a server.
Analogy. Think of giving directions. An absolute direction is "24/26 Ebony Road, Off Rumuola Road, Port Harcourt". A relative
direction is "walk to the shop next door, then turn left". The relative direction only makes sense from where you are standing —
which is why we must get the current location right.
Worked example — the Adaeze project folder. Imagine this arrangement:
```text
webdesign-practice/
├── index.html
├── about.html
├── css/
│   └── style.css
└── images/
    └── logo.png
```
From index.html , to reach the logo you write images/logo.png .
From css/style.css , to reach the same logo you must go up one level first: ../images/logo.png .
Misconception. "A backslash and a forward slash are the same." On Windows file paths use backslashes ( \ ), but web paths
always use forward slashes ( / ). Writing images\logo.png in HTML can break on many servers. Always use / in HTML and
CSS.
F.8 The browser as a tool (and View Page Source)
The idea. The browser is not just a viewer — it is your most important testing tool. It reads HTML, CSS and JavaScript and draws
the result.
Popular browsers: Google Chrome (most widely used), Mozilla Firefox, Microsoft Edge, Safari (Apple devices), Opera. We use
Chrome because it has excellent built-in Developer Tools (which we meet fully in a later session).
The browser is an interpreter, not a creator. It does not "understand" English; it follows the rules of HTML and CSS. If you
make a mistake, the browser usually guesses and keeps going, which is why one small error may cause a strange result rather
than a clear alarm.
View Page Source — reading any website.
1. Open a website in Chrome.
2. Right-click anywhere → View page source (or press Ctrl + U ).
3. The code that builds the page appears.
This is a powerful learning habit: whenever you like how a page is built, view its source and read how it was done. (Look and
learn — but write your own code; do not copy a whole site, which may be protected by copyright.)
Worked example. Open a news site, press Ctrl + U , and search (in the source, press Ctrl + F ) for the headline you see. You
will find the headline text wrapped in HTML tags — proof that the page is built from text.
Misconception. "Looking at page source is hacking." It is not. The browser always receives the HTML; viewing it is a normal
feature. (Note that some sites hide their JavaScript and CSS, but the HTML is always visible.)
F.9 Introduction to Visual Studio Code — your workspace
The idea. A text editor is a program for writing code. The right editor colours and formats the code, helping you avoid
mistakes. This course uses Visual Studio Code (VS Code), which is free and one of the most popular editors in the world.
What a workspace is. A workspace is the set of tools and folders you use to build a website:
1. A text editor (VS Code) to write the code.
2. A browser (Chrome) to view the result.
3. A project folder ( webdesign-practice ) to hold all your files.
Why we open the whole folder, not single files. VS Code's strength is the Explorer panel on the left, which shows all your files
at once. Opening the folder lets you see index.html , the css folder and the images folder together, and create new files in the
right place.
Worked example — opening the workspace.
1. Open VS Code.
2. File → Open Folder… → choose webdesign-practice on the Desktop → Select Folder.
3. The Explorer shows your folder contents on the left.
4. Click the New File icon (a page with a small + ) → type index.html → Enter.
5. You now have a blank index.html ready to write.

F.10 A complete first page — read it line by line
Here is the page we will create together. For now you do not need to understand every tag (that is Session 2); you need to
recognise the shape of an HTML document and see it run.
```text
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Adaeze Fashion — Home</title>
</head>
<body>
  <h1>Welcome to Adaeze Fashion</h1>
  <p>Beautiful, well-made clothes designed in Port Harcourt.</p>
</body>
</html>
```
Line by line:
<!DOCTYPE html> — a declaration telling the browser "this is a modern HTML5 document". Always the first line.
<html lang="en"> — the root element; everything else lives inside it. lang="en" means the page's language is English (good
for accessibility and search engines).
<head> — a hidden section holding information about the page (not shown on screen).
<meta charset="UTF-8"> — tells the browser which characters to expect, so symbols like the Naira sign (₦) show correctly.
<title>…</title> — the words shown on the browser tab.
</head> — ends the head section.
<body> — everything visible on the page goes here.
<h1>…</h1> — the main heading.
<p>…</p> — a paragraph.
</body> and </html> — close the body and the whole document.
Expected browser result: the browser tab reads "Adaeze Fashion — Home"; the page shows the big heading Welcome to
Adaeze Fashion and below it the sentence "Beautiful, well-made clothes designed in Port Harcourt."
The planning note. This is the seed of our running project — Adaeze Fashion's home page. Over the course we will grow it into
a 3–5 page responsive website.
F.11 Summary of the lecture
The internet is the network; the web is the content on it.
Typing a URL triggers a five-step journey: type → DNS → request to server → response → render.
Clients ask; servers answer.
Three languages: HTML (structure), CSS (appearance), JavaScript (behaviour).
File extensions decide how a file behaves — always save pages as .html .
Local files are private; live websites are served to the world.
Relative paths ( images/logo.png ) keep a website portable; use forward slashes / .
The browser (Chrome) both displays and tests your work; View Page Source reveals any page's code.
VS Code is your editor; a workspace = editor + browser + project folder.

## K. Common Mistakes and Troubleshooting
<!-- kind:troubleshooting -->
Use this table as the session's live troubleshooting guide. When a learner hits a problem, do not give the answer at once — ask
them to check the relevant row.
K.1 The page shows the code instead of the finished page
Symptoms: Chrome displays the HTML text (tags and all) rather than a drawn page. Likely causes: The file was saved with an
extension like .txt instead of .html , or the browser treated it as text. How to investigate: Look at the full file name in File
Explorer (turn on "File name extensions" if they are hidden). It must end in .html . Corrective steps: In VS Code, rename the file
to index.html (or Save As with the correct extension). Reopen it in Chrome. How to confirm resolved: The browser now draws
the heading and paragraph. Prevention: Always type .html and turn on file-extension display in File Explorer.
K.2 The file opens but looks completely blank
Symptoms: A white page with nothing on it. Likely causes: Content was typed outside <body> , a tag was mistyped, or the file is
empty/unsaved. How to investigate: Open the code and check that the heading and paragraph sit between <body> and
</body> . Corrective steps: Move the content inside the body; check for typos in <h1> and <p> ; save. How to confirm
resolved: The heading and paragraph now appear. Prevention: Follow the document shape in Section F.10; save often.
K.3 Strange characters instead of ₦ or accents
Symptoms: The Naira sign or other characters show as ? or a box. Likely cause: The file was saved in the wrong text encoding.
How to investigate: Check that <meta charset="UTF-8"> is in the <head> . Corrective steps: In VS Code's bottom-right corner,
click the encoding, choose Save with Encoding → UTF-8; save. How to confirm resolved: The ₦ sign displays correctly.
Prevention: Always keep the <meta charset="UTF-8"> line and save as UTF-8.
K.4 I changed the code but the browser still shows the old page
Symptoms: Edits are not visible. Likely causes: The file was not saved, or the browser was not refreshed. How to investigate:
Look for the dot on the file tab in VS Code (means "unsaved"). Ask: "Did you save? Did you refresh?" Corrective steps: Ctrl +
S , then refresh with F5 (or Ctrl + F5 for a hard refresh). How to confirm resolved: The new text appears. Prevention: Build
the habit: Save, then refresh.
K.5 "Where is my folder?" / VS Code is showing the wrong place
Symptoms: Files are not where the learner expects; the Explorer looks empty. Likely cause: The wrong folder was opened, or the
file was saved in a different location. How to investigate: Read the folder name at the top of the Explorer. Corrective steps: File
→ Open Folder… and select exactly webdesign-practice . How to confirm resolved: The Explorer shows index.html , css and
images . Prevention: Always open the folder first, then create files inside it.
K.6 Confusing the internet with the web
Symptoms: The learner uses the two words as if identical. Likely cause: Everyday speech blurs the terms. How to investigate:
Ask: "Can I send an email without visiting a page?" (Yes.) Corrective steps: Reuse the road/building analogy. How to confirm
resolved: The learner explains the difference. Prevention: Use the analogy consistently all course.
Distinguish likely vs confirmed. In every case, the likely cause becomes a confirmed cause only after checking (seeing the exact
file name, the missing charset line, the unsaved dot). Teach learners to confirm before fixing.

time; focus first on the three building languages and the URL journey.
Level 2 (standard): Complete the exercises and assignment as written.
Level 3 (challenge): Ask the learner to research what a domain name is and explain the difference between http and
https ; or to build a second page about.html that links to index.html using a relative path, and explain what the link does.
Timing guidance (105 minutes). Opening 6 · Prerequisite 7 · Lecture 40 · Demonstration 15 · Guided practical 18 · Independent
exercise 15 · Case study 5 (compress if short on time) · Knowledge check 5 · Reflection/close 4. If the room is slow, protect the
guided practical and the case study may be reduced to a 3-minute mention — doing the setup is the priority. If the room is
fast, spend the spare time on Level 3 research tasks.
