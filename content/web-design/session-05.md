# CSS Layout

## A. Session Identification
<!-- kind:identification -->
**Week / module:** Week 2 — Module 2: CSS Foundations

**Recommended duration:** 105 minutes

**Difficulty:** Beginner (comfortable with HTML and basic CSS)

**Prerequisite knowledge:** Sessions 1–4. The learner must be able to write an HTML page with headings, paragraphs, links, images and sections, and link an external CSS file with <link rel="stylesheet" href="css/style.css"> . If a learner cannot link a CSS file and change a text colour, run the 15 minute refresher in Appendix 5A before this session.

**Connection to previous work:** In Session 4 learners learned to style colour, fonts and spacing. The styles worked, but the page still stacked everything in one dull column, top to bottom. This session teaches how to control where things sit on the page — the difference between a plain document and a real website layout.

**Preparation before class:** Academy PCs on and logged in; VS Code and Chrome installed; a practice folder per learner named adaeze-fashion ; a copy of each learner's Week 1 profile page and Session 4 styled page; the projector set to show the instructor's Chrome and VS Code; print the "Box Model Diagram" handout (one per learner) and the "Flexbox Quick Reference" card (one per learner).

## B. Learning Outcomes
<!-- kind:outcomes -->
By the end of this session, the learner will be able to:
1. Explain in their own words how elements sit on a page in normal flow, and name the difference between a block element
and an inline element.
2. Apply the four display values — block , inline , inline-block and none — to make an element behave in a chosen way,
and state the visible effect of each.
3. Use width , height and max-width to size an element, and explain why max-width is safer than a fixed width .
4. Explain and apply box-sizing: border-box so that padding and border are included inside the width, and describe what
happens to the box when it is missing.
5. Explain why float is a legacy technique and recognise it in old code, naming at least one situation where it still appears
(wrapping text around an image).
6. Build a Flexbox row using display: flex , and control it with flex-direction , justify-content , align-items , gap and
flex-wrap .
7. Build a basic two-column CSS Grid using display: grid , grid-template-columns and gap .
8. Choose between Flexbox and Grid for a given layout and give a reason for the choice.
9. Centre an element horizontally and vertically using Flexbox.
10. Reproduce two common real layouts — a navigation bar using Flexbox and a card grid — and describe the expected on-
screen result.

## D. OPENING ACTIVITY (6 minutes)
<!-- kind:opening -->
Instructor setup: On the projector, open two versions of the same business page for Adaeze's Fashion Design. The first version
has all the content (logo, links, a welcome message, three product boxes, a footer) but no layout — everything is left-aligned
and stacked in one long, boring column, all in the default font. The second version is the same page with a simple layout: the
logo and menu sit side by side along the top, the three products sit in a neat row, and the footer is centred.
What the instructor says:
"Look at these two pages. Same words. Same colours. Same pictures. But the first one looks like a school assignment, and
the second one looks like a shop you would actually buy from. What is the difference?
The difference is layout — the arrangement of things on the page: what sits beside what, what is on top, how wide each
part is. Last week you learned how to style one element. Today you learn how to arrange many elements. That is the skill
that turns a document into a real website."
Expected learner response: Learners may say "one has columns", "the other is more organised", or "the second looks nicer".
Accept all answers and confirm: the content never changed — only the arrangement.
Then demonstrate the hook: In the projector's Chrome, right-click the second (nice) page, choose Inspect, and click the
Elements tab. Hover over the three product boxes — Chrome outlines each one with coloured bars showing content (blue),
padding (green), border (yellow) and margin (orange). Say:
"Every single thing on a webpage is actually a rectangle — a box — even when it does not look like one. Today you will
learn to see the boxes and to move them wherever you want."
Why this opener works: It creates a clear gap between "I can style one element" and "I can arrange a whole page", and it
immediately gives learners a tool (the box diagram) they will use for the rest of the course.

## E. PREREQUISITE REVIEW (7 minutes)
<!-- kind:prereq_review -->
Run this quickly as an oral round-robin. Put the five questions on the projector.
Question 1: "What are the three parts of a CSS rule?"
Expected answer: a selector, a property and a value (e.g. p { color: red; } ).
Common gap: learners name the property and value but forget the selector. Remind them: the selector is what you are
styling.
Question 2: "What does the display property do?" (Even though we cover it in depth today, check what they already think.)
Expected answer: it controls how an element behaves in the page flow. Accept "I am not sure yet" — this is the first thing we
teach today.
Question 3: "How do you link an external CSS file to an HTML page, and where does the line go?"
Expected answer: <link rel="stylesheet" href="css/style.css"> inside the <head> .
Common gap: writing it in the <body> or misspelling stylesheet . Re-state the exact spelling.
Question 4: "What is the difference between .price and #price ?"
Expected answer: .price is a class selector and can appear on many elements; #price is an id selector and must be unique
on the page.
Common gap: swapping them. Restate: dot = class, hash = id.
Question 5: "If a CSS change does not appear in the browser, what is the first thing to check?"
Expected answer: save the file ( Ctrl + S ) and refresh the page ( F5 ). Then check the file path is correct.
Common gap: learners forget to save before refreshing.
Bridge to today (say this):
"Last session you dressed one person. Today you arrange the whole room — you decide who stands where. In CSS, the two
modern tools for arranging things are Flexbox and Grid. By the end of today you will be able to build the top of any
business website: a logo on the left, a menu on the right, and a row of product cards below."
If more than a third of the class cannot answer Question 3, spend 10 extra minutes on the Appendix 5A CSS refresher before
continuing.

## F. Full Lecture Notes
<!-- kind:lecture -->
F.1 Normal flow — how elements sit by default
The idea. Before you arrange anything, you must understand what happens without your help. This default behaviour is called
normal flow (or "the normal document flow").
Plain-English definition. Normal flow is the way the browser lays out elements when you have not told it to do anything special.
The browser reads your HTML from top to bottom and places each element on the page in the order it appears.
Why it exists. HTML was designed for documents — letters, reports, articles. A document naturally flows top to bottom, line by
line, just like text in a book. That is why the first version of any HTML page is a single column: the browser is being a good
reading machine.
What it does:
Block elements stack vertically — one underneath the other.
Inline elements sit side by side on the same line, like words in a sentence.
Everything starts at the top-left and moves down and right.
Analogy. Think of normal flow as writing on a fresh sheet of paper. You start at the top-left. You write across the line; when
the line is full, you go down to the next line. You never jump around unless you deliberately do something. Layout in CSS is the
art of deliberately jumping around.
Worked example — see normal flow for yourself:
```text
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
```
```text
  <title>Normal Flow</title>
  <link rel="stylesheet" href="css/style.css">
</head>
<body>
  <h1>Adaeze's Fashion Design</h1>
  <p>Custom clothing made in Port Harcourt.</p>
  <a href="shop.html">Shop</a>
  <a href="about.html">About</a>
  <a href="contact.html">Contact</a>
</body>
</html>
```
Expected browser result: The <h1> appears on its own line. Below it, the paragraph appears on its own line. Below that, the
three links appear on one line, side by side, separated only by the browser's default word spacing: Shop About Contact . The
headings and paragraph each start on a new line because they are block elements; the links stay together because they are inline
elements.
Misconception. Learners often think the browser "knows" that a heading should be on its own line because of its meaning. It
does not — it is on its own line because headings are block elements. Change the display and you change the behaviour.
Limitation. Normal flow alone cannot make two things sit side by side as columns, cannot centre a box in the middle of the
screen, and cannot make a menu spread out along a bar. For that we need to change how elements display, and then use
Flexbox or Grid.
F.2 The display property — block, inline, inline-block, none
The idea. The display property tells the browser what kind of box an element is. Changing it is like telling a person "you may
now behave as a column" or "you may now behave as a word".
Plain-English definition. display controls how an element participates in the layout: does it take a whole line, sit inline with
text, or disappear entirely?
Why it exists. Different content needs different behaviour. A heading should own its line; a link should sit within a sentence; a
whole section you can hide with JavaScript later needs a way to be switched off. display gives you that control.

Expected browser result: Box A and Box B each take a full-width pink strip on their own line. The two blue "Home" and "Shop"

nothing is shown. Note: an inline element ignores width and height , so the blue spans are only as wide as their words. This
surprises beginners every time — it is the difference between inline and inline-block .
Important note on padding for inline elements. An inline element accepts left/right padding (as shown) but top/bottom
padding does not push other lines apart the way learners expect. If a learner wants a clickable "button" out of a link, they should
usually set display: inline-block so width, height and padding all behave predictably.
Misconception. "If I set display: none , the element is invisible but still pushes things." False — display: none removes it from
the layout entirely. (This is different from visibility: hidden , which hides it but keeps its space; we do not need that this week.)
Limitation. display: block gives you stacking; display: inline-block gives you small side-by-side pieces. Neither can easily
spread items apart, wrap them onto new rows, or align them vertically. That is the job of Flexbox and Grid (F.6 and F.7).
F.3 Sizing — width , height and max-width
The idea. You can set how wide and how tall a box is.
Plain-English definition. width is how wide the element is; height is how tall. max-width means "never get wider than this, but
you may be narrower".
Why it exists. By default, a block element is as wide as its parent and as tall as its content. Sometimes you want a fixed card size;
sometimes you want a box to grow but stop before it becomes too wide to read.
Common units:
Unit Meaning Beginner example
```text
px
```
Fixed pixels
```text
width: 300px;
```
```text
%
```
Percentage of the parent's width
```text
width: 50%;
```
```text
rem
```
Times the root (page) font size
```text
width: 20rem;
```
vw / vh Percent of viewport width / height height: 100vh; (full screen height)
Worked example — fixed width versus max-width:
```text
.fixed {
  width: 600px;
  background-color: #ffe6a7;
```
```text
}
.fluid {
  width: 90%;
  max-width: 600px;
  background-color: #a7e6ff;
}
```
Expected browser result: Both boxes look similar on a wide desktop. But if you drag the browser window narrower to phone
width, the yellow .fixed box stays 600px wide and overflows off the right side of the screen (causing a horizontal scrollbar),
while the blue .fluid box shrinks to 90% of the window and never overflows. That is exactly why max-width is the safer
choice for a responsive website — a theme we expand fully in Session 6.
Rule of thumb for this course: prefer max-width with a percentage or fixed upper limit for content containers; use fixed
width / height only for small, predictable pieces such as icons or cards.
Misconception. "Width includes everything." By default it does not — it applies only to the content box. The next sub-topic
fixes that.
Limitation. Setting a height on a box that contains text is risky: on a narrow screen the text may become taller than the fixed
height and spill out. Prefer min-height (a floor, not a ceiling) when you must set a height at all.
F.4 The box model and box-sizing
The idea. Every element is a rectangle made of four layers. This is called the CSS box model.
Plain-English definition. The box model says each element has, from the inside out:
1. Content — the text or image itself.
2. Padding — space inside the box, between the content and the border.
3. Border — the edge line around the padding.
4. Margin — space outside the box, pushing other elements away.
Why it exists. Separating "space inside" (padding) from "space outside" (margin) lets you create breathing room around text
and control the gaps between boxes independently.
Analogy. Imagine each element is a framed picture on a wall. The picture itself is the content. The white card around the
picture is the padding. The wooden frame is the border. The gap you leave between this framed picture and the next one is the
margin. (This is the same "room" idea some learners met in earlier handouts — content is the furniture, padding is the floor
space to the walls, border is the walls, margin is the corridor between rooms.)
Worked example — the classic surprise:
```text
.box {
  width: 300px;
  padding: 20px;
  border: 5px solid #333;
  margin: 10px;
  background-color: #f3b6c8;
}
```
Expected browser result: The content area is 300px wide. But the total width you see is: 300 (content) + 20 (left padding) + 20
(right padding) + 5 (left border) + 5 (right border) = 350px, plus 10px of margin on each side that pushes neighbours away.
Beginners expect 300px total and are shocked when the box measures 350px. This is the single most confusing thing in CSS
layout — and box-sizing fixes it.
The fix — box-sizing: border-box :
```text
* {
  box-sizing: border-box;
}
```
```text
.box {
  width: 300px;         /* now 300px INCLUDING padding and border */
  padding: 20px;
  border: 5px solid #333;
```
```text
  background-color: #f3b6c8;
}
```
Expected browser result: The box now measures exactly 300px total. The padding and border are counted inside the 300px, so
the content area shrinks to 300 − 40 − 10 = 250px, but the visible box is a clean 300px. Widths become predictable, which is why
nearly every professional stylesheet starts with * { box-sizing: border-box; } .
Say this to the class:
"The * selector means 'every element on the page'. So this one little rule makes every box include its padding and border
in its width. From today, we put it at the top of every stylesheet. It will save you hours of confusion."
How to see it in the browser: Press F12 , click Elements, select a box, and look at the coloured diagram at the bottom of the
right pane — blue content, green padding, yellow border, orange margin. The instructor will do this live in Section G.
Misconception. "Padding and margin are the same." No: padding is inside the border (it adds to the box and takes the
element's own background colour); margin is outside (it is always transparent and pushes other elements away).
Limitation. box-sizing changes how width is calculated; it does not stop an element from overflowing if its content (such as a
large un-resized image) is bigger than the box. Images need their own care (Session 6).
F.5 Floats — and why they are now legacy
The idea. Long before Flexbox and Grid existed, designers used the float property to place boxes side by side.
Plain-English definition. float: left or float: right pulls an element out of the normal vertical flow and pushes it to one side,
letting the following content wrap around it.
Why it existed. In the early 2000s there was no Flexbox or Grid. To build a two-column layout, designers floated the columns
left and right and then "cleared" the float afterwards. It worked, but it was fragile.
What it does today. Its original and still-useful job is wrapping text around an image — exactly how a magazine wraps an
article around a photo:
```text
.article-img {
  float: left;
  width: 200px;
  margin: 0 15px 10px 0;
}
```
```text
<img class="article-img" src="images/adaeze.jpg" alt="Adaeze at her sewing machine">
<p>Adaeze started her fashion business in 2019 with one sewing machine...</p>
<p>The paragraph text wraps neatly around the right side of the photo.</p>
```
Expected browser result: The photo sits on the left; both paragraphs flow down beside it on the right, wrapping under the
picture once the text passes the bottom of the image. This is the one place float is still the natural tool.
Why floats are legacy for layout:
A floated element is removed from normal flow, so its parent can "collapse" and lose its height — a bug that required
clearfix hacks.
Vertical centring with floats was painful.
Responsive behaviour (wrapping, gap, changing direction on mobile) had to be hand-built.
Flexbox and Grid do all of this cleanly and predictably.
What the learner should do about floats. Recognise them in older code and know what they mean. Do not use them to build
page layout in new code — use Flexbox or Grid. If you see a wrapper with float: left and a mysterious clear: both block, you
are looking at an old-fashioned layout.
Misconception. "Float is wrong and I should never use it." Float is not wrong; it is simply no longer the best tool for layout. It is
still correct for text-wrapping an image, and understanding it helps you read existing websites.
Limitation. Even with clearfix tricks, float layouts have no built-in gap , no easy vertical alignment and no clean wrapping —
exactly the gaps Flexbox and Grid were created to fill.
F.6 Flexbox — arranging items in one direction
The idea. Flexbox (short for "Flexible Box Layout") arranges a group of items along a single line — either a row or a column —
and gives you powerful control over spacing and alignment.
Plain-English definition. When you set display: flex on a parent element, that parent becomes a flex container, and its direct
children become flex items. The browser then arranges those items in a flexible line you can control.
Why it exists. Before Flexbox, arranging items in a row and spreading them out, centring them, or making them shrink on small
screens required hacks. Flexbox was designed (and is now supported in every modern browser) to make these common jobs
simple and reliable.
The two-axis idea (diagrams in words). Flexbox works on two axes:
The main axis is the direction the items flow. By default it runs left → right (a row).
The cross axis runs perpendicular to the main axis — for a row, the cross axis runs top → bottom.
Picture a bookshelf. The main axis is the shelf you place books along (left to right). The cross axis is how each book stands tall
(top to bottom). justify-content moves books along the shelf; align-items moves them up and down on the shelf.
If you change flex-direction: column , the whole thing rotates: the main axis now runs top → bottom, and the cross axis runs
left → right. The two properties keep their meaning relative to the axes, which is why they can feel confusing at first — always
ask "which way is my main axis pointing?"
Turning on Flexbox:
```text
.nav {
  display: flex;              /* parent becomes a flex container */
}
```

Limitation. Flexbox is excellent for one line of items (a row or a column). When you want to control items in two directions at
once — rows and columns forming a real grid — Grid is the better tool (next topic).
F.7 CSS Grid basics — laying out rows and columns
The idea. CSS Grid arranges items into a true two-dimensional grid of rows and columns.
Plain-English definition. When you set display: grid on a parent, that parent becomes a grid container, and its children
become grid items that you place into columns and rows you define.
Why it exists. Some layouts are naturally a grid: a photo gallery, a product listing, a page with a sidebar and a main area.
Flexbox can approximate these, but Grid describes them directly and precisely.
The two core properties this week:
Property What it does
```text
display: grid
```
Turns the element into a grid container.
```text
grid-template-columns
```
Defines the columns of the grid, e.g. 1fr 1fr 1fr for three equal columns.
```text
gap
```
Adds even space between rows and columns (same idea as Flexbox).
The fr unit. fr means "fraction of the available space". Three columns of 1fr 1fr 1fr each take one-third of the width. Two
columns of 2fr 1fr make the first column twice as wide as the second.
Worked example — a three-column card grid:
```text
.gallery {
  display: grid;
  grid-template-columns: repeat(3, 1fr);  /* three equal columns */
  gap: 20px;
}
.gallery img {
  width: 100%;
  display: block;
}
```
```text
<section class="gallery">
  <img src="images/dress1.jpg" alt="Ankara dress">
  <img src="images/dress2.jpg" alt="Lace gown">
  <img src="images/dress3.jpg" alt="Aso ebi outfit">
  <img src="images/dress4.jpg" alt="Office wear">
  <img src="images/dress5.jpg" alt="Traditional attire">
  <img src="images/dress6.jpg" alt="Bridal gown">
</section>
```
Expected browser result: Six images arranged in two rows of three, with 20px gaps between every image. Each image is one-
third of the container width. If you reduced the columns to repeat(2, 1fr) , you would get three rows of two.
repeat(3, 1fr) explained: it is shorthand for writing 1fr 1fr 1fr . The first number is how many columns; the second is the size
each should be.
Misconception. "Grid and Flexbox are competitors — I must pick one forever." Not at all. They are partners: use Grid for the
overall page grid, and Flexbox inside individual cells for aligning the small pieces. Real websites mix both constantly.
Limitation. Grid is slightly newer than Flexbox. It is supported in every modern browser (Chrome, Firefox, Edge, Safari), but very
old browsers (Internet Explorer 10 and earlier) do not support it. For our course this is a non-issue — we target modern browsers.
F.8 When to use Flexbox, when to use Grid
This is a decision learners ask about constantly. Use this rule of thumb:
Situation Choose Why
A row of navigation links Flexbox Only one direction (a row); need space-between .
Centring one thing in the middle of a box Flexbox Two lines of CSS with justify-content and align-items .
A row of cards that should wrap Flexbox flex-wrap: wrap plus flex: 1 1 220px handles wrapping.
A photo gallery with fixed columns and rows Grid Needs control in two directions.
A page with a sidebar and a main content area Grid Two columns of different sizes side by side.
One-line memory aid: Flexbox is for one direction; Grid is for two. If you can describe the layout as "a line of things", reach for
Flexbox. If you must talk about both rows and columns at once, reach for Grid.
F.9 Centring things — the classic problem, solved
The idea. Centring was once notoriously hard in CSS. Flexbox makes it easy.
Horizontal centring only:
```text
.title {
  text-align: center;   /* centres inline content such as text */
}
```
This centres the text inside a box. It does not centre the box itself. To centre a block box horizontally, you can also use margin: 0
auto; (auto left and right margins split the leftover space equally) — but this requires the box to have a set width.
Perfect centring (both directions) — the modern one-liner trio:
```text
.hero {
  display: flex;
  justify-content: center;  /* centre along the main axis (horizontal) */
  align-items: center;      /* centre along the cross axis (vertical) */
  min-height: 400px;        /* give the box some height to centre within */
}
```
```text
<section class="hero">
  <div>
    <h1>Custom Fashion for Every Occasion</h1>
    <p>Beautiful, affordable clothing made just for you.</p>
  </div>
</section>
```
Expected browser result: The heading and paragraph sit dead centre of a 400px-tall hero area, both horizontally and vertically.
Before Flexbox, this took multiple hacks; now it is three lines.
Important condition. Vertical centring only works when the container has height to spare. If the container is exactly the height
of its content, there is nothing to centre within. That is why min-height is included.

F.11 Summary of the session
Normal flow stacks block elements vertically and inline elements side by side.
display decides an element's box type: block , inline , inline-block or none .
width / height size a box; max-width is safer because it never overflows.
The box model = content + padding + border + margin. Use * { box-sizing: border-box; } so width includes padding and
border.
Float is legacy for layout; still fine for wrapping text around an image.
Flexbox arranges one row or one column: display: flex plus flex-direction , justify-content , align-items , gap , flex-
wrap .
Grid arranges rows and columns at once: display: grid , grid-template-columns , gap .
Rule of thumb: Flexbox for one direction, Grid for two.
Centring horizontally and vertically is three lines of Flexbox.

## J. Real-World Case Study
<!-- kind:case_study -->
Situation. Adaeze sells her clothes mostly through WhatsApp. A friend builds her a simple website, but the first draft has every
product listed in one long vertical column — a photo, then a name, then a price, then the next photo, all the way down the
page. On a desktop screen, customers must scroll and scroll to see ten products. Adaeze notices that people open the page and
leave quickly.
Relevant facts.
The website has correct content and correct colours; only the arrangement is poor.
Adaeze's customers often compare several outfits before deciding.
Adaeze is not a programmer, but she has just learned Flexbox and Grid.
Decision point. How can layout alone change how the shop feels to a customer?
Possible approaches.
1. Leave the long column and hope customers scroll.
2. Use a Grid to show products in neat rows of three, so many outfits are visible at once.
3. Pay a company to rebuild the site from scratch.
Recommended solution (for this stage). Approach 2. Converting the single column into a grid-template-columns: repeat(3,
1fr) gallery lets a customer see three outfits at a glance and compare them side by side. The content does not change at all —
only the layout — yet the page suddenly feels like a real shop.
Example solution:
```text
.shop {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 20px;
  max-width: 1000px;
  margin: 0 auto;
  padding: 0 16px;
}
```
Trade-offs.
Approach 1 costs nothing but loses customers — the very problem.
Approach 2 takes about 20 minutes and needs no new content.
Approach 3 is expensive and unnecessary; the fix is a handful of CSS lines.
Professional connection. Junior web developers earn money fixing exactly this kind of problem for small businesses: the
content is fine, the layout is the issue. Knowing Flexbox and Grid is one of the most employable front-end skills because almost
every real page needs some arrangement of rows and columns.

## K. Common Mistakes and Troubleshooting
<!-- kind:troubleshooting -->
Use this table as the session's live troubleshooting guide. When a learner hits an issue, do not give the answer immediately —
ask them to check the relevant row.
K.1 Flexbox "not working" — items still stacked
Symptoms: You wrote display: flex; but everything still sits in one vertical column. Likely causes: (a) you put display: flex
on the child instead of the parent; (b) the rule is not saved; (c) a selector does not match any element; (d) a typo such as
display: flexbox; . How to investigate: In DevTools → Elements, click the parent element and check the Styles pane for your
rule. If it is greyed out or missing, the selector or spelling is wrong. Safe corrective steps: Put display: flex on the container
that holds the items; fix the value to exactly flex ; save and refresh. How to confirm resolved: The children line up in a row.
How to prevent recurrence: Always ask "am I styling the container or the item?"
K.2 Widths are bigger than expected
Symptoms: You set width: 300px but the box measures 350px or more. Likely cause: box-sizing is not set, so padding and
border are added on top of the width. How to investigate: Check the box-model diagram in DevTools — the numbers add up.
Safe corrective steps: Add * { box-sizing: border-box; } at the top of the stylesheet. How to confirm resolved: The total
width now matches the value you set. How to prevent recurrence: Put the box-sizing rule at the top of every stylesheet you
write.
K.3 Cards or columns overflow the page (horizontal scrollbar)
Symptoms: A horizontal scrollbar appears and content runs off the right side. Likely causes: A fixed width bigger than the
screen, an image that is too wide, or flex-wrap missing so items refuse to drop to the next line. How to investigate: Drag the
window narrow and watch which element runs off the edge. Safe corrective steps: Replace fixed widths with max-width ; add
flex-wrap: wrap; ; add img { max-width: 100%; } . How to confirm resolved: The scrollbar disappears and content stays inside
the window. How to prevent recurrence: Prefer max-width and percentages; avoid fixed widths on layout containers.
K.4 gap adds no space
Symptoms: You set gap but the items touch each other. Likely cause: You put gap on an item or on a non-flex/grid element.
How to investigate: Check that the element with gap also has display: flex or display: grid . Safe corrective steps: Move
gap to the flex/grid container. How to confirm resolved: Even space appears between items. How to prevent recurrence:
Remember: spacing between items belongs on the container.
K.5 Grid created only one column
Symptoms: You expected three columns but got one, or items stack. Likely cause: grid-template-columns is present but display:
grid is missing, or a typo in the value. How to investigate: In DevTools, look for the grid badge next to the element; if there is
none, it is not a grid. Safe corrective steps: Add display: grid; above grid-template-columns . How to confirm resolved: The
grid badge appears and columns form.
K.6 The whole page has a white border around it
Symptoms: Unwanted blank space around the entire page. Likely cause: The browser's default body margin (usually 8px). Safe
corrective steps: Add body { margin: 0; } . How to confirm resolved: The layout touches the edges of the window. How to
prevent recurrence: Include body { margin: 0; } in your base styles.
Distinguish likely vs confirmed: In every case above, the likely cause becomes confirmed only after you check it in DevTools —
for example, seeing that your rule is missing, or that the box-model numbers add up wrong.

INSTRUCTOR ANSWER KEY (Q1–Q7)
A1. Content, padding, border, margin.
A2. (c) display: inline-block; — it sits in the text flow like inline but accepts width and height like block.
A3. It makes the element's width include its padding and border, instead of adding them on top. We put it at the top of every
stylesheet so all boxes are sized predictably and widths mean what they say.
A4. For a row (the default), the main axis runs left to right and the cross axis runs top to bottom. justify-content spaces
items along the main axis.
A5.
```text

align-items: center;
```

A6.

b) Grid — needs rows and columns (two directions).
c) Flexbox — centring on two axes with justify-content / align-items .

## N. Reflection and Recap
<!-- kind:reflection -->
Plain-English summary. Today you learned to control where elements sit on a page. You met normal flow (the browser's default
stacking), the display property (block, inline, inline-block, none), and sizing with width , height and max-width . You learned
the box model — content, padding, border, margin — and the crucial fix box-sizing: border-box; . You saw why float is now
legacy for layout, then learned Flexbox (one direction, with justify-content , align-items , gap , flex-wrap ) and the basics of
Grid (rows and columns at once). Finally you built two real layouts: a navigation bar and a product grid.
Five important takeaways:
1. Block elements stack; inline elements sit side by side; inline-block does both.
2. Every element is a box: content + padding + border + margin.
3. * { box-sizing: border-box; } should start every stylesheet.
4. Flexbox for one direction, Grid for two.
5. Centring both ways is just display: flex; justify-content: center; align-items: center; .
Questions to help you recognise what you can now do:
Can I make two boxes sit side by side without a table or a float?
Can I explain why my box is wider than the width I set?
Can I build a top bar with the logo left and menu right, from memory?
Can I choose correctly between Flexbox and Grid and say why?
Connection to the next session: Right now these layouts look great on a big desktop screen. But what happens on a small
phone? Next session we make the layout responsive — adapting automatically to phone, tablet and desktop using relative units
and media queries.

## O. Instructor Evaluation Notes
<!-- kind:instructor_notes -->
Observable signs of genuine competence:
The learner puts display: flex / grid on the parent container without being reminded.
The learner can explain, without notes, why a box measured 350px when set to 300px.
The learner chooses Flexbox or Grid with a reason ("this is one row" vs "this needs rows and columns").
The learner uses gap on the container rather than margins on splayed items.
The learner uses the DevTools box diagram to diagnose a sizing problem.
Common misconceptions to watch for and correct:
"Flexbox goes on the children." → It goes on the parent; children become items automatically.
"Padding and margin are the same." → Padding is inside, margin is outside.
"The value is display: flexbox ." → The correct value is display: flex .
"Grid and Flexbox are rivals; pick one." → They are partners; most sites use both.
"Float is evil." → Float is just no longer the right tool for layout; it still wraps text around images.
Suggested remedial exercises for learners who struggle:
1. Box-model tracing: give three elements with the same width but different padding and border; ask learners to predict the
total width, then check in DevTools.
2. Flex/Grid sorting: show six one-line layouts and ask learners to sort them into "Flexbox" and "Grid".
3. Fix the stacked menu: hand out a header where display: flex is on the <a> instead of the <nav> ; ask learners to find and
fix it.
Differentiation:
Level 1 (supported): provide the completed index.html and a style.css with the top-bar CSS already written but the card
CSS missing; guide them to finish it.
Level 2 (standard): the practical and independent exercises as written.
Level 3 (challenge): add a second row using align-self on one card to test vertical alignment, then rebuild the same
lookbook with Grid grid-template-columns: repeat(auto-fit, minmax(220px, 1fr)) and observe how it reflows.
Timing guidance: If the room is slow, shorten the case study (Section J) to a 3-minute mention and protect the guided practical
— the hands-on layout work is the priority. If the room is fast, extend the DevTools grid-inspector time in Section G.4.
