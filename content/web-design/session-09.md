# Styling the Website

## A. Session Identification
<!-- kind:identification -->
**Week / module:** Week 3 — Module: Building a Website

**Recommended duration:** 105 minutes

**Difficulty:** Beginner (builds directly on Sessions 4–8)

**Prerequisite knowledge:** Sessions 1–8. Learners can write semantic HTML for a multi-page site, link pages with relative paths, and know CSS selectors, the box model, flexbox, the link tag and media queries.

**Connection to previous work:** In Session 8 the learner built the skeleton of the Adaeze Fashion website: four HTML pages with a header, navigation, main content and footer. It works, but it is plain black-on-white text — an unstyled document. This session turns that skeleton into a designed, branded website using one shared external stylesheet.

**Preparation before class:** Academy PCs on and logged in; VS Code and Chrome installed; each learner's Session 8 project folder open and complete; a projector that shares the instructor's screen; a printed "CSS Styling Checklist" per learner; the instructor's own finished Adaeze Fashion site ready to show as a target.

## B. Learning Outcomes
<!-- kind:outcomes -->
By the end of this session, the learner will be able to:
1. Create one shared external stylesheet and link it correctly from every page using <link rel="stylesheet"
href="css/style.css"> in the <head> .
2. Define and apply a colour palette using CSS custom properties (variables) so the whole site changes from one place.
3. Define and apply a typography scale — a set of heading and body sizes that are reused consistently.
4. Style the header and navigation with flexbox, including a hover state on the links.
5. Style the hero section, product cards and buttons using flexbox and CSS Grid.
6. Apply a consistent spacing system (repeated padding and margin values) so nothing looks cramped or random.
7. Add borders, shadows and rounded corners to give elements depth.
8. Style a contact form — labels, inputs, textarea and a clear focus state.
9. Organise a stylesheet into commented sections in a logical order, and reuse classes instead of repeating rules.
10. Style all pages of a multi-page website consistently and verify the result in the browser.

## D. OPENING ACTIVITY (6 minutes)
<!-- kind:opening -->
Instructor setup: On the projector, first open the learner's unstyled Session 8 page (plain text, default serif font, blue underlined
links, no colour). Then, in a second tab, open the instructor's fully styled Adaeze Fashion site.
What the instructor says:
"Look carefully. Same words. Same pictures. Same four pages. But which one would make you trust Adaeze with your
money?
The plain one looks like a document someone typed in a hurry. The styled one looks like a shop. The only difference
between them is one file — a stylesheet. By the end of today, your plain site will look like that one. And the good news is
you already know all the pieces; today we simply bring them together for a real business."
Flip between the two tabs three or four times so the contrast lands. Then tell the class the plan for the session: colours, fonts,
spacing, header, hero, products, buttons, footer, form — all in one organised file.
Expected learner response: Learners will nod, laugh at how plain the first one looks, and some will ask "Is that my site?" Accept
that. Point out it is their site from last week and it is completely normal to look plain at this stage.
Why this opener works: It sells the value of CSS in ten seconds (trust = money for a business) and reduces the learner's fear by
reminding them they already learned each individual piece. It frames today as assembly, not new magic.

## E. PREREQUISITE REVIEW (7 minutes)
<!-- kind:prereq_review -->
Run this as a fast oral round-robin. Put the questions on the projector.
Question 1: "What are the three parts of every CSS rule?"
Expected answer: a selector, a property and a value. Example .price { color: #d4a574; } .
Common gap: learners forget the colon between property and value, or the semicolon at the end. Remind them: property:
value; — colon inside, semicolon at the end.
Question 2: "What are the four layers of the box model, from the content outward?"
Expected answer: content, padding, border, margin.
Common gap: mixing up padding (space inside the border) and margin (space outside the border). Say: "Padding is the
bubble wrap inside the box; margin is the gap between boxes on the shelf."
Question 3: "What does display: flex let you do, and give me one place we used it."
Expected answer: it makes an element a flex container and lays its direct children out in a row (or column), making it easy to
space and align them. We used it for the header and navigation in earlier sessions.
Common gap: learners think flex goes on the children. Clarify: it goes on the parent container.
Question 4: "What is a media query and what keyword do we use to break down from desktop to mobile?"
Expected answer: a block of CSS that only applies when a condition is true, usually screen width. @media (max-width: 767px) {
... } .
Common gap: forgetting the parentheses around the condition. It is @media (max-width: 767px) , not @media max-width: 767px .
Question 5: "How do we link a stylesheet, and where does the line go?"
Expected answer: <link rel="stylesheet" href="css/style.css"> inside the <head> .
Common gap: confusing <link> (for CSS) with <a> (for page links). Emphasise: link for stylesheets, a for anchors.
Bridge to today (say this):
"Everything you just answered is a tool. Today we put all the tools on the workbench at once and build one finished,
branded website. The trick professionals use is organisation — one file, one palette, one spacing system, reused
everywhere. That is what makes a site look 'designed' instead of 'decorated'."
If more than a third of the class cannot answer Questions 2 and 3, spend 8 extra minutes re-demonstrating the box model and
flexbox on a single sample page before continuing into Section F.

## F. Full Lecture Notes
<!-- kind:lecture -->
F.1 What "styling a whole website" really means
The idea. Up to now you have styled single elements in isolation — one heading red, one image rounded. A website is different:
dozens of elements across several pages that must look like they belong together.
Plain-English definition. Styling a website means choosing a small set of rules — colours, fonts, sizes and spacing — and
applying them the same way everywhere, so every page feels like one brand.
Why it exists. A visitor does not judge one button; they judge the whole experience. If the Home page uses one blue and the
Contact page uses a different blue, the visitor senses carelessness and stops trusting the business. Consistency is what separates
an amateur site from a professional one.
Analogy. Think of a tailor's shop. Adaeze does not cut a fresh pattern for every customer in a random way; she has house
measurements, house stitching, house colours. The result is that everything from her shop is recognisably hers. A stylesheet is
your house style: cut once, applied everywhere.
What it does. It takes the HTML skeleton and adds colour, type, space and depth. The structure (HTML) never changes; only the
presentation changes.
Important misconception. "More decoration = better design." Wrong. Beginner sites often have fourteen colours and five
fonts. Professional sites usually have three to five colours and two fonts. Restraint looks expensive; clutter looks cheap.
How a learner recognises good styling. Spacing is even, colours repeat consistently, text is readable, buttons look clickable,
and every page matches. If you can move from any page to any other and not feel a "jump", the styling is working.
Limitation. CSS cannot fix bad content or bad structure. If the HTML has no headings and no semantic sections, styling can
only hide the problem, not solve it. Session 8's clean HTML is what makes today possible.
F.2 One shared external stylesheet
The idea. Every page links to the same CSS file. There is only one style.css for the whole site.
Why not one file per page? If each page had its own stylesheet, changing the brand colour would mean editing four files and
hoping you did not forget one. With a shared stylesheet you edit the colour once and all four pages update instantly.
Analogy. A shared stylesheet is like the school uniform rule. Every class wears the same uniform; if the school changes the
badge, every class changes together. Per-page CSS is like every class inventing its own uniform — chaos.
The linking line (goes in the <head> of every page):
```text
<link rel="stylesheet" href="css/style.css">
```
Line by line:
<link> — the tag that connects the page to an outside resource.
rel="stylesheet" — relationship is "stylesheet"; without this the browser does not know what kind of file it is.
href="css/style.css" — the path. It means "from the HTML file, go into the css folder and find style.css ". This is a
relative path (Section K explains why that matters).
Where does style.css live? Inside a css/ folder, sibling to the HTML files:
```text
adaeze-fashion/
├── index.html
├── shop.html
├── about.html
├── contact.html
├── css/
│   └── style.css     ← the one shared file
└── images/
    └── ...
```
Worked example — proving the link works:
HTML ( index.html head):
```text
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Adaeze Fashion | Home</title>
  <link rel="stylesheet" href="css/style.css">
</head>
```
CSS ( css/style.css ):
```text
body {
  background-color: lightyellow;
}
```
Expected browser result: Open index.html and the whole page background turns pale yellow. If it does not, the link or the
path is wrong — check Section K.1.
Consequence of getting it wrong: If the path is wrong (e.g. href="style.css" when the file is in a css/ folder), the page loads
but completely unstyled, and the Console shows a red net::ERR_FILE_NOT_FOUND for the stylesheet.
F.3 CSS custom properties — the colour palette in one place
The idea. Instead of typing #2c1810 fifteen times, you name it once as --color-dark , then use that name everywhere.
Plain-English definition. A CSS custom property (also called a CSS variable) is a named value you store on :root and reuse
with var() .
Why it exists. When a client says "change the brown to navy", you change one line instead of hunting through hundreds of
lines. This is how real design systems stay consistent.
Analogy. It is like naming a jar "SUGAR" in a kitchen rather than writing the word sugar on every recipe. Rename the contents
once; every recipe still says "add sugar".
The Adaeze Fashion palette:
```text
:root {
  /* -- Brand colours -- */
  --color-dark:   #2c1810;   /* deep cocoa brown — headers, footer, headings */
  --color-gold:   #d4a574;   /* warm tan/gold — accents, buttons, logo */
  --color-gold-dark: #b8845a;/* darker gold — hover state */
  --color-cream:  #f5f0eb;   /* soft cream — section backgrounds */
  --color-white:  #ffffff;   /* pure white — cards */
  --color-text:   #333333;   /* body text */
  --color-muted:  #666666;   /* secondary text */
  --color-border: #dddddd;   /* input borders, card outlines */
}
```
:root means "the very top of the document" — a safe place to store global values.
Each line is --name: value; . Note the double hyphen at the start — that is required.
Names are your choice, but meaningful names like --color-gold beat meaningless ones like --c1 .
Using a variable with var() :
```text
body {
  color: var(--color-text);
  background-color: var(--color-white);
}
```
Expected browser result: the text is charcoal #333 on white. Change --color-text to #000 up top and refresh — the text
darkens everywhere at once.
Worked example — proving the power:
```text
:root {
  --color-gold: #d4a574;
}
.button {
  background-color: var(--color-gold);
}
.logo {
  color: var(--color-gold);
}
```
Now edit :root to --color-gold: #1e6091; and refresh. The button and the logo turn blue together. That is the whole point.
Misconception. Learners sometimes write var(--color-gold); as if it were a full declaration. var() is only the value; it must still
sit after a property: color: var(--color-gold); .
Limitation. Variables are not magic storage for arbitrary logic; they simply hold values. Also, very old browsers (Internet Explorer)
do not support them — we do not support IE in this course, so we are safe.
F.4 The typography scale — two fonts, a set of sizes
The idea. Choose two fonts (one for headings, one for body) and a short list of sizes, then never invent a new size in the
middle of the page.
Why it exists. Random font sizes are the fastest way to make a site look messy. A scale makes headings feel like a family.
Analogy. A choir. You do not have 200 people singing 200 different notes; you have sections (soprano, alto) singing a limited set
of notes that harmonise. A typography scale is your limited set of "notes".
Our two fonts:
```text
:root {
  --font-heading: Georgia, "Times New Roman", serif;
  --font-body: "Segoe UI", Arial, sans-serif;
}
```
Georgia is a serif font (small "feet" on the letters) — it feels elegant and traditional, good for a fashion brand.
"Segoe UI" is a clean sans-serif (no feet) — easy to read for body text.
Note the font stack: several names separated by commas. If the first font is not on the device, the browser tries the next.
This is why we include Arial and serif / sans-serif as fallbacks.
The size scale:
```text
:root {
  --size-base: 16px;   /* normal paragraph text */
  --size-h3:   22px;
  --size-h2:   32px;
  --size-h1:   48px;
  --size-small:14px;
}
```
Applying the scale:
```text
body {
  font-family: var(--font-body);
  font-size: var(--size-base);
  line-height: 1.6;
}
h1, h2, h3 {
  font-family: var(--font-heading);
  color: var(--color-dark);
}
h1 { font-size: var(--size-h1); }
h2 { font-size: var(--size-h2); }
h3 { font-size: var(--size-h3); }
```
line-height: 1.6 means each line of text is 1.6 times the font size tall. Around 1.5–1.7 is comfortable for reading; the
default is often too tight.
Grouping h1, h2, h3 with commas applies the shared rules to all three, then each gets its own size. This is a reusable
pattern.
Expected browser result: headings appear in Georgia dark brown at clearly different sizes; body text is a readable Segoe UI.
Misconception. Learners think the browser's default h1 is "the only h1 size". It is not — you can set it to anything. Also, a
heading's size should not be used to make text look bigger; use a heading for a real heading, and change paragraph size if you
need to.
F.5 The spacing system — repeat a few numbers
The idea. Instead of inventing padding: 17px here and padding: 23px there, you pick a small set of spacing values and reuse
them.
Why it exists. Even spacing is a huge part of why a design "feels right". Random spacing makes a page feel jumpy even when
colours are fine.
Analogy. A bricklayer does not lay one row with 2mm mortar and the next with 8mm. Consistent gaps create a solid wall.
Consistent spacing creates a solid layout.
```text
:root {
  --space-1: 8px;
  --space-2: 16px;
  --space-3: 24px;
  --space-4: 32px;
  --space-5: 48px;
  --space-6: 64px;
}
```
Applying it:
```text
section {
  padding: var(--space-5) var(--space-3); /* 48px top/bottom, 24px sides */
}
h1 { margin-bottom: var(--space-3); }      /* 24px under the heading */
p  { margin-bottom: var(--space-2); }      /* 16px under paragraphs */
```
Expected browser result: sections have generous, even breathing room; headings sit a comfortable distance above their text.
Misconception. "Margin and padding do the same thing." They do not: padding pushes outward from inside the element
(space between content and border), margin pushes other elements away (space outside the border). Mixing them up is one of
the top CSS mistakes, covered in Section K.
F.6 Styling the header and navigation (flexbox)
The target look: a dark brown bar across the top. On the left, the logo "Adaeze Fashion" in gold. On the right, four nav links
(Home, Shop, About, Contact) in cream, turning gold when hovered.
The HTML we are styling (from Session 8):
```text
<header>
  <a href="index.html" class="logo">Adaeze Fashion</a>
  <nav>
    <ul>
      <li><a href="index.html">Home</a></li>
      <li><a href="shop.html">Shop</a></li>
      <li><a href="about.html">About</a></li>
      <li><a href="contact.html">Contact</a></li>
    </ul>
  </nav>
</header>
```
The CSS:
```text
header {
  display: flex;
  justify-content: space-between;
  align-items: center;
  background-color: var(--color-dark);
  padding: var(--space-2) var(--space-3);
}
```
```text
.logo {
  font-family: var(--font-heading);
  color: var(--color-gold);
  font-size: 24px;
  font-weight: bold;
  text-decoration: none;
}
```
```text
nav ul {
  display: flex;
  list-style: none;
  gap: var(--space-3);
  margin: 0;
  padding: 0;
}
```
```text
nav a {
  color: var(--color-cream);
  text-decoration: none;
  font-size: var(--size-base);
  transition: color 0.3s ease;
}
```
```text
nav a:hover {
  color: var(--color-gold);
}
```
Line by line:
header { display: flex; ... } turns the header into a flex container so the logo and the nav sit in a row.
justify-content: space-between pushes them to opposite ends — logo on the left, nav on the right.
align-items: center lines them up vertically in the middle.
nav ul { display: flex; } lays the list items out in a row instead of a vertical bulleted list.
list-style: none removes the bullet dots. margin: 0; padding: 0; remove the browser's default list indentation.
gap: var(--space-3) puts a 24px gap between each nav item (cleaner than margins).
transition: color 0.3s ease makes the colour change smooth over 0.3 seconds instead of jumping. ( ease means "start and
finish gently".)

F.11 The reset — starting from a clean slate
Different browsers add their own default margins and sizes. A short reset makes browsers behave the same.
```text
* {
  margin: 0;
  padding: 0;
  box-sizing: border-box;
}
```
* means "every element".
Removing all default margins/padding gives us full control.
box-sizing: border-box is the important one: it tells the browser that an element's declared width includes its padding and
border. Without it, width: 100% plus padding: 16px makes an element wider than 100% and it overflows. With border-box ,
100% means 100% — a huge time-saver.
Misconception. "The reset is optional." For beginners it is close to mandatory, because it removes a whole class of confusing
overflow bugs.
F.12 Organising the stylesheet
A stylesheet that is in a random order is hard to maintain. Professionals write it in a logical order with comment headers, so
anyone (including future-you) can find things.
The order we use all course long:
```text
/* ===== 1. Custom properties (colours, fonts, spacing) ===== */
/* ===== 2. Reset & base ===== */
/* ===== 3. Typography ===== */
/* ===== 4. Layout helpers (containers) ===== */
/* ===== 5. Header & navigation ===== */
/* ===== 6. Hero ===== */
/* ===== 7. Buttons ===== */
/* ===== 8. Product grid ===== */
/* ===== 9. Forms ===== */
/* ===== 10. Footer ===== */
/* ===== 11. Responsive media queries ===== */
```
Why comments matter. In three weeks you will not remember why .product has overflow: hidden . A one-line comment such
as /* keeps long titles from breaking the card */ saves minutes of guesswork. Comment the why, not the obvious.
Reusable classes. Notice we made one .button class and used it on the hero button, each product's Order link and the form
submit button. Write the rule once, reuse it everywhere. That is the professional habit that keeps CSS short and consistent.

## K. Common Mistakes and Troubleshooting
<!-- kind:troubleshooting -->
Use this as the live troubleshooting guide. When a learner hits a problem, ask them to check the matching row before giving the
answer.
K.1 A page has no styling at all
Symptoms: One page (or all pages) shows plain black text and blue underlined links. Likely causes: (a) The <link> tag is
missing from that page's <head> . (b) The href path is wrong (missing css/ ). (c) The file name is misspelled ( style.css vs
styles.css ). How to investigate: Press F12 → Console. Look for a red net::ERR_FILE_NOT_FOUND naming the stylesheet.
Compare the spelling exactly. Corrective steps: Add or fix the <link> line in every page; save; refresh with Ctrl+F5 . How to
confirm resolved: The page's colours and fonts return. Prevention: Put the exact same <link> line in all pages; keep
style.css inside the css/ folder.
K.2 My colours/fonts do not change even after editing :root
Symptoms: You change a variable but the page looks the same. Likely cause: The component is using a hard-coded value (e.g.
color: #2c1810; ) instead of var(--color-dark) . How to investigate: In DevTools, click the element and read which value wins in
the Styles panel. Corrective steps: Replace the hard-coded value with the matching var(...) . Prevention: Decide from the
start that all colours come from :root .
K.3 Product cards stack even on a wide screen
Symptoms: Cards appear in one vertical column instead of three. Likely cause: A class-name mismatch — the HTML says
class="product-grid" but the CSS rule is .products-grid . How to investigate: Compare the class name in the HTML and the
selector in the CSS, character by character (hyphens and plurals are the usual culprits). Or inspect the container in DevTools and
check whether the grid rule is greyed out. Corrective steps: Make both names identical. Prevention: Type the class in the
HTML first, then copy it into the CSS.
K.4 Navigation links keep their underline
Symptoms: The nav links are still underlined despite styling the navigation. Likely cause: The rule targets nav instead of nav
a . The underline belongs to the anchor. Corrective steps: Change nav { text-decoration: none; } to nav a { text-decoration:
none; } . Prevention: Remember: style the a , not its container.
K.5 Form inputs spill past the edge of the page
Symptoms: Inputs are wider than the form and cause a horizontal scrollbar. Likely cause: box-sizing: border-box is missing
from the reset, so padding adds to the 100% width. How to investigate: In DevTools, hover the input and watch the box-model
diagram — if width grows past 100%, this is it. Corrective steps: Add * { box-sizing: border-box; } at the top of the stylesheet.
Prevention: Always include the reset.
K.6 The Naira sign shows as ? or a box
Symptoms: ₦ renders as ? or a tofu box. Likely cause: The file was saved in a non-UTF-8 encoding. Corrective steps: In VS
Code, click the encoding in the bottom-right, choose Save with Encoding → UTF-8, and keep <meta charset="UTF-8"> in the
<head> . Prevention: Always keep the charset line.
K.7 Spacing looks random
Symptoms: Some sections are tight, others huge. Likely cause: You used one-off pixel values instead of the spacing variables.
Corrective steps: Replace ad-hoc values with var(--space-2) , var(--space-3) , etc. Prevention: Restrict yourself to the handful
of spacing values.
Distinguish likely vs confirmed: Every "likely cause" becomes confirmed only after you check it — read the Console error,
compare the class names, inspect the element. Teach learners to confirm before fixing so they do not change the wrong thing.

```text

```

INSTRUCTOR ANSWER KEY (Q1–Q7)
A1. So the design updates in one place and stays consistent across every page — edit once, all pages change together. A2. (c)
<link rel="stylesheet" href="css/style.css"> . A3. --color-dark: #2c1810; and color: var(--color-dark); . (Accept any sensible
variable name.) A4. It makes an element's declared width include its padding and border. Without it, width: 100% plus padding

var(--color-dark) updates automatically. A7. The logo appears on the far left and the nav list on the far right, both vertically
centred, in a single row.

## N. Reflection and Recap
<!-- kind:reflection -->
Plain-English summary. Today you stopped decorating single elements and started designing a whole website. You created one
shared stylesheet, stored the brand's colours, fonts and spacing as CSS custom properties, built a typography scale, and styled
the header, navigation, hero, product grid, buttons, footer and contact form. You organised the file with comment headers in a
logical order, reused one button class everywhere, and added media queries so the whole site adapts from desktop to phone —
all without touching the HTML structure you built last week.
Five important takeaways:
1. One shared external stylesheet keeps a multi-page site consistent.
2. CSS custom properties put the palette, fonts and spacing in one place.
3. Restraint wins: three to five colours and two fonts look professional.
4. Reuse classes (one .button ) instead of writing the same rule repeatedly.
5. Keep media queries at the bottom, in order from large to small.
Questions to help you recognise what you can now do:
Can I link one stylesheet to every page without help?
Can I change my whole site's colour by editing one variable?
Can I explain why nav a , not nav , controls the links?
Can I make a grid of cards that becomes one column on a phone?
Connection to the next session: Your site is now beautiful but still still — it looks good but does nothing when touched. In
Session 10 we add gentle interactivity with CSS (hover, transitions, simple animation), embed a Google Map on the contact page
and a YouTube video on the shop page, and touch on accessibility. That is the difference between a poster and an experience.

Observable signs of genuine competence:
Learner links the stylesheet to all four pages unaided, with the correct relative path.
Learner uses var() throughout rather than hard-coded colours.
Learner can point to :root and explain that changing one line updates the site.

Common misconceptions to watch for and correct:
"Each page needs its own CSS." → One shared file prevents drift.
"More colours and fonts look more designed." → Restraint looks professional.
" text-decoration: none on nav will work." → Style the anchor.
"The reset is unnecessary." → Without box-sizing: border-box , layout bugs multiply.
"Margin and padding are the same." → Inside vs outside the border.
Suggested remedial exercises for learners who struggle:
1. Link hunt: give a four-page site where one page is missing the <link> ; ask the learner to find and fix it using the Console.
2. Palette swap drill: hand over a finished stylesheet and ask the learner to reskin it to a new brand by editing only :root .
3. Selector fix-up: provide five rules with the wrong selector ( nav vs nav a , .product vs .products ) and ask for corrections.
Differentiation:
Level 1 (supported): Provide a partially completed style.css with :root and the reset already in place, and guide the
learner through pasting each section.
Level 2 (standard): The exercise and assignment as written.
Level 3 (challenge): Add a :root dark-mode variant toggled by a .dark class on <body> , add :focus-visible styles for
keyboard users, and introduce CSS clamp() for fluid heading sizes.
