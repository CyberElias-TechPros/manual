# CSS Basics

## A. Session Identification
<!-- kind:identification -->
**Week / module:** Week 2 — Module 2: CSS Foundations

**Recommended duration:** 105 minutes

**Difficulty:** Beginner

**Prerequisite knowledge:** Sessions 1–3. The learner can build a multi-page HTML site with semantic elements, links, images, a table and a form skeleton. Connection to previous session In Week 1 we built the structure of Adaeze Fashion — but it looks plain. This session adds the appearance: CSS. We take the existing HTML and style it without changing its content.

**Preparation before class:** Academy PCs on; VS Code and Chrome open; webdesign-practice open with index.html , about.html , contact.html ; the css folder created; projector connected; a demo "before" and "after" page prepared (Section G). Running project Adaeze Fashion gets its first styling: colours, fonts and spacing, done in an external stylesheet ( css/style.css ), the professional standard.

## B. Learning Outcomes
<!-- kind:outcomes -->
By the end of this session, the learner will be able to:
1. Explain what CSS is and why it exists, and state the split of duties: HTML = structure, CSS = presentation.
2. Name the three ways to add CSS — inline, internal and external — and explain why external is preferred.
3. Write correct CSS syntax — a selector, a property, a value, and a declaration ending in a semicolon.
4. Use the main selectors — element, class, id and grouped — and choose the right one for a task.
5. Specify colours using named colours, hex codes and rgb(), and comment on text/background contrast.
6. Style text using color , font-family , font-size , font-weight , text-align and line-height .
7. Set a background colour and a border, and explain the difference between padding and margin using the box model.
8. Explain, at a beginner level, the "cascading" idea — that later/more specific rules win.
9. Create an external stylesheet, link it to HTML with <link> , and confirm the styles appear in Chrome.

D. OPENING ACTIVITY (~6 minutes)
"The Before and After"
Instructor setup. Display two versions of the same Adaeze Fashion page side by side on the projector (or one after the other):
demo/before.html (HTML only — plain black text on white) and demo/after.html (the same content, styled with colour, fonts and
spacing). Same words, same images, same structure — different look.
What the instructor says:
"Look at these two pages. Same text. Same picture. Same words about Adaeze's gowns. But one looks like a letter typed in
the 1990s, and the other looks like a real business website. What changed?
Nothing in the content. What changed is the appearance. And in web design, appearance has its own language: CSS —
Cascading Style Sheets.
Last week, HTML said: 'This is a heading, this is a price, this is a list.' It never said the heading should be dark red, or the
list needs room to breathe. That was never HTML's job. Today, you learn to dress the page. By the end of the session, you
will make Adaeze's site look like the page on the right."
Expected learner response. Learners immediately prefer the styled page and become curious about which decisions made the
difference. Many will guess "colour" or "font". Confirm: colour, font, spacing and background — all CSS. Some may ask "can I
change the heading to blue?" — "Yes, and that is exactly today's work."
Why this opener works. It creates a strong, felt contrast and makes the value of CSS obvious before any syntax. It also
reinforces the HTML/CSS split taught in Session 1, so the new language feels like a natural next layer rather than a new subject.
E. PREREQUISITE REVIEW (~7 minutes)
Oral round-robin; questions on the projector.
Question 1: "What are the three building blocks of a website, and what is each one's job?"
Expected answer: HTML (structure), CSS (presentation/appearance), JavaScript (behaviour).
Gap: If a learner says "CSS is the structure", correct immediately with the house analogy — the walls are HTML, the paint is
CSS.
Question 2: "What are semantic HTML elements? Name two."
Expected answer: tags that describe meaning — e.g. <header> , <nav> , <main> , <footer> .
Gap: Learners list <div> . Remind that <div> has no meaning.
Question 3: "How do you link to another page on your own site?"
Expected answer: <a href="about.html">About</a> (a relative path).
Gap: Using full https:// addresses for local pages.
Question 4: "What must a form label's for attribute match?"
Expected answer: the input's id attribute.
Gap: Confusing id with the name attribute. Re-state.
Question 5: "After saving, what do you do to see changes in the browser?"
Expected answer: refresh ( F5 ).
Gap: This will be crucial today. Stress: save, then refresh — you will change CSS many times.
Bridge to today (say this):
"Your HTML is the skeleton — and it is solid. Today we add the skin, the clothes and the colour. But here is an important
professional rule from the start: we will not put the styling inside every HTML file. We will keep it in one separate
stylesheet, so one change updates the whole website. That is how professionals work, and that is what you will do today."
Gap handling. If several learners cannot recall that CSS is for appearance, spend two extra minutes with the house analogy. If
many struggle to save-and-refresh, pair them with confident learners, because CSS requires many quick save-refresh cycles.
F. FULL LECTURE NOTES (~40 minutes)
F.1 What CSS is and why it exists
The idea. CSS stands for Cascading Style Sheets. It is the language that controls how a web page looks: colours, fonts, spacing,
borders, backgrounds and layout.
Plain-English definition. If HTML describes what each piece of content is, CSS describes how it should appear. HTML is the
skeleton; CSS is the skin, hair and clothing.
Why it exists. Imagine a shop with 50 pages and a red heading on each. If the colour were written into every page's HTML,
changing it later means editing 50 files. With CSS, you change it once, and all 50 pages update. CSS separates content from
presentation — the second half of the "separation of concerns" idea from Session 1.
Familiar analogy. Think of a person and their clothes. The person's body (HTML) does not change, but different clothes (CSS)
change how they look on different occasions. The same body can wear a work uniform or wedding attire.
Why "Cascading"? "Cascading" means rules can come from different places and fall down in priority. If two rules target the
same element, the browser decides which one wins using the cascade (later rules and more specific rules win). We meet this
gently in F.13.
Worked example.
```text
h1 {
  color: navy;
}
```
This says: "for every <h1> , make the text colour navy." The HTML is unchanged; only appearance differs.
Misconception. "CSS is a programming language." It is a styling language — it describes appearance. It has no loops, no
decisions, no calculations. Do not expect it to "do" anything; it only styles.
F.2 The three ways to add CSS
There are three ways to connect CSS to HTML. Learn all three, but use the third.
1. Inline CSS — written directly on an element with the style attribute.
```text
<p style="color: red;">This text is red.</p>
```
Pros: quick for a one-off test.
Cons: it repeats the style on every element, mixes appearance into the HTML, and is hard to maintain. Avoid it.
2. Internal CSS — written in a <style> block inside the <head> .
```text
<head>
  <style>
    p { color: red; }
  </style>
</head>
```
Pros: keeps a single page's styles in one place.
Cons: it only affects this one page. A 4-page site needs the styles copied into all 4 files. Use only for quick experiments.
3. External CSS — written in a separate .css file, linked from the HTML.
```text
<head>
  <link rel="stylesheet" href="css/style.css">
</head>
```
Pros: one file styles the whole website; changing one file updates every page; the browser can cache it so pages load
faster; the HTML stays clean.
Cons: one extra file to manage — a trivial cost.
This is the professional standard, and what we use for Adaeze Fashion.
Reading the link tag.
<link> — a void element that connects a resource.
rel="stylesheet" — "the relationship is: this is a stylesheet".
href="css/style.css" — the relative path to our CSS file (inside the css folder).
Worked example — the Adaeze project layout.
```text
webdesign-practice/
├── index.html
├── about.html
├── contact.html
├── css/
│   └── style.css      ← ALL styling lives here
└── images/
```
Every HTML page has the same <link> line in its <head> , so the whole site shares one style.
Misconception. "Inline CSS is fine — it is faster." It is faster to type once, but every future change becomes slow and error-prone.
External CSS saves time over the life of a site, which is what matters professionally.
F.3 CSS syntax — selector, property, value, declaration
The idea. Every CSS rule has the same shape. Learn the parts by name.
```text
h1 {
  color: navy;
  font-size: 32px;
}
```
The parts:
h1 — the selector: which elements to style.
{ } — the curly braces: they hold the rule's declarations. (On a Nigerian keyboard, { is Shift + [ and } is Shift + ].)
color — a property: what to change.
navy — a value: how to change it.
color: navy; — the whole line is a declaration (property + value), and it ends with a semicolon ; .
Why the semicolon matters. Each declaration acts like a sentence; the semicolon is its full stop. If you forget it, the browser
may merge the declaration with the next one and ignore both. This is the single most common CSS beginner mistake. (See K.1.)
Whitespace and indentation. CSS ignores extra spaces and new lines. We indent the declarations inside the braces purely for
readability, exactly as we indent HTML.
Worked example — one rule, three declarations:
```text
p {
  color: #333333;      /* dark grey text */
  font-size: 16px;
  line-height: 1.6;
}
```
Expected result: every paragraph shows dark-grey text at 16 pixels with comfortable line spacing.
Misconception. "The ; goes after the closing brace." No — the semicolon ends each declaration inside the braces, not the
rule. The braces are closed with } .
F.4 Selectors — element, class, id, grouping
The idea. A selector tells CSS which element(s) to style. There are four you must know now.
1. Element selector — selects all elements of a type.
```text
p {
  color: #333333;
}
```
Applies to every <p> on the page.
2. Class selector — selects elements that have a matching class attribute. It starts with a dot . .
```text
.highlight {
  background-color: yellow;
}
```
```text
<p class="highlight">This paragraph has a yellow background.</p>
<p>This one is normal.</p>
```
A class can be used on many elements, and an element can have more than one class (space-separated): class="highlight big" .
3. ID selector — selects the one element with a matching id attribute. It starts with a hash # .
```text
#site-header {
  background-color: #1a3a5c;
}
```
```text
<header id="site-header">...</header>
```
An id must be unique on the page — use it for a single specific element.
4. Grouped selector — applies the same rule to several selectors at once, separated by commas.
```text
h1, h2, h3 {
  font-family: Georgia, serif;
}
```
This styles h1 , h2 and h3 with one rule — saves repetition.
How to choose.
Styling all headings → element selector.
Styling several elements of the same kind (e.g. all "price" labels) → class.
Styling one unique thing (e.g. the main header) → id.
Same styles for several selectors → group.
Memory aid. Dot for class, hash for id (from Session 1's Web Dev course too — same rule everywhere).
Misconception. "I can use the same id many times." No — ids are unique. If you want to style several elements the same way,
use a class, not repeated ids.
F.5 Colours — named, hex, rgb, and contrast
The idea. CSS can express a colour in several ways. All are valid; pick the one that suits the job.
1. Named colours — simple words.
```text
color: navy;
color: firebrick;
color: seagreen;
```
There are around 140 named colours. Simple and readable, but limited.
2. Hex codes — a # followed by six characters (0–9 and A–F), representing Red, Green and Blue. Format: #RRGGBB .
```text
color: #1a3a5c;   /* deep blue */
color: #ffffff;   /* white */
color: #000000;   /* black */
color: #e67e22;   /* orange */
```
The first two characters are red, the next two green, the last two blue.
00 means none of that colour; ff means full.
The most precise and widely used method.
3. rgb() — the same idea in decimal numbers from 0 to 255.
```text
color: rgb(230, 126, 34);   /* orange */
background-color: rgb(245, 245, 245);   /* light grey */
```
rgb(255, 0, 0) is pure red; rgb(0, 0, 0) is black.
Shortcut hex. When each pair is doubled ( #ff0000 , #ffffff ), it can be shortened: #f00 , #fff . Both mean the same. (Keep
the long form until you are comfortable.)
Background colours.
```text
body {
  background-color: #f5f5f5;
}
```
Sets the background of the whole page to a soft grey.
Contrast — critically important for a business site.
Contrast means how clearly text stands out from its background.
Dark text on a light background, or light text on a dark background, is readable. Grey text on a grey background is not.
Many websites must be readable by everyone, including people with poor eyesight. Strong contrast is both good design
and basic accessibility.
A simple rule for beginners: avoid light text on light backgrounds and dark text on dark backgrounds. Test by squinting
— if the words blur together, the contrast is too weak.
Worked example — a readable combination.
```text
body {
  background-color: #ffffff;   /* white background */
  color: #222222;              /* near-black text */
}
```
Expected result: strong, easy-to-read contrast.
Misconception. "Hex codes are random." They are not — they are just Red/Green/Blue in base-16. #ff0000 = full red, no green,
no blue.
F.6 Text properties — fonts, size, weight, alignment
The idea. CSS controls every aspect of how text looks.
font-family — which typeface to use.
```text
body {
  font-family: Arial, sans-serif;
```
```text
}
```
The browser tries the first font; if unavailable, it falls back to the next.
Always end with a generic family: serif , sans-serif or monospace .
font-size — how large the text is.
```text
p { font-size: 16px; }
h1 { font-size: 32px; }
```
Common units: px (pixels — fixed), em (relative to the parent), rem (relative to the root). For now, use px for clarity; we meet
relative units later.
font-weight — how thick the text is.
```text
strong { font-weight: bold; }
.normal { font-weight: normal; }
```
Values: normal , bold , or numbers like 400 (normal) and 700 (bold).
text-align — where the text sits horizontally.
```text
h1 { text-align: center; }
p { text-align: left; }
```
Values: left , center , right , justify .
line-height — the space between lines (leading).
```text
p { line-height: 1.6; }
```
A value like 1.6 means "1.6 times the font size". Comfortable reading is usually between 1.4 and 1.8 . A value of 1 feels
cramped.
text-decoration — underlines and lines.
```text
a { text-decoration: none; }        /* removes the underline on links */
.old-price { text-decoration: line-through; }
```
Often used to remove the default underline from navigation links.
Worked example.
```text
h1 {
  font-family: Georgia, serif;
  font-size: 36px;
  font-weight: bold;
  text-align: center;
  color: #1a3a5c;
}
p {
  font-size: 16px;
  line-height: 1.6;
}
```
Expected result: a centred, bold, deep-blue serif heading; body paragraphs in comfortable spacing.
Misconception. " em and px are the same." They are not — px is fixed, em / rem are relative. Use px now; learn relative units
later for responsive design.
F.7 Background and borders
The idea. Any element can have a background colour and a border (a line around it).
Background colour.
```text
header {
  background-color: #1a3a5c;
}
```
Fills the header's area with colour → you would then usually make its text light for contrast.
Border. A border has three parts: width, style, colour.
```text
table {
  border: 1px solid #cccccc;
}
th, td {
  border: 1px solid #cccccc;
  padding: 8px;
}
```
1px — the border thickness.
solid — the border style (others: dashed , dotted , none ).
#cccccc — the border colour.
Important note on HTML tables. By default, browser table borders leave small gaps between cells. CSS can collapse them:
```text
table {
  border-collapse: collapse;
}
```
This makes the borders join into one clean grid — very common on price tables.
Worked example.
```text
th, td {
  border: 1px solid #cccccc;
  padding: 8px;
  text-align: left;
}
```
Expected result: each table cell gets a thin grey line and a little breathing room inside.
Misconception. "A border and a background are the same." No — a background fills; a border is a line around the edge. You
often use both together.
F.8 Padding and margin — the box model explained clearly
This is the most important layout idea for beginners. Take it slowly.
The idea. In CSS, every element is treated as a box. The box has, from the inside out:
1. Content — the text or image itself.
2. Padding — space inside the box, between the content and the border.
3. Border — the line around the box.
4. Margin — space outside the box, pushing other elements away.
The box model, pictured as concentric rectangles:
```text
┌───────────────────────── margin ─────────────────────────┐
│   ┌───────────────────── border ─────────────────────┐   │
│   │   ┌──────────────── padding ─────────────────┐   │   │
│   │   │              CONTENT                     │   │   │
│   │   └───────────────────────────────────────────┘   │   │
│   └───────────────────────────────────────────────────┘   │
└───────────────────────────────────────────────────────────┘
```
Padding versus margin — the plain-English rule.
Padding = space inside the box (between the content and its own border). It pushes the border out from the content.
Margin = space outside the box (between this box and neighbouring boxes).
Familiar analogy. Think of a framed picture on a wall.
The content is the picture itself.
Padding is the mat board inside the frame, between the picture and the frame.
The border is the frame.
Margin is the empty wall space around the frame, separating it from the next picture.
Worked example.
```text
p {
  padding: 16px;      /* space inside the paragraph box */
  margin: 24px;       /* space outside it */
}
```
With padding: 16px , the text sits 16 pixels away from the paragraph's edge (visible if the paragraph has a background or
border).
With margin: 24px , the paragraph is pushed 24 pixels away from the paragraphs around it.
Shorthand. One value sets all four sides. You can also give two values ( 10px 20px = 10px top/bottom, 20px left/right) or four
values (top, right, bottom, left, clockwise). Start with one value.
Why it matters. Spacing is most of what makes a page look "professional" versus "cramped". Generous padding and margin
make text easy to read, which is exactly the difference between the "before" and "after" pages in the opener.
Misconception. "Padding and margin are the same thing." They are the two halves of the box model: padding is inside; margin
is outside. If you remember one thing today, remember this.
F.9 The cascading idea and specificity at a beginner level
The idea. "Cascading" and "specificity" explain what happens when two rules disagree about the same element.
Cascade (order). If two rules have the same specificity, the later rule wins — the one written further down the stylesheet.
```text
p { color: blue; }
p { color: red; }   /* this one wins — it comes later */
```
Expected result: paragraphs are red.
Specificity (how specific a selector is). A more specific selector beats a less specific one, regardless of order. The rough
ranking from weakest to strongest:
1. Element selector ( p ) — weakest.
2. Class selector ( .highlight ) — stronger.
3. ID selector ( #main ) — strongest.
4. Inline style ( style="..." ) — very strong (another reason to avoid it).
```text
p { color: blue; }              /* element — weak */
.highlight { color: green; }    /* class — stronger */
#special { color: purple; }     /* id — strongest */
```
```text
<p class="highlight" id="special">Which colour?</p>
```
Expected result: the text is purple, because the id rule is the most specific.
Why this matters. When a style "will not change", the usual cause is a more specific rule winning somewhere else. Knowing the
ranking helps you debug quickly. (See K.5.)
Keep it simple. For now, prefer classes, keep specificity low, and avoid inline styles. That prevents most "why won't it change?"
headaches.
Misconception. "The rule I want always wins." Not if a more specific rule disagrees. Specificity is the tie-breaker.

## K. Common Mistakes and Troubleshooting
<!-- kind:troubleshooting -->
K.1 A rule does not work (or the one after it fails too)
Symptoms: A style is ignored; sometimes the next style also fails. Likely cause: A missing semicolon at the end of a declaration.
How to investigate: Look at the declaration just above the failing one; check for a missing ; . Corrective steps: Add the
semicolon. How to confirm resolved: Both rules now apply. Prevention: End every declaration with ; before writing the next
line.
K.2 None of the CSS appears
Symptoms: The page has no styling at all. Likely cause: The <link> path is wrong, the file is not saved, or the link is outside
<head> . How to investigate: Compare href with the real file location; check the file is saved. Corrective steps: Fix the path
(e.g. css/style.css ), move the <link> into <head> , save. How to confirm resolved: Styles appear after refresh. Prevention:
Create the CSS file first, then link to its exact path.
K.3 The page still shows the old look
Symptoms: You changed the CSS but nothing moved. Likely cause: The file was not saved, or the browser was not refreshed (or
is showing a cached copy). How to investigate: Check the unsaved dot in VS Code; do a hard refresh with Ctrl + F5 .
Corrective steps: Save, then hard-refresh. How to confirm resolved: The new look appears. Prevention: Save, then refresh —
every single time.
K.4 Text is hard to read
Symptoms: Text blends into the background. Likely cause: Poor contrast (light text on a light background, or dark on dark).
How to investigate: Squint — if the words blur, contrast is too weak. Corrective steps: Darken the text or lighten the
background (or invert both). How to confirm resolved: Text is clearly readable. Prevention: Keep dark text on light
backgrounds or light text on dark backgrounds.
K.5 A style will not change no matter what
Symptoms: You edit a rule but an old value stays. Likely cause: A more specific rule (id, or inline style) is winning. How to
investigate: Use Chrome DevTools: right-click the element → Inspect → look at the Styles panel, which shows which rule
applies and which are crossed out. Corrective steps: Increase this rule's specificity (use the same or a stronger selector) or
remove the conflicting rule. Avoid inline styles. How to confirm resolved: Your value now applies. Prevention: Prefer classes,
keep specificity low, and do not use inline styles.
K.6 Padding and margin confused
Symptoms: Space appears on the wrong side of an element (inside vs outside). Likely cause: Mixing up padding (inside) and
margin (outside). How to investigate: Temporarily add a background colour; padding shows inside the coloured area, margin
is outside it. Corrective steps: Swap the property as needed. How to confirm resolved: The space is where you intended.
Prevention: Remember the phrase: padding is inside; margin is outside.
K.7 :hover written as .hover
Symptoms: The hover effect never appears. Likely cause: You wrote .hover (a class) instead of :hover (a state). How to
investigate: Check the colon. Corrective steps: Use a:hover { ... } . How to confirm resolved: The effect appears on mouse-
over. Prevention: Remember: a leading dot is a class; a leading colon is a state.
Distinguish likely vs confirmed. Confirm before fixing: open DevTools and see which rule applies, check the actual semicolon,
check the actual path. Do not guess.

## O. Instructor Evaluation Notes
<!-- kind:instructor_notes -->
Observable signs of genuine competence.
The learner creates and links an external stylesheet without prompting and uses it on more than one page.
The learner writes correct syntax, including semicolons, and can read a rule aloud (selector, property, value).
The learner chooses the right selector (element vs class vs id) and prefers classes.
The learner checks contrast and can justify a colour choice.
The learner distinguishes padding from margin and uses them purposefully.
The learner uses DevTools to investigate "why won't this style change?".
Common misconceptions to watch for and correct.
"CSS is a programming language." → It is a styling language; it describes, it does not compute.
"Inline CSS is fine." → External is the professional standard; inline is hard to maintain.
"Padding and margin are the same." → Padding inside; margin outside.
"Hex codes are random." → They are Red/Green/Blue in base-16 ( #RRGGBB ).
"Internal CSS styles the whole site." → It styles only one page.
" .hover gives a hover effect." → Use :hover (a state, with a colon).
"A missing semicolon only affects that one line." → It can break the declaration after it too.
Suggested remedial exercises.
1. Semicolon hunt: hand out a stylesheet with five missing semicolons; the learner finds and fixes them and checks in the
browser.
2. Selector sorting: give ten selectors and ten tasks; the learner matches the best selector type to each task and explains why.
3. Box model labelling: print a blank concentric-box diagram; the learner labels content, padding, border and margin, then
sets each in CSS and observes the effect.
4. Colour contrast fix: give three "hard to read" colour pairs; the learner adjusts the text or background to improve contrast and
explains the change.
Differentiation.
Level 1 (supported): Provide a style.css starter with the body , header and h1 rules written and commented; learners
complete the p , a and table rules. Pair with a confident learner.
Level 2 (standard): Complete the exercises and assignment as written.
Level 3 (challenge): Add border-radius (rounded corners), a box-shadow , text-transform: uppercase for a heading, and a
Google-style font stack; introduce a second colour used consistently as an accent, and explain the palette choice.
