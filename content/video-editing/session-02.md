# Editing Software and Interface

## A. Session Identification
<!-- kind:identification -->
**Week / module:** Week 1 — Module 1: Foundations and Story

**Recommended duration:** 105 minutes

**Difficulty:** Beginner (first hands-on editing)

**Prerequisite knowledge:** Session 1 — learners must have their organised, backed-up Pack A with a completed shot log. Basic computer confidence (mouse, keyboard, opening apps). No prior editing experience assumed.

**Connection to previous work:** In Session 1 you organised, named, logged and backed up your footage. Today that discipline pays off: you open CapCut for the first time, learn the interface, and build your first assembly — your clips placed in story order on the timeline, with no music, text or effects. The clean folder from Session 1 is what makes this assembly fast.

**Preparation before class:** CapCut desktop installed and tested on every academy computer (free version); CapCut mobile installed on the instructor's phone (to show the mobile interface); Pack A already organised in each learner's project folder from Session 1; a projector showing the instructor's screen; a sample "first assembly" pre-built by the instructor to show the finished result; headphones available for the next session (remind learners). Instructor note on tone: This is the session where learners touch the tool for the first time. Some will be excited; some will be nervous. Move slowly, repeat the core actions, and celebrate the first assembly loudly. The goal is not to learn every button — it is to learn the five core actions (import, place, split, trim, reorder) that every edit in the world is built from.

## B. Learning Outcomes
<!-- kind:outcomes -->
By the end of this session, the learner will be able to:
1. Open CapCut on desktop and mobile, create a new project, and set the aspect ratio, resolution and frame rate correctly
before importing.
2. Import footage from an organised folder into the media library, and explain why we import from a clean, named folder.
3. Identify the four main areas of the CapCut interface — media library, preview window, timeline and tools panel — and
state what each does.
4. Place clips on the timeline in story order to build a first assembly, with no music, text or effects.
5. Split, trim and reorder clips using the basic tools, and explain what the playhead is and how it controls where an edit
happens.
6. Save and name the project file correctly, and explain why the project file is not the video.

## D. OPENING ACTIVITY (6 minutes)
<!-- kind:opening -->
Instructor setup: On the projector, play a 30-second before-and-after. First, show 10 seconds of raw, unedited footage: a
talking-head clip with a long pause, a shaky start, a "um" in the middle, and a clip that runs too long. Then show the same
moment after editing: the pause removed, the "um" cut out, the clip tightened, the best moment kept.
What the instructor says:
"Good morning. Look at these two clips. Same person, same camera, same room. The first one is what the camera recorded.
The second one is what an editor made from it.
The difference is not magic. It is five actions: import, place, split, trim, reorder. That is it. Every edit you have ever
watched — a Nollywood film, a church highlight, a TikTok — is built from those five actions, repeated a thousand times
with taste and patience.
Today you learn those five actions. By the end of this session, you will have built your first assembly: your clips, in story
order, on a timeline. It will have no music, no text, no effects — and it will be the most important video you have made so
far, because it is the first one you shaped."
Expected learner response: Learners will say "so that is all editing is?", "I thought it was harder", "can I really do this today?"
Accept all answers. Say: "Editing is simple to start and deep to master. Today we start — properly."
Then set the frame: Say clearly:
"A professional does not open the software and start clicking. A professional sets up the project first — the same way you
organised your folder in Session 1. Setup is a habit. We do it the same way every time."
Why this opener works: It shows the transformation (raw → edited) in seconds, it demystifies editing (five actions, not magic),
and it sets the expectation that every learner will produce something real today.

## E. PREREQUISITE REVIEW (7 minutes)
<!-- kind:prereq_review -->
Run this as a fast oral round-robin. Put the questions on the projector.
Question 1: "What are the first four stages of the post-production workflow, and what does each one do?"
Expected answer: Ingest (move footage to the computer), Organise (folders and names), Log (note what each clip shows),
Backup (two copies in two places).
Common gap: learners remember the words but not the order. Clarify: "Ingest before organise, organise before log, log
before backup — each stage prepares the next."
Question 2: "Why did we rename our files in Session 1 instead of keeping the camera names?"
Expected answer: So we can find any clip in ten seconds; so a good name tells us what the clip shows without opening it.
Common gap: learners think renaming is optional polish. Clarify: "Renaming is not polish — it is the difference between a
ten-second find and a ten-minute hunt."
Question 3: "What is the playhead?" (Show a picture of a timeline with a vertical line.)
Expected answer: The vertical line that shows where you are in the video; it is where edits happen.
Common gap: many learners have never heard the word. Clarify: "The playhead is like your finger on a page — it marks the
exact spot where you are working."
Question 4: "What aspect ratio will you use for a YouTube video, and what resolution?"
Expected answer: 16:9 for YouTube; 1920×1080 (1080p) resolution.
Common gap: learners confuse aspect ratio with resolution. Clarify: "Ratio is the shape; resolution is the detail. Both are
setup decisions."
Bridge to today (say this):
"You have your organised pack, your shot log and your backup. Now you open the tool. The interface looks busy — but it
has only four areas that matter today, and five actions that matter forever. Learn those, and you can edit anything."
If more than a third of the class cannot answer Question 1, spend 5 extra minutes reviewing the workflow stages on the board
before continuing.

## F. Full Lecture Notes
<!-- kind:lecture -->
F.1 Why CapCut — and why free is enough
The idea. CapCut is a free video-editing application made by ByteDance (the company behind TikTok). It runs on Windows,
Mac, Android and iOS. It is the tool this course uses because it is free, powerful enough for professional work, and available to
every learner.
Plain-English definition. CapCut is a program that lets you import video clips, arrange them on a timeline, cut and trim them,
add music and text, and export a finished video file.
Why this course uses it:
It is free. No subscription, no trial that expires, no watermark on exports (unlike some free editors).
It is everywhere. A learner can start on a phone and continue on a desktop — the workflow is the same.
It is powerful enough. CapCut handles multi-track editing, keyframes, speed changes, colour tools and captions —
everything this course teaches and more.
It is what the market uses. Many small businesses, churches and creators in Nigeria already use CapCut; knowing it is a
real employable skill.
The honest limitation. CapCut is not the only tool, and it is not the most powerful tool in the world. DaVinci Resolve (free) is
stronger for colour; Adobe Premiere Pro (paid) is the industry standard in big studios. But CapCut covers everything a beginner
and a freelancer need — and the principles you learn in CapCut transfer to any other editor. Learn the principle, and the button
is just a button.
Real-life comparison. Think of CapCut like a small, sharp kitchen knife. A chef's knife set has twenty blades, but a sharp small
knife can prepare 90% of meals. CapCut is that knife — and a learner who masters it can cook real food.
Common misconception. "Free software is for amateurs." No. Free software is a choice — and for a beginner in Nigeria, it is the
smart choice. A ₦40,000 course that requires a ₦200,000 software subscription would be a bad course. This one requires
nothing but free tools.
F.2 The four areas of the interface
The idea. Every video editor — CapCut, Premiere, Resolve, iMovie — has the same four areas. Learn them once and you can
find your way in any software.
The four areas (draw this on the board):
Area What it is What you do there
1. Media Library
The box where your imported clips, music and images live Import, preview and select material
2. Preview Window
The screen that plays your video Watch the current frame; check your work
3. Timeline
The horizontal strip where clips are arranged in order Place, split, trim and reorder clips
4. Tools Panel
The buttons for actions (split, delete, text, audio, etc.) Perform edits on the selected clip
The playhead (the fifth thing to know): The playhead is the vertical line on the timeline that shows the exact moment you are
working on. It is where splits happen, where you place clips, and where you check your edits. Everything in editing happens at
the playhead.
How the four areas work together (the loop):
1. You import clips into the media library.
2. You drag a clip from the library to the timeline.
3. You move the playhead to where you want to cut.
4. You use a tool (split, trim) to make the edit.
5. You watch the result in the preview window.
6. Repeat.
Real-life comparison. The interface is like a kitchen: the media library is your fridge (ingredients), the timeline is your counter
(where you assemble), the preview window is your plate (what you check before serving), and the tools panel is your knives and
spoons. A cook who knows the kitchen can cook in any restaurant.
Common misconception. "I need to learn every button." No. Today you learn the four areas and five actions. The other buttons
are for later sessions — and you will learn them the same way: one at a time, with a reason.
F.3 Project setup — the promise you make before the first cut
The idea. Before importing a single clip, you set up the project: aspect ratio, resolution and frame rate. This is the digital
version of Session 1's folder structure — a promise you make to the whole project.
The setup steps (in order):
1. Open CapCut and click "New Project".
2. Set the aspect ratio — for this session's assembly, use 16:9 (the standard for learning; we will change it for specific
platforms in later sessions).
3. Set the resolution — 1920×1080 (1080p).
4. Set the frame rate — 30 fps (matching the footage).
5. Name the project — CEA-YourName_Assembly1 (using the naming convention from Session 1).
Why this order matters. If you import clips first and set up later, CapCut may guess the settings from the first clip — and if
that clip is the wrong shape or frame rate, the whole project is wrong. Setup first, import second.
What the project file is — and is not. The project file (in CapCut, it is saved in the app's project list) is a set of instructions:
which clips, in which order, with which edits. It is not the video. The video is created only when you export. This is why you can
save a project, close the computer, and come back tomorrow — the project remembers everything.
Real-life comparison. Setting up a project is like laying out your ingredients and tools before you cook. A cook who starts
cooking and then realises the pot is the wrong size has wasted time and food. Setup first, cook second.
Common misconception. "The project file is the video, so I can share it with the client." No. The client needs the exported
video file (the MP4). The project file is your working document — it is for you, not the client.
F.4 Import — bringing your organised footage into the tool
The idea. Import means bringing your video clips from the folder on your computer into CapCut's media library, so the
software can use them.
The import steps:
1. In CapCut, click "Import" (or the media library's add button).
2. Navigate to your organised folder: 01_Footage/PackA_TalkingHead/ .
3. Select the clips you need (use your shot log to choose).
4. Click Open — the clips appear in the media library.
Why we import from an organised folder. In Session 1 you renamed and logged your clips. Now that work pays off: you can
find Client_interview_01 in seconds, instead of hunting through VID_20260314_1832.mp4 . The import is fast because the
organisation was done first.
What import does NOT do. Importing does not move, rename or delete your original files. The originals stay safe in your folder;
CapCut makes a reference to them. This is why the backup from Session 1 matters — if a clip is missing, the project shows it as
"offline."
Real-life comparison. Import is like taking ingredients out of the fridge and putting them on the counter. The fridge (your
folder) stays full; the counter (the media library) is where you work.
Common misconception. "Importing copies the clips into the project, so I can delete the originals." No. Importing creates a
reference. If you delete the original, the project loses the clip. Keep your organised folder intact.
F.5 The five core actions — the alphabet of editing
The idea. Every edit ever made is built from five actions. Master these and you can edit anything.
The five actions (teach them in this order):
1. Place (drag to timeline). Click a clip in the media library and drag it onto the timeline. It becomes a block on the track. The
order of blocks is the order of your video.
2. Split (cut at the playhead). Move the playhead to the exact frame where you want to cut, then click Split. The clip becomes
two separate clips. This is how you remove a pause, an "um", or a bad take.
3. Trim (shorten the ends). Click the edge of a clip on the timeline and drag it inward to shorten the clip, or outward to
lengthen it. This is how you tighten a clip without cutting it in the middle.
4. Reorder (move clips around). Click a clip on the timeline and drag it to a new position. This is how you fix the story order —
move a clip earlier or later.
5. Delete (remove a clip). Select a clip and press Delete (or click the delete tool). This is how you remove a clip you do not
need. Use it carefully — and remember that deleting from the timeline does not delete the original file.
The loop that is editing: Place → Split → Trim → Reorder → Delete → watch → repeat. That loop, done with taste, is the
whole craft.
Real-life comparison. The five actions are like cutting and arranging a plate of food: place the items on the plate (place), cut a
piece in half (split), trim the edges (trim), move the rice to the centre (reorder), and remove the bone (delete). The plate is your
timeline; the meal is your video.
Worked example — the first assembly:
You have 6 talking-head clips and 2 cutaways.
You place them on the timeline in story order: intro clip → point 1 → point 2 → point 3 → closing clip.
You split out the long pause in clip 2.
You trim the shaky start of clip 4.
You reorder: move the closing clip earlier because it works better there.
You delete a clip that repeats what another clip says.
Result: a 60-second assembly with no music, text or effects — just story order.
Common misconception. "I need to learn more tools before I can edit." No. These five actions are enough to build a complete
assembly. The fancy tools come later — and you will appreciate them more because you understand what they add to these
five.
F.6 The timeline and tracks — where the video is built
The idea. The timeline is the horizontal strip at the bottom of the screen where your clips are arranged. It is the heart of the
editor.
Plain-English definition. The timeline is a visual representation of your video from start to finish. Time runs left to right. Each
block is a clip. The playhead moves across as the video plays.
Tracks — the layers of the timeline. The timeline has tracks — horizontal layers stacked vertically. The main video clips live
on the video track (usually the lowest one). Above it, you can add more video tracks for overlays, and below or beside it, audio
tracks for music and sound. For this session, you use one video track and its attached audio.
Why tracks matter. Tracks let you layer material: a talking-head clip on the main track, a cutaway on a track above it (to cover a
jump), music on an audio track below. Learning to think in tracks is learning to think like an editor.
The zoom control. The timeline has a zoom slider. Zoom out to see the whole video; zoom in to make precise cuts. Beginners
often cut at the wrong zoom level — too far out to be precise, or too far in to see the story. Learn to zoom for the task.
Real-life comparison. The timeline is like a seamstress's table: the fabric (clips) is laid out in order, cut to size (split/trim), and
arranged (reorder) before it is sewn. The tracks are the layers of fabric — the main piece, the lining, the decoration.
Common misconception. "More tracks = more professional." No. A clean edit on one track is better than a messy edit on five.
Tracks are tools, not trophies.
F.7 Saving, naming and the project file habit
The idea. Saving is not optional. Saving with a good name is a professional habit.
The save habit:
Save early, save often. CapCut auto-saves, but get in the habit of saving after every significant edit.
Name the project clearly. CEA-YourName_Assembly1 — not "Untitled" or "Project 1".
Know where it lives. CapCut saves projects in its own project list; the exported video goes to your 03_Exports folder.
The project file vs. the export (repeat this until it sticks):
The project file is your working document — the instructions. It is small and fast.
The exported video is the finished file — the MP4 you deliver. It is large and final.
You can have many project files; you export when the edit is done.
Real-life comparison. The project file is like a recipe; the export is the cooked meal. You can reuse the recipe; you cannot
uncook the meal. A client wants the meal — but you keep the recipe.
Common misconception. "If I save the project, I have the video." No. The project is the recipe. Without exporting, there is no
video to share.
F.8 Summary of the lecture
CapCut is free, powerful enough, and the right tool for this course — and the principles transfer to any editor.
The interface has four areas: media library, preview window, timeline, tools panel — plus the playhead.
Setup before import: aspect ratio, resolution, frame rate, project name.
Import brings clips from your organised folder into the media library — without moving or deleting the originals.
The five core actions are: place, split, trim, reorder, delete. Every edit is built from these.
The timeline is where the video is built; tracks are its layers.
The project file is the recipe; the export is the meal. Save often, name clearly.

## G. INSTRUCTOR DEMONSTRATION (15 minutes)
<!-- kind:demo -->
Goal: Build a complete first assembly live on the projector, narrating every decision, so learners see the five actions produce a
real result.
Setup: CapCut desktop open on the projector. Pack A organised in the instructor's project folder. A blank timeline ready.
Step 1 — Set up the project (2 minutes)
Say: "Setup first, always. I choose 16:9, 1080p, 30 fps — the course standard. I name the project CEA-Instructor_Assembly1 ."
Click through the setup on screen. Point out where the settings are.
Ask: "Why before import?" → So CapCut does not guess from the first clip.
Step 2 — Import the pack (2 minutes)
Say: "I import from my organised folder — the one I built in Session 1. I can find every clip in seconds because I renamed
and logged them."
Import 4–5 clips from the media library. Point out that the originals stay in the folder.
Ask: "Did import move my files?" → No, it references them.
Step 3 — Place clips in story order (3 minutes)
Say: "The assembly is just story order. No music, no text, no effects. I place the intro first, then the points, then the close."
Drag clips from the library to the timeline in order. Point out the blocks forming on the track.
Ask: "What is the timeline showing me?" → The order of my video, left to right.
Step 4 — Split and trim (4 minutes)
Say: "Now the craft. Clip 2 has a long pause — I move the playhead to the pause, split, and delete the pause. Clip 4 has a
shaky start — I trim the edge."
Perform the splits and trims on screen. Show the playhead moving, the split happening, the clip shortening.
Ask: "What did the split do?" → It cut the clip into two at the playhead.
Step 5 — Reorder and delete (2 minutes)
Say: "Watching it back, the closing works better earlier. I drag it. And clip 3 repeats clip 1 — I delete it from the timeline."
Drag the clip to its new position; delete the repeated clip.
Ask: "Did delete remove the original file?" → No, only from the timeline.
Step 6 — Watch the result (2 minutes)
Play the full assembly on the projector. It is rough — no music, no text — but it tells the story in order.
Say: "That is a first assembly. It is not finished — but it is shaped. Every professional edit starts exactly like this."
Expected result: A 45–60 second assembly on the timeline, built from five clips, with splits, trims, a reorder and a delete —
the exact model learners will follow.
Questions to ask during the demo:
"What are the four areas of the interface?" (Library, preview, timeline, tools.)
"Where does a split happen?" (At the playhead.)
"What is the difference between the project file and the export?" (Recipe vs. meal.)
"Why no music or text in the assembly?" (Story first; craft comes later.)

## H. GUIDED PRACTICAL EXERCISE (18 minutes)
<!-- kind:guided_practical -->
Objective: With the instructor guiding step by step, each learner builds their first assembly in CapCut desktop (or mobile) from
their organised Pack A.
Starting materials: CapCut open on the academy computer; the learner's organised Pack A in their project folder; the shot log
from Session 1; Worksheet 2.2 (checklist).
Procedure (instructor calls out each numbered step; learners follow; instructor walks the room):
1. Open CapCut and click New Project.
2. Set aspect ratio 16:9, resolution 1920×1080, frame rate 30 fps.
3. Name the project CEA-YourName_Assembly1 .
4. Import 5–6 clips from your organised 01_Footage/PackA_TalkingHead folder.
5. Place the clips on the timeline in story order: intro → points → close.
6. Watch the assembly once in the preview window.
7. Split out one long pause or "um" (move playhead → split → delete the unwanted part).
8. Trim the shaky or slow start of one clip.
9. Reorder one clip to a better position.
10. Delete one clip that repeats another.
11. Watch the full assembly again. Does the story make sense?
12. Save the project.
Expected result: A 45–75 second first assembly on the timeline, built from 5–6 clips, with at least one split, one trim, one
reorder and one delete — no music, text or effects.
Points to pause on and predict:
After step 6: "Does the story make sense in this order? If not, what would you move?"
After step 10: "What did you remove, and why?" (This is the editor's decision — the start of cut craft.)
Troubleshooting while walking the room:
Clips will not import → Check the file format (MP4 and MOV work; some phone formats need conversion).
Split button greyed out → The playhead is not on the clip; move it onto the clip first.
Timeline looks empty → The clip was placed on a hidden track; check the track headers.
Project will not save → Check the name has no special characters; try again.
Preview is choppy → This is normal on academy computers; the export will be smooth.
Completion checklist (learner ticks each):
Project created with correct settings (16:9, 1080p, 30 fps)
Project named with the convention
5–6 clips imported from the organised folder
Clips placed in story order
At least one split performed
At least one trim performed
At least one reorder performed
At least one delete performed
Full assembly watched and makes sense
Project saved

## I. INDEPENDENT CLASS EXERCISE (15 minutes)
<!-- kind:exercise -->
Task: Build a second, different assembly from the same pack — this time making your own decisions, without the instructor's
step-by-step guidance.
Scenario. You are editing a short video for a community organisation. You have the same Pack A footage, but this time the
story is: "Why our community needs a new youth centre." You must build a 30–45 second assembly that tells this story using
only the footage you have.
Requirements:
1. Create a new project with the correct settings.
2. Import and place 4–5 clips in an order that tells the story.
3. Use all five core actions at least once: place, split, trim, reorder, delete.
4. Watch the full assembly and check: does the story make sense? Is there a beginning, middle and end?
Time allowance: 15 minutes.
Success criteria:
Project set up correctly before import.
4–5 clips placed in a deliberate story order.
All five actions used at least once.
Assembly tells a clear beginning-middle-end story.
Project saved with the correct name.
Hints if stuck:
Hint 1: Start with the clip that best introduces the topic — that is your beginning.
Hint 2: The clip with the strongest emotion or action is your middle.
Hint 3: The clip that feels like a conclusion is your end.
INSTRUCTOR ANSWER KEY (model solution — do not show learners):
A strong learner solution has: a project set to 16:9/1080p/30fps; 4–5 clips placed in an order that opens with context, builds
with a point or two, and closes with a call or conclusion; at least one split (removing a pause or mistake), one trim (tightening a
start or end), one reorder (moving a clip to a better position), and one delete (removing a redundant clip); and a saved project
named correctly. The story should be understandable to someone who has never seen the footage — that is the test of an
assembly.
Learner marking (out of 10):
Correct setup before import (2)
4–5 clips placed in a deliberate order (2)
All five actions used (3)
Story has a clear beginning, middle and end (2)
Project saved with the correct name (1)

## J. Real-World Case Study
<!-- kind:case_study -->
Situation. Amina is a NYSC member in Port Harcourt who wants to earn extra income editing videos for small businesses. She
has a laptop and CapCut installed, but she has never taken a paid job. A local restaurant owner asks her to edit a 30-second
promo from 20 clips he shot on his phone. Amina opens CapCut, starts clicking, and two hours later she has a messy timeline,
no clear story, and no idea how to finish. She almost gives up.
Relevant facts.
Amina knows the CapCut interface — she has used it for fun.
The restaurant owner's clips are well-lit but unsorted: 20 clips with camera names, mixed with family photos.
Amina has no shot log, no folder structure and no backup.
She tried to add music and text before the story was in order — and now the timeline is chaotic.
Decision point. What went wrong — and what should Amina do differently?
Possible approaches.
1. Keep clicking until it looks right — she is close, she thinks.
2. Start over, but this time add music and effects first to make it interesting.
3. Start over with the professional sequence: organise, log, assemble, then craft.
Recommended solution. Approach 3. Amina's problem is not her software skill — it is her sequence. She tried to decorate
(music, text) before she had a structure (story order). The professional sequence is: organise the clips, log them, build the
assembly in story order, and only then add music, text and effects. Starting over with this sequence takes less time than fixing a
chaotic timeline.
Reasoning / what Amina would do:
Create a project folder and copy the 20 clips in.
Rename and log them.
Back up to a USB drive.
Build the assembly: 5–6 clips in story order, no music or text.
Only then add a music bed, a title and a caption.
Export and deliver.
Trade-offs.
Approach 1: the timeline gets more chaotic with every attempt; the job takes longer and the result is worse.
Approach 2: music and text without structure is decoration on a broken frame — it looks worse, not better.
Approach 3: starting over feels like lost time, but it is actually faster — because the assembly is the foundation everything
else sits on.
Professional connection. Amina can charge ₦15,000–₦25,000 for a 30-second restaurant promo. The restaurant owner
does not care how many buttons she knows — he cares that the video makes people hungry and shows the order number. An
editor who can take 20 messy clips and return a clean, story-shaped video in one day is an editor who gets paid. The assembly is
the skill that makes the sale.

## K. Common Mistakes and Troubleshooting
<!-- kind:troubleshooting -->
Use this table as the live guide. Point learners to the row rather than giving the answer.
K.1 Importing before setting up the project
Symptoms: The project has the wrong aspect ratio or frame rate; clips look stretched or cropped. Likely cause: Clips were
imported first, and CapCut guessed the settings from the first clip. How to investigate: Check the project settings against the
course standard (16:9, 1080p, 30 fps). Corrective steps: Create a new project, set up first, then import. How to confirm
resolved: Project settings match the standard before any clip is imported. Prevention: Setup is step one — every time, without
exception.
K.2 Splitting at the wrong place
Symptoms: The cut lands in the middle of a word or a breath; the edit feels jagged. Likely cause: The playhead was not on the
exact frame; the timeline was zoomed out too far. How to investigate: Zoom in on the timeline and check the playhead
position frame by frame. Corrective steps: Zoom in, move the playhead to the exact frame, split again. How to confirm
resolved: The cut lands on a clean frame — not mid-word. Prevention: Zoom in for precision cuts; the playhead is the scalpel.
K.3 Deleting the original file instead of the timeline clip
Symptoms: The clip is gone from the folder; the project shows it as "offline." Likely cause: The learner deleted the source file
instead of removing the clip from the timeline. How to investigate: Check the organised folder — is the file still there?
Corrective steps: Restore the file from the backup (this is why Session 1's backup matters). How to confirm resolved: The file
exists in the folder and the project. Prevention: Delete from the timeline only; the folder is sacred.
K.4 Adding music and text before the assembly
Symptoms: The timeline is cluttered; the story is unclear; the edit feels chaotic. Likely cause: Decoration was added before
structure. How to investigate: Watch the timeline — is there a clear story order under the music and text? Corrective steps:
Remove the music and text, fix the assembly, then add them back. How to confirm resolved: The assembly tells the story on its
own, without music or text. Prevention: Assembly first, craft second — always.
K.5 Not saving the project
Symptoms: After closing CapCut, the work is gone. Likely cause: The project was not saved; or the learner closed without
confirming the save. How to investigate: Open CapCut's project list — is the project there? Corrective steps: Rebuild (if
unsaved) — and save immediately after every significant edit. How to confirm resolved: The project appears in the project list
after closing and reopening. Prevention: Save early, save often; name the project so you can find it.
K.6 Confusing the project file with the export
Symptoms: The learner tries to send the project file to the client; the client cannot open it. Likely cause: The project file (the
recipe) was sent instead of the exported video (the meal). How to investigate: Ask: "What file did you send? Is it an MP4?"
Corrective steps: Export the video and send the MP4. How to confirm resolved: The client receives an MP4 that plays.
Prevention: The project is for you; the export is for the client.
K.7 Working from an unsorted folder
Symptoms: The learner cannot find the clip they need; the import takes forever; clips are missing. Likely cause: The footage
was not organised and named in Session 1. How to investigate: Open the footage folder — are the files named meaningfully?
Corrective steps: Stop, organise and rename (return to Session 1's method), then import. How to confirm resolved: Every clip
is findable in seconds. Prevention: Organisation is the foundation — never skip it.
Distinguish likely vs confirmed: A "likely cause" becomes "confirmed" only after you check it (e.g., the learner can show you
the project settings, or the missing file in the folder). Teach learners to confirm before concluding.

## L. Session Assignment
<!-- kind:assignment -->
Assignment title: "My First Assembly — Two Versions and a Reflection"
Purpose: To practise the five core actions until they are automatic, and to build the assembly skill that the capstone depends on.
Realistic scenario. You are editing a 60-second video for a Port Harcourt community group. You have a footage pack of talking-
head clips and cutaways. Your job is to build two different assemblies from the same pack — and explain your decisions.
Detailed instructions:
1. Open CapCut and create a new project with the correct settings (16:9, 1080p, 30 fps).
2. Import 6–8 clips from your organised Pack A.
3. Build Assembly A: a 45–60 second version that tells the story in a straightforward order.
4. Build Assembly B: a 30–45 second version that tells the same story with a different structure (e.g., start with the strongest
moment, or end with a question).
5. For each assembly, write 3–4 sentences explaining: which clips you chose, why that order, and what you removed and
why.
6. Save both projects with clear names ( CEA-YourName_AssemblyA , CEA-YourName_AssemblyB ).
Required deliverables:
Two saved CapCut projects (checked in class or via screenshot of the timeline).
A short written reflection (3–4 sentences per assembly) explaining the decisions.
Submission format: Reflection as a typed document ( Session2_YourName.docx or .pdf ) submitted to /Video-
Editing/Week1/Assembly/ , plus the two project files checked in class.
Deadline: Before Session 3.
Marking rubric (20 marks):
Criterion Marks Description of a strong answer
Correct project setup 3 16:9, 1080p, 30 fps, named correctly
Assembly A — story order 4 Clear beginning, middle, end; clips in a deliberate order
Assembly B — different structure 4 A genuinely different structure, not just a shorter cut
Five actions used 4 Place, split, trim, reorder, delete all used in both
Written reflection 3 Clear reasons for clip choice, order and removals
Saving and naming 2 Both projects saved with correct names
Common mistakes to avoid: importing before setup; adding music or text before the assembly; deleting original files; not
saving; two assemblies that are identical; no reflection.
INSTRUCTOR REFERENCE SOLUTION (do not show learners):
A strong learner solution has: two projects with correct settings; Assembly A as a straightforward chronological story (intro →
points → close) using 6–8 clips with splits, trims, a reorder and a delete; Assembly B as a different structure — for example,
opening with the strongest emotional moment, then flashing back to the context, then closing with a call — using fewer clips
and tighter cuts; and a reflection that names specific decisions: "I put the owner's welcome first because it is the beginning of
the story; I removed the third clip because it repeated the second; I moved the closing clip earlier because it works as a
summary."

## M. Knowledge Check
<!-- kind:knowledge_check -->
(Learner version — answers only in the Instructor Key.)
Q1. Short answer. What are the four main areas of the CapCut interface?
Q2. List. Name the five core editing actions, in the order you would use them to build an assembly.
Q3. Multiple choice. When should you set the aspect ratio, resolution and frame rate? a) After importing the clips b) Before
importing the clips c) After exporting d) It does not matter
Q4. True or false. Importing a clip into CapCut moves the file from your folder into the project, so you can delete the original.
Q5. Explain. What is the difference between the project file and the exported video?
Q6. Scenario. You are building an assembly and the story does not make sense in the order you placed the clips. What should
you do — and which of the five actions will you use?
INSTRUCTOR ANSWER KEY (Q1–Q6)
A1. Media library, preview window, timeline, tools panel (plus the playhead).
A2. Place, split, trim, reorder, delete (then watch and repeat).
A3. (b) Before importing the clips — so CapCut does not guess the settings from the first clip.
A4. False. Importing creates a reference to the file; the original stays in the folder. Deleting the original breaks the project.
A5. The project file is the working document — the set of instructions (which clips, which order, which edits). The exported
video is the finished MP4 file you deliver to the client. The project is the recipe; the export is the meal.
A6. Reorder the clips — drag them to a better position on the timeline until the story makes sense. The action is reorder.
(Accept any answer that identifies reorder and explains checking the story.)

## N. Reflection and Recap
<!-- kind:reflection -->
Plain-English summary. Today you met the tool. You learned that CapCut is free, powerful enough, and the right choice for this
course — and that the principles you learn in it transfer to any editor. You learned the four areas of the interface (media library,
preview window, timeline, tools panel) and the playhead. You set up a project correctly before importing, imported from your
organised folder, and built your first assembly using the five core actions: place, split, trim, reorder, delete. You learned that the
project file is the recipe and the export is the meal. And you saw that an assembly — rough, with no music or text — is the
foundation every professional edit is built on.
Five important takeaways:
1. CapCut is free and enough — and the principles transfer to any editor.
2. The interface has four areas — library, preview, timeline, tools — plus the playhead.
3. Setup before import — aspect ratio, resolution, frame rate, name.
4. Five actions build every edit — place, split, trim, reorder, delete.
5. The project is the recipe; the export is the meal — save often, name clearly.
Questions to help you recognise what you can now do:
Can I name the four areas of the interface?
Can I set up a project correctly before importing?
Can I build an assembly using the five core actions?
Can I explain the difference between the project file and the export?
Can I explain why the assembly comes before music and text?
Connection to the next session. You have your first assembly — your clips in story order. Next session we turn that assembly
into a rough cut with real cut craft. You will learn the named cut types — straight cut, jump cut, cut on action, match cut —
and the two invisible workhorses, the J-cut and L-cut. You will learn pacing, rhythm and story shape, and how B-roll covers a
jump. The assembly you built today is the raw material for that craft.

## O. Instructor Evaluation Notes
<!-- kind:instructor_notes -->
Observable signs of genuine competence:
Learner sets up the project correctly before importing, without being reminded.
Learner names the four interface areas and the playhead.
Learner builds an assembly using all five core actions.
Learner explains the difference between the project file and the export.
Learner's assembly tells a clear story in order — beginning, middle, end.
Learner saves the project with a correct name.
Common misconceptions to watch for and correct:
"I need to learn every button first." → Five actions are enough to start; the rest come with reasons.
"Music and text make the video." → Structure first; decoration second.
"The project file is the video." → The project is the recipe; the export is the meal.
"Importing moves the files." → It references them; the originals stay.
"Setup can wait." → Setup mistakes are expensive to undo.
Suggested remedial exercises for learners who struggle:
1. Five-action drill: give the learner three clips and ask them to place, split, trim, reorder and delete — narrating each action
as they do it.
2. Interface labelling: give a screenshot of the CapCut interface with blank boxes; the learner labels the four areas and the
playhead.
3. Setup race: ask the learner to create a new project with the correct settings in under one minute — repeated until it is
automatic.
Differentiation:
Level 1 (supported): provide a step-by-step checklist with screenshots; the learner follows it to build the assembly.
Level 2 (standard): the session as written — guided practical plus independent second assembly.
Level 3 (challenge): ask the learner to build an assembly that tells the story without the obvious chronological order — for
example, starting at the end and flashing back — and explain why that structure works.
Timing guidance. The priority is learners building their own first assembly (Sections H and the assignment). If the room is
slow, shorten the case study (Section J) to a 3-minute mention and limit the independent exercise to one assembly instead of
two. Protect the practical time — a learner who leaves without a completed assembly has no foundation for Session 3's cut
craft.
