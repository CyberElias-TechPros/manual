# Hardware Diagnostics

## A. Session Identification
<!-- kind:identification -->
**Week / module:** Week 2 — Module: Diagnostics

**Recommended duration:** 105 minutes

**Difficulty:** Beginner (first structured hardware fault-finding)

**Prerequisite knowledge:** Sessions 1–4: the six major components, safe handling and tools, disassembly/reassembly, and the five-step diagnostic workflow (Observe → Ask → Hypothesise → Test → Resolve). If a learner cannot name the six major components or list the workflow, run the 10-minute refresher in Appendix 5A before this session.

**Connection to previous work:** Session 4 gave you the workflow. This session gives you the tools and tests you apply at the "Test" step when you suspect the fault is hardware.

**Preparation before class:** Practice desktops on the benches; diagnostic software installed (CrystalDiskInfo, HWMonitor); a bootable MemTest86 USB prepared by the instructor; one known-good and one known faulty RAM stick; one known-good and one failing hard drive; one known-good PSU; a working monitor and one spare VGA/HDMI cable; anti-static wrist straps; a PSU tester if the academy has one (optional); printed Diagnostic Report Forms (one per learner); Component Identification Charts on the wall. A note on wording used in this course. In CEA materials the word "diagnostics" means the act of finding out what is wrong, not only software. A diagnostic tool is any device or program that helps you find a fault. This session is about hardware: physical parts that can fail. Session 6 is about software.

Institution

## B. Learning Outcomes
<!-- kind:outcomes -->
By the end of this session, the learner will be able to:
1. Explain, in plain language, what a hardware fault is and how it differs from a software fault.
2. Describe the common symptoms of a faulty RAM stick — failure to boot, beep codes, random restarts, blue screens —
and run a memory test using Windows Memory Diagnostic or MemTest86.
3. Read a storage drive's S.M.A.R.T. health in CrystalDiskInfo and decide whether the drive is Good, Caution or Bad; state when
to back up and when to replace.
4. List the basic checks for a power supply fault (no power, random shutdowns) and explain why the PSU must never be
opened.
5. Identify an overheating problem by checking temperatures with HWMonitor and inspecting dust, fans and thermal paste.
6. Diagnose a "no signal" display fault by testing the cable, the monitor, the GPU and the RAM in a sensible order.
7. Apply the swap-testing and isolation method to prove which component is faulty.
8. Record findings on a Diagnostic Report Form using clear, plain language a customer can understand.

## D. OPENING ACTIVITY (6 minutes)
<!-- kind:opening -->
Instructor setup: On the projector, show a photo or drawing of a car dashboard with the check-engine light on. Do not explain
yet.
What the instructor says:
"Good morning. When your car's check-engine light comes on, you do not open the bonnet and start changing parts at
random. You take it to a mechanic. The mechanic plugs in a small computer and it gives codes — it tells him exactly which
sensor is complaining. He does not guess; the tool does the guessing for him.
A computer is the same. When a computer misbehaves, we do not start replacing parts blindly. We use tools to ask the
machine a question and read the answer. Sometimes the machine answers with a beep instead of words. Sometimes it
answers with a temperature reading. Sometimes it answers with a health status: Good, Caution or Bad.
Today you become the mechanic. You will learn the tools that make a computer tell you what is wrong with its hardware."
Expected learner response: Some may mention "blue screen", "it beeps", "loud fans" or "the screen just shows nothing".
Accept all answers and write them on the board. Say: "These are all symptoms. Today we turn symptoms into a diagnosis."
Then demonstrate the hook: On the projector, open CrystalDiskInfo. Point at the blue "Good" status and say:
"See this word — Good. That is the drive telling us it is healthy. If I open a drive that is failing, this turns yellow, or even
red. One colour is the difference between a fine computer and five years of somebody's photos lost forever. By the end of
today, you will be able to read this yourself."
Why this opener works: It connects a familiar everyday tool (the mechanic's code reader) to computer work, it sets the
expectation that we test rather than guess, and it ends with a concrete, exciting promise (reading drive health) that the learners
will actually do in the practical.

## E. PREREQUISITE REVIEW (7 minutes)
<!-- kind:prereq_review -->
Run this as an oral round-robin. Put the questions on the projector. Keep it fast — this is revision, not new teaching.
Question 1: "Name the five steps of the diagnostic workflow."
Expected answer: Observe → Ask → Hypothesise → Test → Resolve (then document).
Common gap: learners remember "test" but forget "ask the customer" or "document". Remind them that a diagnosis you
cannot explain is not finished.
Question 2: "What are the six major components inside a computer?"
Expected answer: Motherboard, CPU, RAM, storage (hard drive/SSD), PSU, GPU.
Common gap: omitting the PSU. Probe: "What turns the wall electricity into the voltages the parts need?"
Question 3: "Why do we always start by checking the simplest possible cause first?"
Expected answer: Because the simplest cause is quick to check and is very often the real one. We save time and money by
ruling out easy things (a loose cable, a dead socket) before opening the case.
Common gap: learners jump straight to "replace the hard drive". Correct this — a loose monitor cable looks exactly like a
dead GPU, and costs ₦0 to fix.
Question 4: "A computer fails to start and you hear repeated beeps. What is the machine trying to tell you?"
Expected answer: The motherboard lights up and runs a self-test before loading Windows; if something basic fails, it beeps
a pattern instead of showing a picture. Beeps usually point to RAM, the GPU, or another key part.
Common gap: learners think the beeps are "just a noise". Introduce the term POST now (Power-On Self-Test) — we define
it properly in Section F.
Question 5: "Why must we document every finding, even when we are not yet sure?"
Expected answer: So the work can be verified later, so a colleague can continue where you stopped, and so the customer
gets an honest, clear report. Also, comparing "before" and "after" readings proves the repair worked.
Bridge to today (say this):
"In Session 4 you learned to think like a technician. Today you learn to test like one. Think of a doctor. The workflow is the
doctor asking questions and forming a theory. The diagnostic tools today are the stethoscope and the blood test — the
things that turn a theory into a fact."
Gap handling: If more than a third of the class cannot answer Question 1 or 2, pause and run the Appendix 5A refresher now (10
minutes), then continue. Do not push on with learners who cannot name the parts — today depends on it.

## F. Full Lecture Notes
<!-- kind:lecture -->
F.1 Hardware fault versus software fault — what is the difference?
The idea. Everything that goes wrong with a computer is either hardware or software. Getting this right early saves hours.
Plain-English definition.
A hardware fault is a problem with a physical part: a stick of RAM that is damaged, a hard drive that is wearing out, a fan
that has stopped spinning.
A software fault is a problem with the instructions or data: a virus, a corrupted Windows file, a wrong driver.
Why the distinction exists. The word "fault" describes what is wrong, but hardware and software are fixed in completely
different ways. Hardware faults are usually fixed by replacing or repairing a part. Software faults are usually fixed by cleaning,
correcting or reinstalling the software. If you fix the wrong type, you waste time and money.
Analogy. A car is hardware; the driver's bad habit of always pressing the brake is "software". If the brake pedal itself is broken,
that is a hardware fault — you replace the pedal. If the pedal is fine but the driver keeps stalling, that is a "software" fault —
you have to change the behaviour. Replacing a perfectly good pedal because of a driving habit would be a waste.
Realistic Port Harcourt scenario. A customer in Rumuokoro says his laptop "is very slow and sometimes beeps and restarts".
The "slow" part sounds like software (too many startup programs, or a virus). But the "beeps and restarts" part sounds like
hardware (RAM or overheating). This session's job is the second half — the hardware. Session 6 handles the first half. A good
technician separating the two is what makes a diagnosis fast.
Important misconception. "If Windows is slow, it must be a virus." Not always. A failing hard drive and too little RAM both
make a computer slow, and both are hardware. Always test before you decide.
Key limitation. Some faults look like one type but are the other. Example: a failing hard drive can corrupt Windows files, so you
see software symptoms caused by a hardware problem. This is why we test the hardware first — if the foundation (RAM, drive,
power, cooling) is bad, no amount of software fixing will hold.
F.2 POST and beep codes — the very first test
The idea. When you press the power button, before Windows ever appears, the computer runs its own quick self-check.
Plain-English definition. POST stands for Power-On Self-Test. It is a tiny set of instructions stored on the motherboard that
checks that the basic parts — CPU, RAM, graphics, keyboard — are present and responding before handing over to the
operating system.
Why it exists. Imagine a bus company that will not move the bus until it has checked that the engine, brakes and doors work.
POST is the computer doing that check on itself. If a critical part fails the check, the computer cannot show a picture, so it uses
beeps (or a light on the motherboard, depending on the model) to tell you which basic part failed.
What it does. It runs in the first one or two seconds after power-on. If everything passes, you hear a single short beep (on some
models) and the screen shows the maker's logo. If something basic fails, you hear a pattern of beeps, or nothing at all.
Analogy. POST is like the fuel-pump priming sound you hear for a moment when you switch on many cars before the engine
starts — the car checking itself quietly before it lets you drive.
Realistic Port Harcourt scenario. A cyber café PC will not show anything on screen and beeps three times. The café owner
assumes the monitor is dead and is about to buy a new monitor. A technician recognises the beep pattern as a memory (RAM)
warning, reseats the RAM stick, and the machine works — for free.
Important note on beep meanings. The beep pattern depends on the make of the motherboard's BIOS/UEFI (for example,
the number and length of beeps). Because this differs between makers, the correct professional method is: count the beeps,
then look up that maker's beep code in the manual or on the maker's support page. Do not memorise one pattern and
assume it fits every computer. In this course we teach you to count and look up, not to guess.
Important misconception. "No beep means the computer is completely dead." Not always. Many modern motherboards have
no built-in speaker, so they cannot beep at all. On those, a small debug light or LED code on the board does the same job. Also,
some working computers never beep. Absence of a beep is a clue, not a verdict.
Limitation. POST only checks very basic things. It does not test your storage deeply, it does not test the display cable, and it
cannot tell you a drive is slowly failing. For those, we use the tools below.
F.3 Diagnosing RAM faults
The idea. RAM (Random Access Memory) is the fast scratch-pad where the computer holds whatever it is working on right
now. When RAM goes bad, the computer becomes unstable in a very particular way.
Plain-English definition. RAM faults are failures in the memory sticks — the long, flat strips plugged into the motherboard. A
stick may be entirely dead, or it may work most of the time and fail only occasionally (called an intermittent fault, one of the
hardest to catch).
Why RAM matters. Windows and every program keep their current work in RAM. If the memory returns a wrong value even
once, calculations go wrong, programs crash, or Windows shows a blue screen.
Common symptoms of faulty RAM:
Computer will not start, or starts then restarts again and again ("boot loop").
Repeated beep patterns during POST.
Blue screen errors (in Windows, the "Blue Screen of Death" or BSOD) — especially stop codes that mention memory.
Programs closing suddenly with no warning.
Files becoming corrupted for no clear reason.
Random freezes under load.
Analogy. RAM is like the work-table of a tailor in the market. If one corner of the table is warped, most sewing is fine, but every
time you lay cloth on that corner the measurement comes out wrong. The whole table is not useless — only that spot — but it
spoils everything that touches it.
How we test RAM — Tool 1: Windows Memory Diagnostic.
1. Save all work and close all programs.
2. Press the Windows key, type Windows Memory Diagnostic, and open it.
3. Choose Restart now and check for problems.
4. The computer restarts and runs the test outside Windows. This can take 10–30 minutes.
5. When Windows restarts, the results appear (also visible later in Event Viewer).
What it does: it writes known patterns into RAM and reads them back, looking for any mismatch.
How we test RAM — Tool 2: MemTest86. MemTest86 is the deeper, more trusted test. It runs from a USB drive before
Windows starts.
1. Insert the MemTest86 USB prepared by the instructor.
2. Restart and boot from the USB (the exact key to enter the boot menu — often F12, F10, F2 or Del — depends on the make;
the instructor will show it on the practice machines).
3. The test starts automatically and shows a screen of moving numbers.
4. Let it complete at least two full passes (this can take 30+ minutes, so in class we usually start it and observe the first pass
only).
5. Any red line or "errors" count above zero means the RAM is faulty.
Isolating the bad stick (swap testing). If the machine has more than one RAM stick:
1. Remove one stick, leaving only stick A, and run the test.
2. If errors appear, stick A is bad. If not, remove stick A and test stick B alone.
3. Test one at a time until you find the faulty one.
4. You can also swap a known-good stick in: if the faults disappear, the original stick was the problem.
Important misconception. "The computer counts 8 GB of RAM, so the RAM is fine." Capacity is not health. A stick can be fully
detected and still return wrong values occasionally. Only a test proves health.
Limitation. Memory testers cannot find every intermittent fault, because a bad spot may only fail when hot or under a certain
load. If a memory test passes but the symptoms strongly suggest RAM, an experienced technician may still swap the stick as a
test. Also, a blue screen can be caused by a bad driver rather than bad RAM — Session 6 covers that.
F.4 Diagnosing storage faults (hard drives and SSDs)
The idea. Storage is where your files live permanently. When a spinning hard disk is wearing out, it usually warns you before it
dies — if you know how to read the warning.
Plain-English definition.
A hard disk drive (HDD) has spinning metal platters and a moving read/write head. Being mechanical, it can wear out and
make noise.
A solid-state drive (SSD) has no moving parts; it stores data in memory chips. It is faster and quieter, but it can still fail,
often with less warning.
S.M.A.R.T. stands for Self-Monitoring, Analysis and Reporting Technology — a built-in system where the drive
continuously measures its own health and reports it.
Why it exists. Drive makers realised that most drives die slowly. S.M.A.R.T. was created so that a technician's tool could read
these self-measurements and warn the owner before total failure — giving time to back up.
What it reports (the important parts).
An overall Health Status: Good (blue), Caution (yellow) or Bad (red).
Temperature — a drive running too hot may need better airflow or cleaning (see F.6).
Reallocated sector count — sectors the drive has quietly set aside because they became unreadable. Any number above
zero is a warning sign; a rising number means the drive is dying.
Power-on hours — how long the drive has been running in its life, useful context.
Analogy. S.M.A.R.T. is like the oil-warning light in a car. It does not fix the engine, but it tells you "the engine is not happy" early
enough for you to act. Ignore it, and you get a broken-down car and a big bill.
Tool: CrystalDiskInfo.
1. Open CrystalDiskInfo.
2. Read the Health Status word and colour at the top.
3. Read the Temperature.
4. Scroll the attribute list and look at Reallocated Sectors Count and any item flagged in yellow or red.
5. If it says Good — continue normal checks. If Caution — back up the customer's data immediately and recommend
replacement. If Bad — stop writing to the drive, back up if it still reads, and replace it.
Symptoms a storage drive is failing:
The computer became very slow, especially at start-up or when opening files.
Clicking, ticking or grinding noises from the drive (HDD only).
The drive is not detected by the BIOS or by Windows.
"No boot device" or "operating system not found" errors.
Files and folders disappearing or becoming corrupted.
Clicking noise — what to do. A repetitive clicking sound from an HDD almost always means the head is failing to read the
platter. Do not keep powering it on and off trying to make it work — each attempt can scrape more data away. If the data is
important, power it down and take it to a data recovery specialist. Explain to the customer, honestly, that data recovery is not
something a general repair technician should attempt casually, and that it can be expensive.
Important misconception. "SSDs do not fail." They do fail. They are more shock-resistant than HDDs, but they can still stop
working, often suddenly. Backups matter for both.
Limitation of CrystalDiskInfo. A drive can show "Good" and still fail suddenly (especially some SSDs). S.M.A.R.T. is a warning
tool, not a guarantee. The only true protection is a backup. Say this to every customer: "Health tools reduce risk; only a backup
removes it."
F.5 Diagnosing power supply (PSU) faults
The idea. The PSU (Power Supply Unit) converts the wall electricity (240 V in Nigeria) into the low voltages (12 V, 5 V, 3.3 V) the
components use. If it is weak or dead, the whole computer is affected.
Plain-English definition. The PSU is the metal box, usually at the top or bottom-back of the case, that the power cable plugs
into. A PSU fault means it is not delivering correct, stable power.
Why it exists. Components cannot use 240 V directly — they would be destroyed instantly. The PSU safely steps the voltage
down and steadies it.
Common symptoms of a PSU fault:
The computer does not power on at all (no lights, no fans).
The computer powers on for a second then dies.
Random shutdowns or restarts, especially when the computer is working hard.
Burning smell, or scorch marks near the PSU.
The fans twitch but the machine will not start.
Analogy — and this analogy is a warning. The PSU is like the transformer that feeds a whole street. If your mains voltage is
unstable, every appliance in the house behaves strangely — flickering lights, a fridge that hums then dies. The PSU is the same
for the computer. But unlike a street transformer, you must never open the PSU to check inside.
SAFETY — READ ALOUD AND POST ON THE WALL. Never open a PSU case. Even when the computer is unplugged
and has been off for hours, the large capacitors inside a PSU can store a lethal electrical charge. Touching the wrong
part can kill you. A PSU is not a repairable item for a general technician — it is a replace-only item.
Basic PSU checks a beginner may perform (all with the computer unplugged unless stated):
1. Visual check (unplugged): look for bulging capacitor tops, burn marks, melted plastic or a strong burnt smell. A bulging or
burnt PSU means replace it, full stop.
2. Smell test: a sharp burning smell around the PSU = failed, replace it.
3. Connection check (unplugged): make sure the big 24-pin motherboard cable and the CPU power cable are fully seated. A
loose connector causes no-power symptoms.
4. Socket check: confirm the wall socket actually has power — test it with another appliance or a known-good lamp. This
sounds obvious, but it is the most common "no power" cause.
5. Swap test (the safest and most reliable): replace the suspect PSU with a known-good PSU of suitable wattage. If the
computer then works, the original PSU was the fault.
The paperclip test — advanced and optional. There is a way to force a PSU on by bridging two pins on its main connector
with a bent paperclip, to see if the fan spins. This test:
Should only ever be done by the instructor, on a bench, as a demonstration; it is not a learner task.
Requires care because you are working with a live PSU once it starts.
Proves only that the PSU powers up; it does not prove the voltages are within spec.
Because of the danger and its limited usefulness, this course uses the swap test as the standard method. If the academy has a
PSU tester (a small device that plugs onto the main connector and shows the voltage readings), the instructor may
demonstrate it — it is safer and more informative than the paperclip method.
Important misconception. "A bigger wattage PSU always fixes random shutdowns." Wattage is a capacity, not a health
measure. A failing 700 W PSU is still failing. Also, choosing the correct wattage matters (Session 7 covers this).
Limitation. A PSU can fail in subtle ways that basic checks miss — delivering slightly wrong voltages that cause random faults.
When symptoms strongly suggest PSU and the swap test confirms it, replace it; do not try to "tune" it.
F.6 Diagnosing overheating
The idea. Every chip produces heat when it works. If that heat cannot escape, performance drops and, eventually, parts are
damaged.
Plain-English definition. Overheating means a component is running hotter than it should. The usual cause is dust, a failed
fan, dried-out thermal paste, or blocked airflow.
Why it matters. Modern CPUs and GPUs can slow themselves down on purpose when hot (called thermal throttling) — that
is why a dusty computer feels slow. If it gets hotter still, the computer shuts itself off to protect the part (a thermal shutdown).
Analogy. Imagine wearing a thick coat (northern-style) in the Port Harcourt heat while doing hard labour. You cannot work well,
and if you keep going you collapse. The computer "collapses" by shutting down.
Tool: HWMonitor. This free tool displays temperatures, fan speeds and voltages for the sensors it can find on the machine.
Normal ranges (rough guide):
CPU: around 30–50 °C when idle; up to about 80 °C under heavy load.
GPU: around 30–60 °C idle; up to about 85 °C under load.
Hard drive: roughly 25–45 °C.
Motherboard: roughly 30–50 °C.
These are guides, not exact rules; different models differ. What matters is: a reading well above the guide, or a big gap
between "before" and "after" cleaning, tells you overheating is happening. If a value keeps climbing toward 90 °C or
above, treat it as a fault.
Common symptoms of overheating:
Random shutdowns after some minutes of use.
Fans running loudly all the time.
The case or the base of a laptop feeling very hot.
Slowness that gets worse the longer the computer runs.
Basic checks (with the computer off and unplugged):
1. Dust: open the case and look at heatsinks and fan blades. Thick dust "felt" between the fins blocks airflow (the "dust
blanket").
2. Fans: check that every fan spins freely when the machine is running and is not grinding. A stopped CPU fan is serious —
the computer may run for a minute then shut down.
3. Thermal paste: the grey paste between the CPU and its heatsink can dry out over years and lose its ability to transfer heat.
Re-applying it (Session 8) restores cooling.
4. Airflow: confirm intake and exhaust vents are not blocked by a wall, a curtain, or a laptop sitting on a soft bed.
Important misconception. "If the fan is loud, the fan is broken." Often the fan is loud because it is working hard to fight
overheating — the cause is dust, not the fan. Clean first, then judge the fan.
Limitation. Not every machine exposes every temperature sensor, and some older machines report only a few values. Absence
of a reading is not proof that temperature is fine. Where sensors are missing, rely on symptoms (shutdowns, hot case) and
physical inspection.
F.7 Diagnosing display (no signal) faults
The idea. "No signal" or a black screen does not mean the computer is dead. It means the picture is not reaching the screen.
There are several possible breaks between the computer and your eyes.
Plain-English definition. A display fault is anything that stops a correct picture appearing: the cable, the port, the GPU, the
monitor, or the computer not finishing POST.
Analogy. Think of a DSTV or GOtv setup. If the TV shows "no signal", you do not immediately buy a new TV. You check the
cable, the decoder, the dish. The same order of thinking applies to a computer screen.
Order of checks (cheapest and simplest first):
1. Is the monitor on, and on the right input? Many monitors have several inputs (HDMI1, HDMI2, VGA). The input may have
been switched by mistake. Check the monitor's menu.
2. Cable: unplug and firmly reseat the display cable at both ends. Try a known-good spare cable. A damaged or loose cable is
a very common "no signal" cause.
3. Try a different port: if the computer has both a motherboard video output and a GPU output, try the other. On a desktop
with a dedicated GPU fitted, the monitor should be connected to the GPU, not the motherboard — connecting to the
wrong one can give no signal.
4. Does the computer finish POST? If the fans spin but there is no picture and there is a beep pattern, the fault may be RAM
or GPU, not the screen. Test RAM as in F.3.
5. Swap the monitor: try a known-good monitor. If the picture appears, the original monitor was faulty.
6. Swap the GPU: on a desktop, fit a known-good GPU (or use the motherboard output) to test. If the picture appears, the
original GPU was faulty.
Common symptoms and what they suggest:
"No signal" but the PC fans spin and lights come on → cable, monitor, GPU or POST failure.
Picture appears only after wiggling the cable → damaged cable or port.
Screen shows strange colours or lines → often the monitor or cable (sometimes the GPU).
Laptop screen dark but an external monitor works → the laptop's screen or its ribbon cable, not the GPU.
Important misconception. "Black screen = dead computer." Very often the computer is running fine and only the display path
is broken. Also, on a laptop, a very dim screen may just be backlight or brightness — shine a torch at an angle to see if a faint
image exists; that points to backlight rather than a dead machine.
Limitation. Diagnosing laptop screens in detail (screen replacement, ribbon cables) is beyond this session; here we focus on
isolating whether it is the screen and passing that finding on.
F.8 Motherboard and laptop battery issues
The idea. The motherboard is the main circuit board everything plugs into. The laptop battery stores power so the laptop can
run without the charger.
Motherboard — plain-English definition and symptoms. The motherboard is the large board that carries the CPU socket,
RAM slots, expansion slots and connectors. Motherboard faults are usually the hardest to diagnose because the board controls
so much.
Symptoms: no POST at all, no beeps, no display, no power lights; sometimes power comes on for one second and dies;
sometimes some ports dead while others work.
Common causes: a failed capacitor, physical damage, a power surge, or liquid spillage.
Beginner rule: because the motherboard interacts with everything else, you must first rule out the other parts (RAM, PSU,
GPU, display) using swap tests. Only when every other part is known-good do you conclude "the motherboard is faulty".
Motherboard-level repair (soldering, chip replacement) is advanced work and outside the scope of this certificate — the
honest action is to replace the board or advise the customer.
Laptop battery — plain-English definition and symptoms. The battery is the rechargeable pack that powers a laptop when it
is not plugged in. A worn battery is not a "fault" in the same way, but it causes problems:
Symptoms: laptop only works when plugged in; battery percentage jumps; the laptop shuts down suddenly; the battery
swells (bulges) and may push the trackpad out.
Safety warning: a swollen battery is a fire risk. Stop using the laptop immediately, do not press on it, do not puncture it,
and advise the customer to have it replaced by a technician. Do not attempt to force a swollen battery out of a laptop
without proper care and supervision.
Diagnostic note: a "not charging" laptop might be the battery, the charger cable, or the charging port. Try a known-good
charger first (cheapest test), then consider the battery, then the port.
Important misconception. "A swollen battery just looks a bit fat, it is still fine." It is not fine. Swelling means the cells are failing
and can catch fire. Treat it as a priority safety issue.
Limitation. Battery health detail (cycle count, capacity percentage) can be read with some built-in laptop tools, but tool names
and menus differ by make. In this course we rely on the clear physical signs (only works on charger, swollen pack) rather than
model-specific tools.
F.9 Swap testing and isolation — the professional method
The idea. The fastest, safest way to prove which part is faulty is to change one thing at a time.
Plain-English definition. Swap testing means replacing a suspect part with a known-good part to see if the fault disappears.
Isolation means removing or disconnecting parts to narrow down where the fault is.
Why it exists. Guessing wastes money. If a customer is told "buy a new GPU" and the real fault was a ₦500 cable, you lose the
customer's trust. Swap testing turns a guess into a confirmed diagnosis.
Rules of swap testing:
1. Change only one thing at a time. If you change two parts and it works, you do not know which one fixed it.
2. Use a known-good part — one you are sure works. If your "test" part is also faulty, you will reach a wrong conclusion.
3. Power off and unplug before swapping internal parts, and wear your anti-static wrist strap.
4. Record each step on the Diagnostic Report Form: what you changed, and what happened.
5. Return the machine to its original state if the swap does not fix it, before trying the next test.
Analogy. A doctor testing for malaria does not treat for five diseases at once. She tests one thing, reads the result, then decides
the next test. Swap testing is the same discipline.
Important misconception. "I do not need to use a known-good part; any spare will do." No. Your conclusion is only as good as
your test part. Always use a part you trust.
Limitation. Some parts are hard to swap quickly (a soldered laptop battery, an integrated screen). For those, isolation
(disconnecting, checking connectors, using external equivalents) replaces swapping.
F.10 Summary of the session
Every fault is hardware or software; today we prove hardware faults.
POST runs first; beep codes (count, then look up) point to basic failures.
Faulty RAM → boot loops, beeps, blue screens, crashes. Test with Windows Memory Diagnostic or MemTest86; isolate
one stick at a time.
Failing storage → slowness, clicks, not detected. Read S.M.A.R.T. in CrystalDiskInfo (Good / Caution / Bad). Back up on
"Caution".
PSU faults → no power, random shutdowns, burning smell. Never open a PSU. Use the swap test.
Overheating → shutdowns, loud fans, slowness. Check dust, fans, paste, airflow and temperatures in HWMonitor.
Display faults → check monitor, cable, port, GPU, POST, in that order.
Motherboard / laptop battery — rule out everything else first; swollen batteries are a fire risk.
Swap testing + isolation turns guesses into confirmed diagnoses.

## G. INSTRUCTOR DEMONSTRATION (15 minutes)
<!-- kind:demo -->
G.1 What the instructor prepares
One practice desktop, opened on the bench, with an anti-static wrist strap.
One known-good RAM stick and one stick designated "suspect" (the class is not told which).
CrystalDiskInfo and HWMonitor installed and openable.
One attempt at Windows Memory Diagnostic queued (or MemTest86 USB ready).
A known-good monitor and a spare display cable.
The Diagnostic Report Form on the projector.
G.2 Demonstration 1 — Reading drive health with CrystalDiskInfo (4 minutes)
Say: "Watch me ask this drive a question and read its answer."
Steps:
1. Open CrystalDiskInfo. Point to the top line: the Health Status word and colour.
2. Read the Temperature. Say: "38 °C — that is cool and normal."
3. Scroll to Reallocated Sectors Count. Say: "It is zero. That is what we want — zero means the drive has not yet set aside any
bad spots."
4. Now open CrystalDiskInfo on the training drive that shows wear. Point at Caution (yellow) and the non-zero reallocated
count.
5. Say: "Caution means this drive is telling us it is getting sick. Our action is simple and urgent: back up the data today, and
tell the customer to plan for a replacement."
Expected results: "Good" (blue) on the healthy drive, "Caution" (yellow) with a non-zero reallocated sector count on the
training drive.
Reasoning to say aloud: "I am not guessing. The drive measured itself and I am reading the measurement. That is the whole
philosophy of diagnostics."
Common errors to show and correct:
Reading only the word and ignoring the attribute list. Show that Caution can appear even if the summary word is slow to
update.
Confusing a warm drive with a failing drive — temperature and health are different columns.
Questions to ask during the demo:
"If the status is Caution, what do we do first — back up or replace?" (Back up first, so we do not lose data.)
"Is a drive with zero reallocated sectors guaranteed to live forever?" (No — that is why we back up.)
G.3 Demonstration 2 — Temperature check with HWMonitor (3 minutes)
Say: "Now the health of the cooling system."
Steps:
1. Open HWMonitor. Point to the CPU temperature and the fan speed rows.
2. Say: "CPU at 45 °C idle — normal for these machines."
3. Point to fan speeds. Say: "These are the CPU and case fan speeds. If a fan shows zero while the machine is on, that fan is not
spinning — investigate."
4. Optional: gently run a heavy task (or just say what would happen) to show the CPU number rising under load.
Expected results: a CPU reading within the normal idle guide, and fan speeds above zero.
Questions to ask: "If the CPU sits at 85 °C while doing nothing, what are the first two things to check?" (Dust and fan rotation.)
G.4 Demonstration 3 — RAM test and swap isolation (5 minutes)
Say: "The hardest fault to catch is the one that only happens sometimes. Memory is famous for this."
Steps:
1. Show the RAM slots. Point out the clips at each end.
2. Put in one suspect stick. Say: "Let us say the customer complains of random restarts."
3. Start Windows Memory Diagnostic (or insert the MemTest86 USB and begin booting it). Explain that it runs outside
Windows so it can test all of memory.
4. While it runs (or while describing the result), reveal the known-faulty stick result.
5. Perform the isolation: power off, unplug, strap on, remove the suspect stick, fit the known-good stick, power on.
6. Say: "The fault is gone. We have not guessed — we have proven the original stick was bad by swapping in a known-good
one."
Expected results: the memory test reports errors on the faulty stick; the machine behaves normally with the known-good stick.
Reasoning to say aloud: "One change at a time. Known-good part. Record every step. That is how we avoid blaming the wrong
component."
Common errors to show and correct:
Forcing the stick in the wrong way (show the notch alignment).
Forgetting to unplug and to wear the wrist strap.
Concluding "RAM is bad" from a single blue screen without any test.
Questions to ask:
"Why do we run the test outside Windows?" (So Windows is not using the memory we are testing.)
"If there were two sticks and only one were bad, how would we find it?" (Test/isolation one at a time.)
G.5 Demonstration 4 — No-signal display isolation (3 minutes)
Say: "Black screen — do not panic, and do not buy a monitor yet."
Steps:
1. With the machine running and the monitor showing "No Signal", first check the monitor's input menu.
2. Reseat the display cable at both ends. Still no signal.
3. Swap in the known-good spare cable. Picture appears.
4. Say: "We found it: a bad cable. Cost to the customer: the price of a cable, not a monitor or a GPU. This is why we test from
cheapest to most expensive."
Expected results: picture returns after the cable swap.
Questions to ask: "Why do we try the cheap cable before swapping the expensive GPU?" (Cost, and the cheapest cause is very
often the real one.)

## H. GUIDED PRACTICAL EXERCISE (18 minutes)
<!-- kind:guided_practical -->
Objective: With the instructor guiding, each learner (or pair) runs the hardware diagnostic tools on a practice machine and
records findings on a Diagnostic Report Form.
Safety first — read aloud before starting:
Switch off and unplug the computer before opening the case or touching any internal part.
Wear your anti-static wrist strap whenever you handle internal components.
Never open the PSU.
Keep drinks away from the bench.
Handle RAM and drives by the edges; do not touch the gold contacts.
If anything smells burnt or you see a swollen battery, stop and call the instructor.
Procedure (instructor calls out each step; learners follow; instructor walks the room):
1. On the running machine, open CrystalDiskInfo. Record: Health Status word and colour; drive temperature; and the
Reallocated Sectors Count value.
2. Open HWMonitor. Record the CPU temperature, the GPU temperature (if listed) and the fan speeds. Note any fan
showing zero.
3. Pause and predict: "Before we start a memory test, what would you expect to see if this stick is healthy?" (Zero errors,
machine passes.) Write your prediction before running.
4. Start Windows Memory Diagnostic (or insert the MemTest86 USB and begin the boot). If time is short, observe the first pass
and note the running errors count. Do not force the machine to keep testing if it is needed for the next group —
coordinate with the instructor.
5. Display isolation drill: with the machine running, deliberately loosen the display cable at one end (or start from a "no
signal" setup) and follow the order: check input → reseat cable → known-good cable → known-good monitor. Record
which step fixed it.
6. Swap-test drill (instructor supplies parts): power off, unplug, strap on. Remove the suspect RAM stick and fit the known-
good stick. Note the difference in behaviour (or in the memory-test result).
7. Overheating inspection: with the machine off and unplugged, open the case and inspect the CPU heatsink, fans and vents
for dust. Record what you see (light dust / heavy dust / clear).
8. Complete the Diagnostic Report Form, writing each finding in plain language a customer could understand.
Expected results:
CrystalDiskInfo shows the drive health word and a temperature.
HWMonitor shows at least one CPU temperature and fan speeds.
The memory test reports a pass (or, on the faulty stick, an error count).
The display isolation drill identifies the specific fault (input/cable/monitor/GPU).
The swap test changes the machine's behaviour in the expected direction.
A completed report form.
Points to pause on and predict:
After step 1: "If the status is Caution but the count is zero, what could still be wrong?" (Temperature, or a different flagged
attribute.)
After step 5: "We changed two things — which one fixed it?" (Correct answer: we must change one at a time to know.)
After step 6: "If the machine still fails with the known-good stick, what does that tell us?" (The RAM was probably not the
fault — look elsewhere.)
Troubleshooting while walking the room:
CrystalDiskInfo shows no drives → the tool may need to be run as administrator; also confirm the drive cable is connected.
HWMonitor shows very few values → this machine has few sensors; record what is shown and say so.
Windows Memory Diagnostic will not restart → save work and make sure no other user is logged in.
MemTest86 USB does not boot → confirm the boot key and that "USB boot" is enabled; try another USB port.
Learner forces RAM → stop immediately, show the notch, re-seat gently.
Completion checklist (learner ticks each):
CrystalDiskInfo opened; health status, temperature and reallocated count recorded
HWMonitor opened; temperatures and fan speeds recorded
A memory test started and its result noted
Display isolation drill completed and the cause identified
Swap test completed (one change at a time, known-good part)
Overheating inspection done (dust, fans, vents noted)
Diagnostic Report Form completed in plain language
All safety steps followed (power off, unplugged, strap worn, PSU never opened)

## I. INDEPENDENT CLASS EXERCISE (15 minutes)
<!-- kind:exercise -->
Task: Diagnose three simulated hardware faults without copying the instructor. For each one, use the correct tool, decide
whether the component is healthy or faulty, and write your conclusion in plain language.
Scenario cards (each learner or pair receives these; the instructor can set up each as a bench station).
Card A — "The Beeping Cyber Café PC". A desktop will not display a picture. When switched on, it beeps three times, then
pauses, then beeps three more times. All fans spin. The drive and PSU are known-good. There are two RAM sticks fitted.
Card B — "The Slow Office Computer". A desktop started fine but now boots to Windows very slowly and sometimes says
"operating system not found". CrystalDiskInfo is available. The machine's drive makes a soft ticking sound occasionally.
Card C — "The Machine That Dies". A desktop runs for about 20 minutes, then suddenly switches off with no warning. It
restarts when you press the power button, then dies again after some minutes. Fans spin during use. CrystalDiskInfo and
HWMonitor are available.
Requirements:
1. For each card, state the most likely faulty component.
2. State which tool or test you used (or would use) to confirm it.
3. State the next safe action for a technician (e.g., back up, clean, replace).
4. Write each answer as a short paragraph in plain English.
Time allowance: 15 minutes.
Constraints:
Do not open the PSU.
Use a known-good part for any swap test.
Record the finding on the Diagnostic Report Form.
Success criteria:
Each card is matched to the correct component.
The confirmation test chosen makes sense.
The recommended action is safe and honest.
Hints available if stuck:
Hint 1 (Card A): repeated beeps before any picture usually point to one basic component that the machine needs before it
can show anything.
Hint 2 (Card B): ticking plus "operating system not found" points to a mechanical component that stores data.
Hint 3 (Card C): a machine that dies after a set time, then dies again, is the classic sign of a heat or power problem.
INSTRUCTOR ANSWER KEY — Independent Class Exercise (do not show learners)
Card A — Most likely faulty component: RAM. Three repeating beeps during POST usually indicate a memory fault; all fans
spinning means the PSU is probably fine and the machine is trying to start.
Confirmation test: MemTest86 (or Windows Memory Diagnostic), and isolation by removing one stick at a time, testing
each alone.
Next safe action: identify the bad stick, replace it with a matching known-good stick, re-test. Do not buy a new
motherboard first.
Card B — Most likely faulty component: the storage drive (HDD) is failing. Slow boot, "operating system not found" and
ticking all point to a dying mechanical drive.
Confirmation test: CrystalDiskInfo — look for Caution and a non-zero reallocated sector count; note the ticking
(mechanical failure).
Next safe action: back up the customer's data immediately if the drive still reads; then replace the drive (an SSD upgrade is
ideal — see Session 7) and reinstall/the-clone the system. Warn the customer that a ticking drive may fail fully at any
moment.
Card C — Most likely faulty components: overheating (dust/dried paste) or a weakening PSU. Dying after a fixed time is
the signature of heat buildup; random shutdowns can also be a PSU problem.
Confirmation test: HWMonitor for temperatures under load; inspect dust, fan rotation and thermal paste; then a PSU
swap test with a known-good PSU.
Next safe action: clean the dust and check fans/paste first (free and safe); if it still dies, perform the PSU swap test and
replace the PSU if confirmed. Never open the PSU.
Marking guidance (out of 12):
Correct component identified for each card (3 × 2 = 6)
Sensible confirmation test chosen for each (3 × 1 = 3)
Safe, honest next action for each (3 × 1 = 3)
Plain-language writing and completed report form (bonus up to +1, cap at 12)
Accept any answer that shows correct testing logic, even if the wording differs. Penalise unsafe actions (such as opening the
PSU or "replace everything") heavily.

## J. Real-World Case Study
<!-- kind:case_study -->
Situation. Emeka owns a small business centre along Ikwerre Road, Port Harcourt. His main office computer holds his customer
invoices, his accounting records and the software he uses for printing. For two weeks it has been slow and sometimes restarts
on its own. He ignores it — "it is still working." One Friday evening, the machine refuses to boot: "Boot device not found." He
calls a technician.
Relevant facts.
The computer is seven years old and still has its original mechanical hard drive.
It had begun to make a soft ticking noise some weeks earlier.
Nobody had ever run a health check on the drive.
No backup exists.
The decision point. The technician opens CrystalDiskInfo. The drive shows Bad (red), with a high reallocated sector count and
repeated read errors. The shop's invoice and accounting data were only on this one drive.
Possible approaches.
1. Keep trying to boot the drive repeatedly to copy files.
2. Power the failing drive down, back up what can still be read with care, then replace the drive.
3. Send the drive for data recovery immediately.
Recommended solution (for this stage). Approach 2, with honest limits. The technician explains that a drive in this state may
copy some files but is at high risk of dying completely at any moment, and each attempt shortens its life. He backs up the most
critical data first (invoices and accounts), then attempts the rest. He advises Emeka that if any important data cannot be copied,
only a professional data recovery service should open the drive — not the shop technician.
Trade-offs.
Approach 1 risks destroying the remaining data faster; repeatedly powering a dying drive is dangerous.
Approach 2 preserves the best chance of saving data and is affordable; but some files may already be lost.
Approach 3 is expensive and unnecessary if the important files are still readable — it should be the last resort.
Professional connection. Real repair shops earn trust by doing exactly this: reading S.M.A.R.T. health, being honest that a failing
drive must be replaced, and telling the customer to back up. The course certificate says a graduate can "diagnose common
hardware faults" — this is precisely that skill, plus the professional honesty that goes with it.
Transfer exercise (ask the class): "If a customer's drive shows Caution, and the customer says 'I will bring it back next month,'
what should the technician do or say?"
Suggested answer: explain clearly, in writing, that Caution means the drive is already showing wear, that it can fail before next
month, and that the data should be backed up now. Record the advice on the service sheet so the customer cannot later say
they were not warned.

## K. Common Mistakes and Troubleshooting
<!-- kind:troubleshooting -->
Use this table as the session's live troubleshooting guide. When a learner hits a problem, ask them to check the relevant row
first.
K.1 Black screen / "No Signal" but the machine seems to run
Symptoms: fans spin, keyboard lights come on, monitor shows "No Signal".
Likely causes: monitor on the wrong input; loose or damaged display cable; monitor connected to the motherboard
instead of the GPU; a POST fault (RAM/GPU); or a dead monitor.
How to investigate: check the monitor input menu; reseat the cable at both ends; try a known-good cable; try the other
video output; check for beeps; try a known-good monitor.
Safe corrective steps: work from cheapest to most expensive — input, cable, port, then monitor/GPU. Power off before
changing cables.
How to confirm resolved: a picture appears and stays stable.
Prevention: keep a spare known-good cable and monitor on the bench.
K.2 The computer does not power on at all
Symptoms: no lights, no fans, nothing.
Likely causes: wall socket dead; power cable loose or faulty; PSU switch (on the back) off; PSU failed.
How to investigate: test the socket with another appliance; check the power cable and the PSU switch; then try the swap
test with a known-good PSU.
Safe corrective steps: replace the power cable, use a working socket, swap the PSU. Never open the PSU.
How to confirm resolved: the machine powers on and completes POST.
Prevention: use a surge protector (Session 8); label good cables.
K.3 Random shutdowns and restarts
Symptoms: works, then dies; sometimes restarts by itself.
Likely causes: overheating (dust, dead fan, dried paste); weak PSU; loose power connectors; faulty RAM.
How to investigate: check temperatures in HWMonitor; inspect dust and fans; reseat the 24-pin and CPU power
connectors; run a memory test; do a PSU swap test.
Safe corrective steps: clean cooling first (free); re-seat connectors; swap PSU. Power off and unplug for all internal checks.
How to confirm resolved: the machine runs a heavy task (or a long memory test) without dying.
Prevention: regular cleaning (Session 8), surge protection, correct PSU wattage.
K.4 Memory test shows errors
Symptoms: MemTest86 or Windows Memory Diagnostic reports errors above zero.
Likely causes: a faulty RAM stick; a dirty or faulty RAM slot; RAM not fully seated; incompatible/mismatched RAM.
How to investigate: reseat the stick; clean the slot with compressed air; test one stick at a time; test each stick in each slot.
Safe corrective steps: remove the faulty stick; if the slot itself is bad, use a different slot; replace the faulty stick.
How to confirm resolved: re-run the test and get zero errors.
Prevention: hold by the edges, never force a stick, power off first.
K.5 CrystalDiskInfo shows Caution or Bad
Symptoms: yellow or red health status; non-zero reallocated sectors; read errors.
Likely causes: the drive is wearing out or already failing.
How to investigate: read the full attribute list; listen for clicks; note the temperature.
Safe corrective steps: back up the customer's data immediately; stop writing new data; replace the drive. For clicks or
unreadable important data, hand over to a data recovery specialist.
How to confirm resolved: the new drive shows Good and the system runs normally.
Prevention: regular health checks (Session 8) and a backup habit.
K.6 Distinguishing likely from confirmed
In every row above, a likely cause becomes a confirmed cause only after a test proves it: a swap test that changes the behaviour,
a S.M.A.R.T. reading, a temperature reading, or a memory-test error count. Teach learners never to write "confirmed" on a
report based on a guess. Saying "likely cause" honestly is professional; overclaiming is not.

## L. Session Assignment

Assignment title: "Hardware Diagnostic Report on a Real Machine"
Purpose: To practise the full hardware diagnostic process — inspecting, testing with tools, isolating with swap tests, and
writing findings in plain language — on a real computer.
Realistic scenario: A customer brings you a desktop computer and says: "It is slow, sometimes it restarts on its own, and last
week the screen went black once." You must produce a professional diagnostic report before any repair is done.
Detailed instructions:
1. Choose a real computer you have access to (a practice machine at CEA, a family computer, or a machine at your work). Get
permission before opening any machine that is not yours.
2. Observe and record: note the make/model if visible, the symptoms, and anything the "customer" told you.
3. Run the software checks (safe, no case opening needed): CrystalDiskInfo (health, temperature, reallocated sectors) and
HWMonitor (CPU/GPU temperatures, fan speeds).
4. Run a memory test (Windows Memory Diagnostic or MemTest86) and record the result.
5. Physical inspection (only if you may open the machine): with it off and unplugged, note dust levels, fan condition, and
whether the case has good airflow. Do not open the PSU.
6. Write your conclusion: state the most likely faulty component (or that all tested parts look healthy), and your
recommended next action.
7. Complete the Diagnostic Report Form and hand it in.
Required deliverables:
One completed Diagnostic Report Form (the CEA template), including all readings.
A one-paragraph plain-language summary for the "customer".
Submission format: Written report on the CEA template, submitted to the instructor (paper or the class folder).
Deadline: Before Session 6.
Marking rubric (20 marks):
Criterion Marks Description of a strong answer
Observation & symptom record 3 Clear, specific symptoms and customer description
CrystalDiskInfo findings 3 Health status, temperature and reallocated count all recorded
HWMonitor findings 3 CPU (and GPU if available) temperatures and fan speeds recorded
Memory test result 3 Test named, run, and result clearly stated
Physical inspection (if permitted) 2 Dust, fans and airflow noted honestly
Conclusion & recommendation 4 Logical, safe, honest conclusion with a sensible next action
Plain-language summary 2 A customer could understand it; no unexplained jargon
Common mistakes to avoid: writing "confirmed" without a test; confusing temperature with health; recommending "replace
everything"; opening the PSU; forgetting to record the actual numbers.
Instructor reference solution (abbreviated example):
Machine: CEA practice desktop (7th-gen CPU, 4 GB RAM, 500 GB HDD). Symptoms: slow boot; one random restart last
week; one black screen. CrystalDiskInfo: Health Caution (yellow); temperature 41 °C; Reallocated Sectors Count 18
(and rising). HWMonitor: CPU 52 °C idle; CPU fan 1,250 RPM; one case fan reads 0 RPM. Memory test: Windows
Memory Diagnostic — 0 errors (passes). Physical inspection: heavy dust between CPU heatsink fins; one case fan not
turning. Conclusion — likely cause: the hard drive is wearing out (Caution, non-zero reallocated sectors) and the
cooling is compromised (dust + one dead case fan). Recommendation: back up the customer's data today; replace the
hard drive (an SSD will also make it much faster); clean the dust and replace/repair the stopped case fan; re-test
temperatures after cleaning. Plain-language summary: "Your computer's storage is showing early signs of failure, and
dust is making it run hot. Please let us back up your files now, then we will replace the storage and clean the cooling."

## M. Knowledge Check
<!-- kind:knowledge_check -->
(Learner version — answers only in the Instructor Key below.)
Q1. Short answer. What does POST stand for, and why does it use beeps instead of the screen? Q2. Multiple choice. A drive in
CrystalDiskInfo shows Caution (yellow) with a non-zero reallocated sector count. What is the correct first action? a) Replace the
drive immediately without copying anything. b) Back up the customer's data immediately. c) Ignore it — Caution is normal. d)
Open the drive to look inside. Q3. True or false, with a reason. "A PSU can be safely opened to check the capacitors as long as
it is unplugged." Q4. Practical identification. A desktop has two RAM sticks, shows random restarts and produces repeated
beeps at start-up. Describe, step by step, how you would find the faulty stick. Q5. Scenario. A laptop shuts down after about 30
minutes every time. Give two likely causes and the test you would use for each. Q6. Explain in your own words. Why do we
change only one thing at a time during swap testing?
INSTRUCTOR ANSWER KEY (Q1–Q6)
A1. POST = Power-On Self-Test. It uses beeps because it runs before the graphics/display is set up, so it cannot show a
message on screen. If a basic part fails, a beep pattern (or a debug light) tells the technician where to look. (The beep pattern
depends on the motherboard maker, so we count and look it up.)
A2. (b) Back up the customer's data immediately. Caution means the drive is already showing wear and could fail soon. Data
first, then replace the drive.
A3. False. Even unplugged, the large capacitors inside a PSU can hold a lethal charge for a long time. A PSU is replace-only for
a general technician.
A4. Step-by-step: power off and unplug; wear the anti-static strap. Remove one stick, leaving only stick A; run MemTest86 (or
Windows Memory Diagnostic); note errors. If errors appear, stick A is bad. If not, power off and test stick B alone. Alternatively,
swap in a known-good stick; if the faults disappear, the original stick was bad. Test one stick (one change) at a time and record
each result. (Accept any answer that follows isolation + known-good swapping.)
A5. Likely causes: overheating (dust, failed fan, dried thermal paste) and a weakening PSU. Test for overheating with
HWMonitor while the machine runs (watch the temperature climb before shutdown) and by inspecting dust/fans/paste. Test
for the PSU with a swap test using a known-good PSU of suitable wattage. (Also accept "faulty RAM" if supported by a memory
test.) Never open the PSU.
A6. Because if you change two things at once and the fault disappears, you cannot tell which change fixed it. One change at a
time gives a confirmed answer, saves money, and produces an honest report.
Marking: award for correct concept even if wording differs. Deduct for unsafe answers (opening the PSU, "replace everything").

## N. Reflection and Recap
<!-- kind:reflection -->
Plain-English summary. Today you learned to prove hardware faults instead of guessing them. You saw how a computer checks
itself at start-up (POST) and tells you via beeps when a basic part fails. You learned the symptoms and tests for faulty RAM
(boot loops, blue screens — tested with Windows Memory Diagnostic or MemTest86), failing storage (slowness, clicks, "not
found" — read with CrystalDiskInfo using S.M.A.R.T.), PSU faults (no power, random shutdowns — swap test only, never
open it), overheating (shutdowns, loud fans — HWMonitor, dust, fans, paste), display faults (no signal — check input, cable,
port, monitor), and motherboard / laptop battery issues (rule out everything else; swollen batteries are a fire risk). Above all,
you learned swap testing and isolation: change one thing at a time, use a known-good part, and record every step.
Five important takeaways:
1. Test, do not guess — a diagnosis you cannot prove is not finished.
2. Never open the PSU; capacitors can hold a lethal charge.
3. Caution in CrystalDiskInfo means back up now, then replace.
4. Change one thing at a time with a known-good part.
5. Always back up before replacing storage, and always record your findings.
Questions to help you recognise what you can now do:
Can I read a drive's health and decide the next action?
Can I find a faulty RAM stick using isolation?
Can I explain why we never open a PSU?
Can I check temperatures and spot overheating?
Can I find a "no signal" fault from cheapest to most expensive cause?
Safety self-check (tick honestly):
I powered off and unplugged before opening any machine.
I wore my anti-static wrist strap when handling parts.
I never opened a PSU.
I backed up before touching storage data.
I stopped and called the instructor when unsure.

## O. INSTRUCTOR EVALUATION NOTES (instructor-only)
<!-- kind:instructor_notes -->
Observable signs of genuine competence:
The learner checks cheapest/simplest causes first (socket, cable, monitor input) before opening the case.
The learner reads the actual number in CrystalDiskInfo (reallocated count, temperature) rather than only the colour.
The learner uses a known-good part for a swap test and changes one thing at a time.
The learner states findings in plain language and distinguishes "likely" from "confirmed".
The learner automatically powers off, unplugs, and wears the wrist strap.
The learner refuses unsafe actions (opening the PSU, poking a swollen battery).
Common misconceptions to watch for and correct:
"Black screen means the computer is dead." → Often just the display path or POST.
"Caution is fine." → Caution means back up now.
"A loud fan is a broken fan." → Usually it is fighting overheating; fix the dust/heat first.
"A bigger PSU fixes shutdowns." → Wattage is capacity, not health.
"I can open the PSU if it is unplugged." → Never. Lethal stored charge.
Suggested remedial exercises for learners who struggle:
1. Tool-drill: with a working machine, repeatedly open CrystalDiskInfo and HWMonitor and read aloud the health,
temperature and fan values until fluent.
2. Swap-test tracing: give a written scenario where two parts were changed at once and ask "what can we conclude?"
(Answer: nothing certain — repeat one at a time.)
3. Symptom sorting: hand out ten symptom cards and ask learners to sort them into "RAM / storage / PSU / heat / display"
buckets.
Differentiation:
Level 1 (supported): provide a step-by-step tool card and a partially completed report form; pair the learner with a stronger
partner for the swap test.
Level 2 (standard): the exercise as written.
Level 3 (challenge): introduce a mixed fault (e.g., a failing drive and overheating at once) and ask the learner to diagnose
both and prioritise which to fix first, justifying the order.
Timing guidance: This is a practical-heavy session. If the room is slow, protect the guided practical (Section H) and trim the
case study to a two-minute mention. Memory tests can be time-consuming — start the test early, let it run while other checks
happen, and do not let one test consume the whole session. If a real memory test cannot finish in class, record the running
result and note honestly that a full pass is required.
