# Google Docs and Google Sheets

## A. Session Identification
<!-- kind:identification -->
**Week / module:** Week 1 — Module: Cloud Storage and Email

**Recommended duration:** 105 minutes

**Difficulty:** Beginner (builds on Sessions 1–2)

**Prerequisite knowledge:** Sessions 1 and 2. Learners must be able to log in, navigate Google Drive, create folders, share with Viewer/Commenter/Editor, and find files by search. Basic typing is assumed.

**Connection to previous work:** In Session 1 you built a safe, organised home for your files. In Session 2 you organised your email and learned to share with least privilege. Now you create the content that lives in that home: written documents in Google Docs and spreadsheets in Google Sheets — and you learn to collaborate on them live, using the sharing rules you already know.

**Preparation before class:** Academy PCs on and logged in to a Google account; Chrome open; a learner Doc and a learner Sheet created beforehand in the Drive structure from Session 1 (or created live); the sample business-letter text and the sample expense data ready to paste (Section C); document and spreadsheet templates prepared; the Docs and Sheets cheat sheets printed; projector connected; internet working.

## B. Learning Outcomes
<!-- kind:outcomes -->
By the end of this session, the learner will be able to:
1. Create a document in Google Docs and give it a clear title, and explain that Docs auto-saves to Drive.
2. Format a document using the toolbar — font, size, bold/italic/underline, alignment, lists — and apply heading styles
(Heading 1, 2, 3) to create structure.
3. Insert a table, an image and a hyperlink, and explain when each is useful.
4. Set up page settings and export/download a document as a PDF and as a .docx Word file.
5. Share a document with the correct role (Viewer, Commenter, Editor), and use commenting and suggesting mode for
collaboration.
6. Use version history to view and restore an earlier version of a document, and explain what auto-save means for safety.
7. Create a spreadsheet in Google Sheets and identify cells, rows, columns and ranges using cell references like B2 .
8. Enter and format data, including formatting numbers as Naira (₦) currency.
9. Write basic formulas — SUM , AVERAGE , MIN , MAX , COUNT — and explain what each does.
10. Create a simple chart, freeze a header row, and sort and filter data.
11. Explain the difference between Docs and Sheets and choose the right tool for a task.

## D. OPENING ACTIVITY (6 minutes)
<!-- kind:opening -->
Instructor setup: Have a real (or realistic) Word document open on the projector, and a second window ready with a Google
Doc. Do not reveal the trick yet.
What the instructor says:
"Let me tell you about Funmi. Funmi is a student here in Port Harcourt. She has a big assignment due at 8am. She types it
all night in Microsoft Word on her laptop. At 2am the power goes off — the laptop battery is old and dies instantly. She
had not saved since 9pm. Five hours of work, gone. She had to start again and she missed the deadline.
Now watch this." [Open the Google Doc on the projector. Type a sentence. Pause. Point to the top of the screen.]
"See that little message at the top that says 'Saved to Drive'? I did not press Save. I do not have a Save button — well, I
have Ctrl+S, but the document saves itself as I type. Every single keystroke goes to Google's servers. If this computer catches
fire right now, my document is still safe. Funmi's problem cannot happen here.
But Docs is not only about saving. Today you will also learn to make a document look professional — with headings and
tables and images — and to work on it together with other people at the same time. Then we will switch to Google
Sheets and learn to make the computer do the maths: adding up your sales or expenses with one short formula instead of
a calculator."
Expected learner response: Learners commonly share their own "lost work" stories. Accept them warmly and connect them:
"Every one of those stories is a reason this tool exists."
Hook — demonstrate collaboration: On the projector, open the same Google Doc on the instructor's phone or a second
logged-in window, type a change, and let learners watch it appear in the other window within a second. Say:
"Two people, two devices, one document, live. That is what you will be able to do before this session ends."
Why this opener works: It starts with a universally painful and very Nigerian problem — power cuts destroying unsaved work
— and immediately delivers the solution visually ("Saved to Drive"). It ends with a live collaboration demo that creates curiosity
about the rest of the session.

## E. PREREQUISITE REVIEW (7 minutes)
<!-- kind:prereq_review -->
Run as a fast oral round-robin. Put the questions on the projector.
Question 1: "Where do we save files in this course, and what does cloud storage protect us from?"
Expected answer: In Google Drive; it protects us from theft, fire, flood and computer failure because the files live on
Google's servers.
Common gap: learners may still save to the Desktop from habit. Reinforce: create and edit in the cloud.
Question 2: "What are the three sharing roles, and which one lets a person comment but not change the content?"
Expected answer: Viewer, Commenter, Editor; Commenter can comment but not edit the content.
Common gap: confusing Commenter and Editor. Clarify.
Question 3: "Why do we keep General access on 'Restricted'?"
Expected answer: So only the people we choose can open the file; "Anyone with the link" exposes it publicly.
Common gap: learners think links are private by default.
Question 4: "In Gmail, what is a label, and how is it different from a folder?"
Expected answer: A label is a tag; one email can have many; a folder holds an item in one place only.
Common gap: some still think labels and folders are the same. A quick reminder is enough.
Question 5: "How do you find a file quickly in Drive?"
Expected answer: Search bar with the name or operators like type: and is:starred .
Bridge to today (say this):
"You have your files organised (Session 1) and your email organised (Session 2). Today we fill the folder with real work. A
document lives in your Drive folder and can be shared like any other file. A spreadsheet does the same — but it also
calculates. The sharing rules from Session 1 apply here exactly: Viewer to read, Commenter to review, Editor to co-work."
If the room struggles with Question 2 or 3, spend a couple of extra minutes reinforcing sharing safety, because collaboration
today depends on it.

## F. Full Lecture Notes
<!-- kind:lecture -->
These notes are the actual teaching. Read them as written.
F.1 Google Docs — what it is and why it matters
The idea. Google Docs is a word processor that runs in your browser and saves to Google Drive. You use it to write and format
documents: letters, reports, CVs, proposals, minutes, assignments.
Plain-English definition. A word processor is software for writing text and making it look good — choosing fonts, sizes,
headings, lists, tables, images. Microsoft Word is the famous one you install; Google Docs is the free online version, and it lives
in the cloud.
Why it exists. Word processing needs three things that paper typewriters cannot give: the ability to edit easily, the ability to
format professionally, and the ability to share. Google Docs adds a fourth, powerful thing: real-time collaboration — several
people can type in the same document at once.
Familiar analogy — the shared exercise book. Writing a letter in Microsoft Word is like owning one exercise book. If you want
a colleague to work on it, you must photocopy it and pass it around — and now there are two versions that disagree. Google
Docs is like a single exercise book lying open on a table that everyone you invite can write in at the same time, and at any
moment you can look back and see who changed what.
What Docs does for you:
Auto-save to Drive — no lost work, no Save button needed (the screen shows Saved to Drive).
Formatting — make documents look professional.
Collaboration — share, comment, suggest, edit together.
Version history — see and restore earlier drafts.
Export — download as PDF, Word (.docx), and more.
Worked example — Adaeze's grant letter. Adaeze needs to ask for an SME grant application form. She writes the letter in
Google Docs, formats it properly, exports it as a PDF, and emails a Drive link to the grant office. Because it is a PDF, it looks the
same on the officer's computer as it does on hers — the layout cannot shift. We build this exact letter in the practical.
Common misconception. "I must click Save." You do not. Docs saves continuously. You can press Ctrl+S , but it is not
necessary — the honest truth is that if you see Saved to Drive, your work is safe. (The one thing not to do is close the tab mid-
typing on a very slow connection; give it a second to catch up.)
Limitation. Google Docs is excellent for documents, but it is not strong at very complex print layouts (magazines, posters with
detailed positioning) — for those, designers use specialised tools. For letters, reports, CVs and everyday business documents,
Docs is more than enough.
F.2 The Docs interface and formatting basics
How to get there. Open Chrome and either:
Go to docs.google.com , or
Go to Drive, click + New → Google Docs.
To name the document: click the box at the top-left that says Untitled document, type a clear name (use your naming
convention, e.g. 2026-10-09 - AdaezeFashion - Grant-Letter - v1 ), and press Enter. The title also becomes the file name in Drive.
The toolbar — the main controls:
Control What it does
Styles dropdown (usually shows "Normal text") Applies a style: Normal text, Title, Subtitle, Heading 1, Heading 2, Heading 3
Font Changes the typeface (e.g. Arial, Times New Roman)
Font size Changes the size (e.g. 11, 12, 14)
B / I / U Bold, Italic, Underline
Text colour / highlight Changes the colour of text or the marker behind it
Control What it does
Insert link Makes selected text open a website (see F.4)
Add comment Opens a comment box on the selected text
Insert image Adds a picture
Align Left, Centre, Right, Justify
Line & paragraph spacing Adjusts spacing
Bulleted / numbered list / checklist Creates lists
Indent / outdent Moves paragraphs in or out
Formatting text — the exact steps:
1. Select the text (click and drag over it, or double-click a word).
2. Apply the change from the toolbar — e.g. click B to bold it, or pick a font size.
3. To remove formatting, select it and use the Format → Clear formatting option.
The golden formatting rule for beginners. Do not format word by word by hand. Instead, use styles. This is the most
important formatting concept today — see F.3.
Common misconception. Learners bold and enlarge headings manually, one line at a time. That "looks" like a heading but is
not really one — and later, tools like the table of contents and outline cannot see it. Use the Styles dropdown for headings; that
is what it is for.
F.3 Heading styles — structure that works for you
The idea. A heading style is a pre-set format (size, boldness, spacing) applied to a title or section heading. Instead of guessing
that "16pt bold" looks right, you apply Heading 1, Heading 2 and Heading 3, which are consistent and carry meaning.
Why styles matter. Styles do more than make text look nice:
They create an outline (the left-hand panel) that lets you jump around a long document.
They let you build a table of contents automatically.
They keep formatting consistent — every Heading 2 looks the same, with no accidental differences.
If you change a style, every heading of that type updates at once.
Analogy — the street sign system. Numbered house numbers (1, 11, 111) tell the postman exactly where a house is. Heading
1, Heading 2, Heading 3 are like the levels of a building: floor, room, cupboard. Structure helps everyone find their way —
including you, a month later.
How to apply a heading style:
1. Click on the line you want as a heading (e.g. the document title).
2. Open the Styles dropdown (it says "Normal text" by default).
3. Choose Title for the document title, Heading 1 for main sections, Heading 2 for subsections.
4. The line is formatted instantly, and the outline panel on the left updates.
Table of contents. For a long document (a report, a proposal), go to Insert → Table of contents. Docs builds it from your
headings. (It works best when you have used heading styles — a direct payoff of doing it right.)
Worked example. In Adaeze's grant letter, the document title "Adaeze Fashion" is the letterhead, not a heading; but in a longer
business profile, she would make "About the Business" a Heading 1, "Products" a Heading 1, and "Pricing" a Heading 2 under
Products. Then a table of contents builds itself at the top.
Common misconception. Learners think Heading 1 is "the biggest heading" only. Size is part of it, but the real value is the
structure it records — which the outline and table of contents use.
F.4 Inserting tables, images and links
Tables. A table arranges information in rows and columns — perfect for price lists, timetables, comparisons.
Insert → Table, then drag across the grid to choose rows and columns (e.g. 3 columns × 4 rows), or use Insert → Table
→ Insert table and type the numbers.
Fill the cells by clicking and typing. Add or delete rows by right-clicking a cell → Insert row above/below, Delete row.
Table borders and cell background are edited via Format → Table or the border/shading controls.
Images. You can add pictures to make a document clearer or more attractive.
Insert → Image, then choose Upload from computer, Search the web, Drive, Photos, or By URL.
Resize by dragging a corner handle. Wrap text around it via the image options.
For Adaeze's business profile, an image of her Ankara designs makes the profile come alive.
Links. A hyperlink is text you click to open a web page (or another file).
Select the text, then Insert → Link (or press Ctrl+K ), paste the web address, and press Enter.
Example: the words "our website" could link to https://adaezefashion.example .
Say to the class:
"A table is for things that repeat in rows and columns — like a price list. An image is for things that are easier to see than
to read — like a design. A link is for pointing someone somewhere else — like a website or a form. Use each for its proper
job."
Common misconception. Learners paste huge images straight from a phone, which makes documents slow. For a professional
document, use reasonably sized images. (Google usually compresses them, but do not paste 20-megapixel photos when a
smaller version will do.)
F.5 Page setup, auto-save and exporting (PDF and Word)
Page setup. To change margins, paper size and orientation: File → Page setup. Here you can set:
Orientation — Portrait (tall) or Landscape (wide).
Paper size — A4, Letter, etc.
Margins — the white space around the edges.
Page colour — usually left white.
Auto-save. As you type, Docs saves to Google Drive automatically. The top of the screen shows Saved to Drive when
everything is up to date (it may briefly show "Saving…"). You do not need a Save button — but Ctrl+S does no harm.
Download / export. To give someone a copy in a fixed format:
File → Download, then choose:
Microsoft Word (.docx) — for people who use Word.
PDF Document (.pdf) — for a fixed layout that looks the same everywhere (best for official letters and CVs).
OpenDocument (.odt), Rich Text (.rtf), Plain text (.txt), Web page (.html).
Why PDF is the professional default for finished documents. A PDF "freezes" the layout. Your letter looks identical on the
grant officer's computer, whether they use Windows, Mac or a phone. If you send a .docx , the layout can shift if they have a
different font or software version.
Other useful File options:
File → Make a copy — create an independent duplicate (useful as a template).
File → Share → Publish to web — turns it into a public web page (use with care; it is for things you genuinely want
public).
File → Move — relocate the document into the correct Drive folder (your Session 1 skill).
Worked example. Adaeze finishes her grant letter, clicks File → Download → PDF Document (.pdf), and the PDF lands in her
computer's Downloads folder. She uploads it to her Adaeze Fashion/01-Admin folder in Drive and emails the link. The officer sees
exactly what Adaeze intended.
Common misconception. Learners think exporting removes the Google Doc. It does not — the Google Doc stays in Drive; the
export is an extra copy on the computer.
F.6 Collaboration — sharing, commenting and suggesting
The idea. Docs is built for several people to work on one document. You already know the sharing roles from Session 1; now
you use them inside a document.
Sharing a Doc:
1. Click the blue Share button (top-right).
2. Add people by email and choose their role:
Viewer — read only.
Commenter — can read and comment, and can use Suggesting mode, but cannot directly change the content.
Editor — can change anything.
3. Set General access to Restricted (default), and click Send.
The three modes (top-right, a dropdown). Inside the document, the mode button lets you switch how you work:
Editing — you type directly; changes are immediate.
Suggesting — your changes appear as suggestions (in a different colour) that others can Accept or Reject. This is like
"tracked changes" in Word.
Viewing — read only.
Suggesting mode is the collaboration superstar. When a colleague might disagree with your edit, suggest rather than change.
The document owner accepts what they like and rejects what they do not — with a full record of who suggested what.
Comments. Leave a note without altering the text:
1. Select the words you are commenting on.
2. Click the Add comment icon in the toolbar, or press Ctrl+Alt+M , or use Insert → Comment.
3. Type your comment and click Comment.
4. The commenter or an editor can Reply, and when the issue is handled, click Resolve to remove it from view (it is kept in
the history).
Mentioning people. In a comment, type @ followed by a name to assign the comment and notify that person. They get an
email and a notification.
Worked example — the collaborative letter. Adaeze shares her grant letter with her accountant as Commenter. The
accountant selects the sentence about employment numbers and comments: "We now have five staff, not four — please
update." Because he is a Commenter, he cannot silently change it. Adaeze updates it and clicks Resolve. Clean, tracked,
professional.
Say to the class:
"If you are the owner, you edit. If you are reviewing someone else's work, you comment or suggest. Never silently change
another person's document when the role they gave you was Commenter — that is the digital equivalent of changing
someone's letter after they signed it."
Common misconceptions:
"If I share as Editor, the other person's changes appear instantly and I cannot stop them." True — that is why you use
Commenter or Suggesting when you want control.
"Resolving a comment deletes it forever." It hides it from view but keeps it in history; you can re-open resolved comments.
Limitation. Anyone with Editor access can also delete content. For important documents, prefer Commenter/Suggesting during
review, and give Editor only to people you trust to co-own the document.
F.7 Version history — your time machine
The idea. Version history records every change made to a document, with who made it and when. You can look back and, if
needed, restore an earlier version.
How to open it: File → Version history → See version history. A right-hand panel appears listing versions by date and time,
often with the names of people who edited.
What you can do:
Click any version to preview it (it highlights what changed).
Click the three-dot ⋮ next to a version → Restore this version to bring the whole document back to that state.
Name this version — give an important milestone a label like "Draft for client review", so you can find it easily later.
Analogy -> Ctrl+Z beyond the grave. Ctrl+Z undoes your last few actions in the current session. Version history is Ctrl+Z that
reaches back in time — days, weeks or months — and can recover even after you closed the document or someone else
edited it.
Worked example. A staff member accidentally deletes a whole section of Adaeze's business profile. Adaeze opens Version
history, finds the version from before the deletion, previews it (the section is present), and clicks Restore this version. The work
is back in seconds.
Common misconception. Learners think the "Save" nature of Docs means there is only one version. There are many — Docs
keeps the history automatically.
Limitation. Version history is powerful but not a substitute for good naming. For major drafts, you can also use File → Make a
copy and give it a version number (v1, v2) so you have clearly separated files.
F.8 Google Sheets — what it is and how the grid works
The idea. Google Sheets is a spreadsheet — a grid of rows and columns used to store data and, crucially, to calculate with it.
Where Docs is for words, Sheets is for numbers.
Plain-English definition. A spreadsheet is a grid where each box (cell) can hold a number, text or a formula. Change one
number, and every formula that uses it updates automatically. This is why accountants, shop owners and analysts live in
spreadsheets.
Why it exists. Imagine Adaeze adds up her monthly expenses on a calculator. If she later fixes one wrong amount, she must re-
add everything. In a spreadsheet, she changes the one wrong cell and the total recalculates itself instantly. Spreadsheets also
sort, filter and chart data.
The grid vocabulary — learn these exactly:
Column — runs vertically, labelled with letters: A, B, C, D…
Row — runs horizontally, labelled with numbers: 1, 2, 3, 4…
Cell — one box, where a column and row meet. A cell is named by its column letter + row number: B2 means column B,
row 2.
Range — a rectangle of cells, written as firstcell:lastcell , e.g. C2:C11 means the cells from C2 down to C11.
Active cell — the one currently selected (shown with a blue border); its reference appears in the Name box (top-left).
Formula bar — the long bar near the top where you type or edit what is in the active cell.
Sheet tabs — at the bottom; a single file (workbook) can contain several sheets, e.g. "October" and "November".
Analogy — the accountant's ledger book. A paper ledger has rows and columns where an accountant writes amounts and
totals. A spreadsheet is the same ledger, but the totals do the arithmetic themselves and never make a mistake.
Worked example — naming a cell. In Adaeze's expense sheet, the first expense amount (Fabric - Ankara, ₦45,000) sits in
column D, row 2 — so its reference is D2 . If she wants the total of all amounts, she will ask Sheets to add the range D2:D11 .
Common misconception. Learners think Sheets is "just a table like in Docs". A table in Docs only displays data; a spreadsheet
calculates it. That is the whole reason to use Sheets.
F.9 Entering and formatting data (including Naira)
Entering data:
1. Click a cell (e.g. A1 ).
2. Type the content (a heading like "Date", or a value like 45000 ).
3. Press Enter to move down, or use Tab to move right.
4. To edit, double-click the cell or select it and edit in the formula bar.
Entering dates and numbers. Sheets recognises dates if you type them in a clear format (e.g. 2026-10-01 or 01/10/2026 ,
depending on locale). Numbers are typed plainly ( 45000 , no commas). Do not type the Naira sign into the cell if you want to
calculate — type the number and let Sheets add the formatting.
Formatting numbers as Naira (₦):
1. Select the cells with amounts (e.g. D2:D11 ).
2. Go to Format → Number → Custom currency.
3. In the currency settings, choose Nigerian Naira (₦) from the currency dropdown (the exact wording can vary between
versions; look for NGN / Naira, or type the ₦ symbol). Confirm.
4. The amounts now display as ₦45,000.00 etc. — but the underlying value is still the number 45000, so formulas still work.
(You can also use the quick currency and percent buttons on the toolbar, but those may default to a different currency — set
the Naira custom currency once to be safe.)
Other useful formatting:
Bold your header row so it stands out.
Borders (the border icon) — draw lines around your table for readability.
Text wrapping and alignment — centre headings with the align buttons.
Format → Number → Date — to standardise date display.
Worked example. Adaeze types 10 expenses. The amounts go in column D as plain numbers. She selects D2:D11 and applies
Custom currency → Nigerian Naira, and the column shows ₦ signs. She bolds row 1. The sheet now reads like a proper
business record.
Common misconception. Learners type "₦45,000" by hand into cells. Then the cell holds text, not a number, and SUM cannot
add it — you get 0 or an error. Type the number; format the currency. This is the single most common Sheets mistake (see
Section K).
Limitation. Spreadsheets obey exactly what the cell is. A number stored as text looks fine but breaks calculations. When a total
looks wrong, suspect a text-number first.

the formula shows in the formula bar.

How to write a formula:
1. Click the cell where you want the answer (e.g. D13 ).
2. Type = to begin.
3. Type the formula name and the range, e.g. =SUM(D2:D11) .
4. Press Enter. The answer appears.
Shortcut for SUM: select the range and click the Î£ (Sum) button in the toolbar, or use the menu Insert → Function →
SUM.
Important notes about these functions:
SUM adds numbers.
AVERAGE divides the total by how many numbers there are (ignoring blank and text cells).
MIN and MAX give the smallest and largest.
COUNT counts only cells that contain numbers — if some cells contain text or are blank, COUNT skips them. (If you need to
count all non-empty cells including text, that is COUNTA — an advanced note.)
Worked example — Adaeze's expense sheet. The ten amounts are in D2:D11 . Adaeze writes:
=SUM(D2:D11) → the total of all expenses.
=AVERAGE(D2:D11) → the average expense.
=MIN(D2:D11) → the smallest (₦2,500, sewing machine oil).
=MAX(D2:D11) → the largest (₦62,000, fabric - lace).
=COUNT(D2:D11) → 10 (ten expenses recorded).
She uses template labels so she knows what each number means: put "TOTAL" in C13 and the formula in D13 ; "AVERAGE" in
C14 and its formula in D14 , and so on.
Familiar analogy. A formula is like giving instructions to a very fast, very obedient clerk. You do not say "add these ten numbers
in your head"; you say "add everything from D2 to D11" — and the clerk never makes an arithmetic mistake.
Common misconceptions:
"I can just use the calculator app." You can, for one sum. But when one number changes, you must redo it. A formula
updates itself.
"Numbers typed with a ₦ sign work in SUM." They do not — that is text. Type plain numbers and format them.
"COUNT counts every cell." COUNT counts only numbers; blank or text cells are skipped.
Limitation. These five functions are the foundation, not the whole story. Real accountants use many more ( IF , VLOOKUP , pivot
tables). You have the essential vocabulary now; the rest is a natural next step.
F.11 Charts, freezing, sorting and filtering
Charts — making numbers visible.
Select your data (including headings), e.g. A1:D11 or just B1:C11 .
Go to Insert → Chart.
The Chart editor opens on the right. In Setup, choose the chart type — a Column chart (vertical bars) or Bar chart is a
good start for comparing expenses by category; a Pie chart shows proportions.
In Customize, you can add a title, change colours and label the axes.
The chart appears on the sheet and updates automatically if the data changes.
Freezing a header row. When you have many rows, scroll down and the header (Date, Item, Category, Amount) scrolls out of
sight, so you forget which column is which. Freeze it:
View → Freeze → 1 row (freezes row 1), or 1 column, or Up to current row if your cursor is on a lower row.
Now the header stays visible as you scroll.
Sorting. To arrange data in order:
Select the data range, then Data → Sort range, choose the column to sort by (e.g. Amount, largest first).
To sort the whole sheet simply, use Data → Sort sheet — but be careful: it sorts everything, so know what you are doing.
Filtering. A filter hides rows that do not match a condition, without deleting them:
Select the range, then Data → Create a filter (or click the filter icon in the toolbar).
Small dropdown arrows appear in the header cells. Click one and choose what to show — e.g. show only expenses in the
Materials category.
Click Filter again (or Data → Remove filter → Turn off filter) to bring everything back.
Worked example. Adaeze filters her expense sheet to show only Materials expenses, sorts them by amount from largest to
smallest, freezes the header row, and inserts a column chart comparing spending by category. In two minutes she can see that
fabric is her biggest cost — an insight worth real money.
Common misconceptions:
"Filtering deletes the hidden rows." It does not; it only hides them.
"Sorting one column is safe." If you sort only one column of a table and not the rest, the rows no longer line up. Always sort
the whole range (or use Sort sheet).
Limitation. Charts and filters are only as good as the data. If a number is stored as text, the chart may misbehave — another
reason formatting and data types matter.

Google Docs = free online word processor that auto-saves to Drive (look for Saved to Drive).

Insert tables, images and links; set page setup; download as PDF or .docx.

Version history (File → Version history) shows and restores earlier drafts.
Google Sheets = free online spreadsheet; cells have references like B2 ; ranges like D2:D11 .
Type plain numbers; apply Naira formatting with Format → Number → Custom currency.
Five core formulas: =SUM , =AVERAGE , =MIN , =MAX , =COUNT .
Insert → Chart for charts; View → Freeze for the header; Data → Sort / Create a filter for organising rows.

## J. Real-World Case Study
<!-- kind:case_study -->
Situation. The Rumuola Youth Foundation (the NGO from Session 2) is preparing a fundraising report for a partner organisation
in Abuja. Two staff members — the programme officer and the accountant — must produce one report: written sections and
a budget table. In the past they emailed a Word document back and forth. The file names became report.doc ,
report_final.doc , report_final2.doc , report_final_REALLY.doc . Twice, the partner received the wrong version, and once the
accountant's budget numbers were missing from the version that was sent because the two editors had overwritten each other's
changes.
Relevant facts.
The report needs both narrative text (explaining the programmes) and a budget (numbers).
Two people must contribute and review.
The partner needs a fixed, professional final file.
The team already uses Google accounts but has been "doing it the Word way".
Decision point. Should the Foundation (a) keep emailing Word documents, (b) build the report in a single Google Doc with a
linked Google Sheet for the budget, using Suggesting mode and comments, or (c) have the accountant produce everything
alone to avoid conflicts?
Possible approaches and trade-offs.
1. Keep emailing Word versions. Familiar but the version chaos continues; overwriting is likely; the partner may get the
wrong file. Trade-off: no learning curve, high error and embarrassment risk.
2. One Google Doc + a linked Google Sheet, with Suggesting mode and comments. Everyone works in one live document;
the accountant owns the numbers in the Sheet; the programme officer suggests text changes; version history keeps a full
record; the final is exported as a PDF. Trade-off: a short learning curve, but eliminates version chaos and overwriting.
3. Accountant does everything. Removes conflict but overloads one person and loses the programme officer's expertise.
Trade-off: simpler human process, poorer report and a bottleneck.
Recommended solution (for this stage). Approach 2. The programme officer drafts the narrative in a Google Doc and shares it
as Commenter with the accountant for budget notes. The accountant keeps the budget in a Google Sheet — so the numbers
calculate automatically and update when figures change — and the Doc links to it or pastes the final numbers once. Reviewers
use Suggesting mode and comments. When approved, they File → Download → PDF and send the PDF (or a Restricted link).
Version history is their safety net if anyone deletes a section.
Trade-offs of the recommendation. The team must learn Docs and Sheets and agree on who owns which part. If they edit the
same sentence simultaneously, they can still clash — Suggesting mode and clear ownership reduce this. And a linked Sheet is
only as good as the access setting: it must be shared with the right people, at the right role.
Professional connection. This is everyday work in offices, NGOs, schools and businesses: producing one accurate document
from several contributors without version chaos. The skills — heading styles, tables, Suggesting mode, comments, version
history, a calculated spreadsheet, and PDF export — are exactly the skills employers expect of an administrative or programme
assistant. The team that masters this looks organised and trustworthy; the team that emails final_final2 looks chaotic.

## K. Common Mistakes and Troubleshooting
<!-- kind:troubleshooting -->
Use this as the session's live troubleshooting guide. Have the learner confirm the cause before fixing.
K.1 The SUM gives 0 or an error — numbers stored as text
Symptoms: =SUM(D2:D11) shows 0 , or the total is too low. Likely causes: (a) Some amounts were typed with a currency sign or
comma ( ₦45,000 ) and are stored as text. (b) Amounts were pasted from a source that treated them as text. (c) A trailing
space. How to investigate: Click a suspicious cell — numbers are right-aligned by default; text is left-aligned. Look at the
formula bar; if it shows ₦45,000 as text, that is the cause. Corrective steps: Retype the value as a plain number ( 45000 ) and
apply Naira formatting instead of typing the sign. You can also use Format → Number → Number to convert. How to
confirm resolved: The cell right-aligns and the SUM updates. Prevention: Always type plain numbers; format the currency via
the menu.
K.2 The formula shows as text instead of calculating
Symptoms: The cell displays =SUM(D2:D11) literally. Likely cause: The cell was formatted as Plain text before the formula was
typed, or the leading = is missing. How to investigate: Check the formula bar and the cell's format. Corrective steps: Set the
cell to Format → Number → Number (or Automatic), then retype the formula starting with = . Prevention: Format cells as
numbers before writing formulas.
K.3 The heading does not appear in the outline / table of contents
Symptoms: The heading looks big but the outline is empty. Likely cause: The heading was formatted by hand (bold + size)
instead of using the Styles dropdown. How to investigate: Click the line and look at what the Styles dropdown says — if it
says "Normal text", it is not a real heading. Corrective steps: With the line selected, choose Heading 1 / 2 / 3 from the Styles
dropdown. Prevention: Always use styles for headings.
K.4 Shared the wrong way — Commenter cannot edit, or Editor changes silently
Symptoms: A reviewer complains they cannot type; or your document changes without your knowledge. Likely cause: Wrong
sharing role. Commenter can only comment/suggest; Editor can change everything. How to investigate: Open Share and read
each person's role. Corrective steps: Change the role to what is needed — Commenter for review, Editor only for trusted co-
authors. Prevention: Use least privilege; prefer Suggesting mode during review.
K.5 Lost work "someone deleted a section"
Symptoms: Content that existed earlier is gone. Likely cause: An editor deleted it, or a bad paste replaced it. How to
investigate: File → Version history → See version history; find the version before the deletion. Corrective steps: Preview that
version and Restore this version (or copy the missing part back). Prevention: Keep a named milestone version before big
edits; limit Editor access.
K.6 Chart looks wrong or empty
Symptoms: The chart shows odd values or nothing. Likely cause: The selected range included headings/empty cells incorrectly,
or text-number cells were included. How to investigate: Check exactly which cells were selected for the chart; click a suspicious
source cell. Corrective steps: Reselect just the data columns (including or excluding headers deliberately), and fix any text-
numbers. Prevention: Clean your data types before charting.
K.7 Sorting scrambled the data
Symptoms: After sorting one column, the rows no longer match up (dates next to wrong items). Likely cause: Only one column
was sorted instead of the whole table. How to investigate: Look down the rows — do the fields still belong together?
Corrective steps: Undo ( Ctrl+Z ), then select the entire range and use Data → Sort range, or use Sort sheet. Prevention:
Always sort the whole data range; watch the warning Sheets may show.
K.8 Exported PDF is missing or opens oddly
Symptoms: The downloaded PDF is not in the expected place or looks different. Likely causes: The browser saved it to a
different folder; permission prompt was missed; unusual fonts/columns. How to investigate: Check the browser's Downloads
list; open the PDF to inspect. Corrective steps: Re-export with File → Download → PDF; check page setup
(margins/orientation) before exporting. Prevention: Use File → Page setup and preview before exporting official documents.
K.9 "I cannot find my Doc/Sheet in Drive"
Symptoms: The file is not where the learner expects. Likely cause: It was created in the wrong Drive location. How to
investigate: Search Drive by name, or open Recent. Corrective steps: Open the file, use File → Move to put it in the correct
folder. Prevention: Open the destination folder before clicking + New → Google Docs/Sheets.
Distinguish likely vs confirmed. For each case, treat the cause as likely until you verify it — click the cell and see it is text, open
the Share panel and see the role, open version history and see the deletion. Then fix the confirmed problem.

(Learner version — answers only in the Instructor Key that follows.)
Q1. Short answer. Where does a Google Doc save your work, and how do you know it has saved?

Q5. Error detection. A learner types ₦45,000 into a cell, then writes =SUM(D2:D11) and gets 0 . What is the problem and how
do they fix it?
Q6. Scenario. You must send a finished CV to an employer. Should you send the Google Doc link, a .docx file, or a PDF?
Explain your choice.
Q7. Short answer. What is version history for in Google Docs, and how do you open it?
INSTRUCTOR ANSWER KEY (Q1–Q7)
A1. It saves automatically to Google Drive. You know it has saved when the top of the screen shows Saved to Drive (it may
briefly show "Saving…").
A2. (b) B2:B10 .
A3. A Commenter can read and leave comments or suggestions but cannot directly change the content; an Editor can change
or delete the content. It matters because you should give people only the access they need — reviewing someone's draft
should not mean the power to silently alter it. Use Commenter for review, Editor only for trusted co-authors.
A4. a) =SUM(D2:D11) ; b) =AVERAGE(D2:D11) ; c) =MAX(D2:D11) ; d) =COUNT(D2:D11) .
A5. The value was typed as text because it includes the ₦ sign (and comma). SUM ignores text, so it adds nothing and returns
0. Fix: retype the value as the plain number 45000 , then apply Format → Number → Custom currency → Nigerian Naira (₦)
to display the currency.
A6. Send a PDF. A PDF freezes the layout so the CV looks exactly as you designed it on any computer or phone, regardless of the
employer's software or fonts. A .docx can shift when opened in a different version of Word; a Google Doc link depends on the
employer having (and being comfortable with) access.
A7. Version history records every change with who made it and when, letting you look back and restore an earlier version if
something is deleted or spoiled. Open it with File → Version history → See version history.

Five important takeaways:
1. Google Docs auto-saves to Drive — look for Saved to Drive — so your work survives even a sudden power cut.
2. Use heading styles (not manual bold+size) to create real structure, outlines and tables of contents.
3. Collaborate with the right role: Commenter to review, Editor to co-edit; use Suggesting mode and comments for
controlled feedback.
4. In Sheets, type plain numbers and apply Naira formatting; write formulas with = — SUM , AVERAGE , MIN , MAX , COUNT .
5. Export finished documents as PDF for a fixed, professional look; use Docs for writing, Sheets for calculating.

## O. Instructor Evaluation Notes
<!-- kind:instructor_notes -->
Observable signs of genuine competence:
The learner applies a real heading style rather than hand-formatting, and can say why.
The learner exports a document as PDF without help.
The learner distinguishes Commenter from Editor and uses Suggesting mode appropriately.
The learner types plain numbers and applies Naira formatting, and explains why.
The learner writes a correct =SUM(range) and can point out the range on screen.
The learner freezes a header and filters without prompting.
The learner chooses Docs vs Sheets correctly with a reason.
Common misconceptions to watch for and correct:
"I must press Save." → Docs saves automatically; look for Saved to Drive.
"Typing ₦ in the cell is fine." → It becomes text and breaks formulas.
"A big bold line is a heading." → Only the Styles dropdown makes a real heading.
"Editor is friendliest, so share as Editor." → Use least privilege; Commenter to review.
"Filtering deletes data." → It only hides rows.
"Sorting one column is fine." → Sort the whole range, or rows misalign.
Suggested remedial exercises for learners who struggle:
1. Cell-reference drill: give a small grid and ask for the reference of six named cells and the range of a shaded block.
2. Formula drill: give five spreadsheet tasks and ask the learner to write the formula for each.
3. Format drill: give a list of items and ask "type as number, or type as text?" and how to format currency.
4. Docs structure drill: give a paragraph and ask the learner to mark which lines should be Heading 1 vs normal.
5. Tool-choice drill: give ten tasks and ask "Docs or Sheets, and why?"
Differentiation:
Level 1 (supported): provide a Doc with the letterhead already done and a Sheet with headers and two rows filled; the
learner formats, adds formulas and exports.
Level 2 (standard): the exercise as written.
Level 3 (challenge): add a second sheet tab ("November") and a summary on the first tab that references it; add a pie chart
of spending by category; set a named version ("Ready for client") in version history; and build a reusable invoice template
in Docs with blanks.
Timing guidance: If the room is slow, trim the chart and filter steps to a demonstration only, and protect the Doc letter and the
SUM / AVERAGE work, which are the core skills. If Wi-Fi is weak, keep the sample text ready to paste to save typing time. If the
class is fast, add the Level 3 invoice-template challenge.
